## 摘要
现代大型语言模型（LLM）代理可以使用外部工具帮助用户解决复杂任务。然而，对于需要从长期历史事件或先前的代理-环境交互中学习的问题，LLM代理需要使用记忆机制来存储和检索经验。尽管对话代理存在复杂的记忆系统，但很少有研究实证性地探讨如何通过过去用户-代理对话来提高代理的工具使用能力。我们提出MemToolAgent，一个通过记忆管理来改善工具使用的框架。我们的方法包含一个记忆提取模块，将过去的经验处理为结构化的记忆条目，以及一个检索模块，动态选择存储记忆条目的子集。这使得无需LLM微调即可实现更个性化和准确的响应，与用户偏好和反馈保持一致。总之，这项工作的三个主要贡献是：（1）统一的记忆条目格式，无需LLM微调即可改进通用和个性化工具使用；（2）基于反思的记忆提取，利用环境和用户反馈将错误执行提炼为批评并存储；（3）一个检索模块，根据记忆相似性分布选择使用多少过去的经验。与强基线相比，MemToolAgent在WorkBench、NESTFUL和PEToolBench基准上分别实现了29%、80%和17%的相对改进。

## Abstract
Modern large language model (LLM) agents can use external tools to help users solve complex tasks. However, for problems that require learning from long-term historical events or from previous agent-environment interactions, LLM agents are required to use memory mechanisms to store and retrieve experiences. While sophisticated memory systems exist for dialogue agents, few studies have empirically examined how to improve agents' tool-using capabilities through past user-agent conversations. We propose MemToolAgent, a framework that improves tool use through memory management. Our approach contains a memory extraction module that processes past experiences into structured memory entries, and a retrieval module that dynamically selects a subset of the stored memory entries. This enables more personalized and accurate responses aligned with user preferences and feedback without requiring LLM fine-tuning. In summary, this work has three main contributions: (1) a unified memory entry format that improves both general-purpose and personalized tool use without LLM fine-tuning, (2) a reflection-based memory extraction that uses environment and user feedback to distill wrong executions into critiques to store, and (3) a retrieval module that chooses how many past experiences to use based on the memory similarity distribution. MemToolAgent achieves 29%, 80%, and 17% relative improvements compared to strong baselines on the WorkBench, NESTFUL, and PEToolBench benchmarks, respectively.

## 1. 核心问题与整体含义（研究动机和背景）

- **问题**：现代LLM代理虽能调用外部工具解决复杂任务，但缺乏有效利用长期历史交互经验的能力。固定上下文窗口导致长对话中信息丢失，无法维持连贯性；代理常犯错误（如参数幻觉、依赖错误、过早调用工具），且难以从过去错误中学习。
- **背景**：已有记忆系统（如MemGPT、Reflexion、A-MEM等）主要关注对话或通用记忆，但针对**工具使用代理**如何通过存储和检索过去**用户-代理交互**来提升性能的实证研究很少。
- **整体含义**：无需LLM微调，仅通过统一记忆格式和反思机制，即可显著提升代理在通用工具使用和个性化工具编排上的准确性与鲁棒性。

## 2. 方法论：核心思想、关键技术细节、算法流程

### 核心思想
- 将过去经验（查询、工具调用、用户反馈、反思）存储为结构化记忆条目；推理时根据当前查询动态检索最相关条目作为**上下文示例**，引导代理正确调用工具。
- 两个关键模块：**记忆提取模块**（反思生成）与**动态n检索模块**（自适应选择记忆数量）。

### 关键技术细节
1. **记忆条目格式**：每个条目 \( m = (q, a, f, r) \)，其中：
   - \( q \)：用户查询
   - \( a = \{a_1, a_2, ..., a_n\} \)：工具调用序列
   - \( f \in \{0,1\} \)：二进制用户反馈（1成功，0失败）
   - \( r \)：当 \( f=0 \) 时由记忆提取模块生成的反思/批评（反思内容包括错误原因、正确步骤等）

2. **动态n Top-n嵌入检索**（Algorithm 1）：
   - 计算当前查询与所有记忆条目的余弦相似度，降序排列。
   - 用滑动窗口估计相似度一阶导数（变化率）。
   - 利用 `scipy.signal.find_peaks` 在导数曲线上找峰值（代表相似度骤降点，即“膝盖”），选择第k个峰值对应的索引作为检索数量 \( n \)。
   - 超参数：半径R（平滑度）、prominence（峰值重要性）、peak_number（选择第几个峰值）。R=10，prominence=1e-5，WorkBench/NESTFUL用第一峰，PEToolBench用第二峰。

3. **记忆提取模块**（LLM-based）：
   - 输入：当前查询、工具集、代理执行轨迹、环境反馈、用户反馈、检索到的相似记忆。
   - 输出：对失败执行的反思/批评（如“条件不满足时不应创建图表”）。
   - 对个性化任务，模块提取高阶用户偏好（如“用户偏好API_X下的工具”）。

### 算法流程（文字说明）
1. 推理开始时，用动态n检索从记忆库中选出最相关条目。
2. 将检索到的条目作为系统提示中的示例（正例和反例均含反思），引导LLM代理执行当前任务。
3. 任务结束后，若用户反馈失败，记忆提取模块根据此次执行生成反思，并将 \( (q, a, 0, r) \) 加入记忆库；若成功，存储 \( (q, a, 1, \emptyset) \)。

## 3. 实验设计

### 数据集/场景与Benchmark
- **WorkBench**：通用工具使用，5个领域（Analytics、Calendar、CRM、Email、Multi-Domain），27个工具，模板化查询。评估指标：**准确性**（数据库状态匹配）。测试集：549个查询。
- **NESTFUL**：嵌套工具调用序列，基于MathQA和StarCoder2-Instruct。1891个测试查询（取前500做测试，后500做记忆填充）。指标：F1 Function、F1 Parameter、Partial Sequence Matching、Full Sequence Matching、Win Rate。
- **PEToolBench**：个性化工具编排，每个查询附带80-100条历史交互记录（二进制评分）。测试集：591个查询（子集用50或100个）。指标：Tool Accuracy、Parameter Accuracy。

### 对比方法
- **WorkBench / NESTFUL**：No Memory（直接推理）、Extended Thinking（Claude延长思考）、ReAct Agent。
- **PEToolBench**：A-MEM、Mem0（最新记忆架构，均用Top-15检索）。
- **消融实验**：固定k vs 动态n、有无记忆提取模块、不同记忆类型（原始查询、改写查询、合成查询）、硬偏好引导（移除负反馈工具）等。

### 实验充分性与公平性
- **充分性**：主实验覆盖三个不同性质的Benchmark，总计超过10组结果；消融实验包括检索机制、记忆模块、记忆类型、个性化策略等，共约6组消融子实验。

## 6. 主要结论与发现

1. **显著提升**：在WorkBench整体准确率从57.6%→85.1%（相对提升29%）；NESTFUL Full Sequence Matching从15.6%→30.4%（+80%）；PEToolBench Tool Accuracy从0.70→0.82（+17%）。
2. **动态检索优于固定k**：动态n自适应选择记忆数量，避免过多噪声或信息不足。
3. **记忆提取（反思）是关键**：将原始失败轨迹转化为批评反思，代理更容易从错误中学习（WorkBench消融：无反思时准确率69.8%，有反思时74.5%）。
4. **硬偏好引导可替代内存提取**：在个性化任务中，直接移除负反馈工具（Hard Preference Guiding）是一种简单的低成本有效策略。
5. **合成查询可缓解冷启动**：使用LLM生成的合成查询填充记忆，效果优于无记忆基线（但复杂多域任务仍困难）。

## 7. 优点

- **无需微调**：完全基于检索式ICL，可快速适配不同LLM和工具集。
- **统一记忆格式简洁有效**：包含反思的高阶信息，比原始轨迹更易学习。
- **动态检索**：利用导数估计峰值，比简单阈值或固定k更鲁棒。
- **兼顾通用与个性化**：同一框架支持两类任务，通过不同的记忆提取策略区分。
- **输出token节省**：相比Extended Thinking和ReAct，输出token大幅减少，降低延迟和成本。

## 8. 不足与局限

- **冷启动问题**：初始记忆为空时表现下降（虽用合成查询可缓解，但多域复杂场景效果不佳）。
- **工具数量限制**：实验仅含<40个工具，实际场景工具更多时记忆覆盖和检索难度增大。
- **单轮任务局限**：所有Benchmark均为单次用户查询，未验证多轮对话中记忆的动态更新（如每轮需重新检索）。
- **超参数敏感**：动态n检索需手动调参（R、prominence、peak_number），且不同数据集最优峰值不同，缺乏自适应调整。
- **消融规模有限**：部分消融实验数据量小（50/100查询），结论推广性需更多验证。
- **二进制反馈简化**：仅用正确/错误标签，未探索更细致的文本反馈或评分反馈。
- **单次运行**：未报告统计显著性，实验结果可能存在随机波动。
