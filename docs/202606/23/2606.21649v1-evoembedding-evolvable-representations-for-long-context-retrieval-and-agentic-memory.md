## 摘要
现有的嵌入模型本质上是静态的：它们孤立地编码文本片段，忽略其周围上下文和时序。本文提出EvoEmbedding，一种新颖的嵌入模型，可生成用于检索的可演化表征。它专为长上下文场景量身定制，其中信息是动态的、序列化的，并需要持续的状态追踪。我们的设计很简单：EvoEmbedding在顺序处理输入时维护一个持续更新的隐式记忆，并利用它和原始内容共同生成可演化的嵌入。因此，对于相同的查询，我们的模型会调整其表征，基于不断变化的上下文检索不同的目标，超越了静态语义搜索。为了使模型具备此能力，我们构建了EvoTrain-180K，一个多样化的数据集，用于隐式记忆和检索的联合优化。此外，我们引入一个记忆队列来防止循环编码期间的表征崩溃，以及分段批处理技术来解决显著的长度差异，并将训练加速3.8倍。大量实验表明，我们的模型不仅在多项长上下文检索基准上优于更大规模的专家模型（例如Qwen3-Embedding-8B和KaLM-Embedding-Gemma3-12B），还能很好地泛化到下游任务（例如个性化），上下文长度达到训练窗口的10倍。值得注意的是，EvoEmbedding无缝集成到智能体工作流中以提升性能。例如，配备我们模型的朴素RAG流水线超越了专门的智能体记忆系统。项目页面：https://clare-nie.github.io/EvoEmbedding。

## Abstract
Existing embedding models are inherently static: they encode text segments in isolation, ignoring their surrounding context and temporal order. This paper introduces EvoEmbedding, a novel embedding model that generates evolvable representations for retrieval. It is tailored for long-context scenarios, where information is dynamic, sequential, and requires continuous state tracking. Our design is simple: EvoEmbedding maintains a continuously updated latent memory as it sequentially processes inputs, and uses it alongside the raw content to jointly generate evolvable embeddings. Consequently, for the same query, our model adapts its representation to retrieve distinct targets based on the evolving context, going beyond static semantic search. To equip the model with this capability, we construct EvoTrain-180K, a diverse dataset for the joint optimization of latent memory and retrieval. Furthermore, we introduce a memory queue to prevent representation collapse during recurrent encoding, alongside segment-batching techniques that tackle significant length variance and accelerate training by 3.8$\times$. Extensive experiments show that our model not only outperforms larger-scale specialists (e.g., Qwen3-Embedding-8B and KaLM-Embedding-Gemma3-12B) across a range of long-context retrieval benchmarks, but also generalizes well to downstream tasks (e.g., personalization) with contexts 10$\times$ longer than its training window. Notably, EvoEmbedding seamlessly integrates into agentic workflows to boost performance. For instance, a naive RAG pipeline equipped with our model surpasses dedicated agentic memory systems. ## 1. 核心问题与整体含义（研究动机与背景）

- **现有嵌入模型的根本缺陷**：传统文本嵌入模型（如Sentence-BERT、E5、Qwen3-Embedding等）本质上是静态的——它们将文本片段孤立编码，忽略片段之间的时序顺序和全局上下文关联。这种“分段-独立编码”的方式破坏了长上下文中的时序连续性和跨段关联，导致在处理**动态、序列化、需要状态追踪**的长上下文场景（如多轮对话、长期个性化记忆）时，检索结果常常过时、不准确，或者引入噪音。
- **下游影响**：在RAG（检索增强生成）和智能体（agent）系统中，静态检索是性能瓶颈。尽管现有工作通过索引优化（构建结构化记忆、添加元数据）和检索优化（查询重写、重排序、多步迭代检索）来缓解问题，但这些方法引入大量计算开销和延迟，且仍无法从根本上恢复丢失的全局上下文。
- **解决思路**：在表征层面直接注入上下文动态性和时序感知能力，让同一个查询在不同上下文中能够检索到不同的目标，实现**可演化**的表征。

## 2. 方法论：核心思想、关键技术、公式与流程

### 核心思想
EvoEmbedding 在顺序处理输入时维护一个**持续更新的隐式记忆（latent memory）**，将其与当前输入片段联合编码，生成**上下文可演化的嵌入（evolvable embeddings）**。这样，模型可以在推理时利用记忆跟踪状态的演变，从而根据当前语境精准定位目标信息。

### 关键技术细节

#### （1）整体架构（图3）
给定当前输入片段 \(x_t\) 和上一时刻的记忆 \(M_{t-1}\)，模型并行执行两个任务：
- **记忆演化（Memory Evolution）**：利用特定LoRA适配器（\(\theta_m\)）从 \(x_t\) 和 \(M_{t-1}\) 生成新的隐式记忆令牌 \(\tilde{M}_t\)，并更新记忆队列。
- **表征生成（Representation Generation）**：利用检索LoRA适配器（\(\theta_r\)）将 \(x_t\) 和 \(M_{t-1}\) 编码为当前片段的嵌入向量 \(v_t\)。

公式表示为：
\[
\tilde{M}_t = \pi_{\theta_m}(x_t, M_{t-1}), \quad v_t = \pi_{\theta_r}(x_t, M_{t-1})
\]

#### （2）隐式记忆队列（Latent Memory Queue）
- 采用**先进先出（FIFO）** 的队列结构存储最近 \(L\) 个步骤的隐式记忆，总容量 \(C = L \times K\)（默认 \(C=512,\;K=16\)）。
- 优点：① 限定单条记忆最多被循环编码 \(L\) 次，避免循环编码导致的**表征坍塌**，无需课程学习即可直接训练长上下文；② 严格限制计算复杂度，显存开销仅相当于一张编码图像。

#### （3）动态分段批处理（Dynamic Segment-Batching）
- 训练推理时，将连续 \(k\) 个片段作为一批并行处理，通过动态调整 \(k\)（使总token数不超过预设阈值，如2048）来利用并行计算。
- 训练速度提升约 **3.8×**，且性能略有提升。

#### （4）多LoRA解耦设计
- 记忆演化、表征生成各使用独立的LoRA适配器，冻结骨干LLM，避免灾难性遗忘。推理时可根据任务灵活切换LoRA。

#### （5）损失函数
联合优化两项损失：
- **记忆生成损失** \(L_{\text{mem}}\)：以最终记忆 \(M_T\) 和查询 \(q\) 为条件，用交叉熵预测标准答案 \(y\)。期间冻结所有LoRA，迫使隐式记忆与基础LLM的语义空间兼容。
- **对比表征损失** \(L_{\text{con}}\)：长度加权多正例对比损失。将当前样本的所有正片段嵌入 \(\{v_i^+\}\) 与负片段嵌入 \(\{v_j^-\}\) 进行对比，并引入权重因子 \(\log(N+1)\) 以自适应平衡样本难度。

#### （6）训练数据集 EvoTrain-180K
- 通过三阶段自动合成构建：① 原始上下文构建（多样化网页文本、对话、记忆）；② 动态QA生成（40+模板，兼顾简单语义匹配和复杂推理）；③ 检索标注与验证（使用Gemini-3.1-Pro进行标注和过滤）。
- 共计184,137个样本，每个样本最长12K tokens（实际上平均1.2K），最长256个片段。训练数据量仅为当代模型（如KaLM-Embedding-Gemma3）的不足1%。

## 7. 优点

- **创新性架构**：将隐式记忆引入嵌入生成，打破了静态检索的局限，使表征具有时序敏感性和上下文依赖性。
- **轻量高效**：记忆队列+分段批处理大幅降低训练/推理开销，且记忆容量仅512 tokens，显存占用低。
- **易部署**：作为独立嵌入模型使用，也支持通过LoRA切换嵌入不同的智能体系统，兼容黑盒API。
- **强泛化能力**：训练数据为短中长度（平均1.2K），却能泛化到128K测试场景，证明学到了可迁移的建模能力。
- **损失函数设计合理**：长度加权对比损失解决了不同长度样本难度不均的问题；记忆生成损失迫使记忆与LLM原生语义对齐。
- **实验全面且深入**：覆盖检索、生成、消融、效率、时序分析、集成性，证据充分。

## 8. 不足与局限

- **训练数据规模有限**：仅180K样本，且自动合成流程依赖强LLM（Gemini）标注，可能存在偏差或覆盖不完全，导致某些域外场景性能下降（作者已指出）。
- **缺乏多模态支持**：当前仅处理文本，无法直接应用到图像、音频等模态的长上下文记忆。
- **推理延迟增加**：由于需要顺序编码并更新记忆，上下文编码时间比并行编码的静态模型更长（表6：22.08s vs 3.80s），虽然峰值显存降低，但在对延迟敏感的场景下可能成为瓶颈。
- **时序记忆容量固定**：512 tokens容量可能不足以捕获超长历史（如完整对话日志），虽在128K测试中表现良好，但更大规模下的饱和点未充分探索。
- **消融中“w/o Memory Queue”性能灾难性下降（>50%）**，表明模型对显式记忆机制的依赖极强，若记忆损坏或初始化不当，鲁棒性可能不足。
- **部分子任务仍有差距**：在LoCoMo的Temporal和Open-domain子任务上，EvoEmbedding弱于专门化系统LightMem，说明复杂时序推理场景仍有改进空间。
- **语言与领域偏向**：训练数据来自FineWeb和LLM生成对话，主要覆盖英语，对其他语言或专业领域（如法律、医疗）的泛化性未验证。
