## 摘要
大语言模型智能体越来越多地被部署在需要跨长时间交互历史进行持续推理的长周期任务上。要大规模实现这一点，智能体需要持久地存储、检索并更新其跨会话的记忆。一个丰富的智能体记忆系统生态已经出现，涵盖平面检索、LLM介导的提取、固化事实存储以及智能体控制流。然而，其系统级行为仍未被刻画。我们首次对智能体记忆进行了系统特性分析。首先，我们引入了一个面向系统的分类法，沿四个轴对智能体记忆系统进行分类。其次，我们构建了一个阶段感知的性能剖析工具，将成本归因于构建、检索和生成。第三，我们刻画了跨两个基准测试套件的十个代表性系统，揭示了设计选择如何在写入和读取路径上转移成本。最后，我们推导出10条系统建议，涵盖构建调度、能力下限、通过查询量的摊销、新鲜度-延迟权衡以及集群规模管理。

## Abstract
LLM agents are increasingly deployed on long-horizon tasks requiring sustained reasoning over extended interaction histories. Realizing this at scale requires agents to persistently store, retrieve, and update their own memory across sessions. A rich ecosystem of agent memory systems has emerged spanning flat retrieval, LLM-mediated extraction, consolidating fact stores, and agentic control flows. Yet, their system-level behavior remains uncharacterized. We present the first systems characterization of agent memory. First, we introduce a system-oriented taxonomy classifying agent memory systems along four axes. Second, we build a phase-aware profiling harness attributing cost to construction, retrieval, and generation. Third, we characterize ten representative systems across two benchmark suites, uncovering how design choices shift cost across the write and read paths. Finally, we derive 10 system recommendations covering construction scheduling, capability floors, amortization via query volume, freshness-latency tradeoffs, and fleet-scale management.

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：将智能体记忆系统划分为四种范式（Paradigm），并构建阶段感知的（phase-aware）性能剖析框架，将成本归因于构建（construction）、检索（retrieval）和生成（generation）三个阶段。
- **关键技术细节**：
  - **四轴分类法**（见表1）：
    1. **构建管道**（Construction Pipeline）：是否使用LLM、Embedding、结构化提取、智能体控制流。
    2. **存储结构**（Agent DB）：原始上下文、倒排索引、稠密存储、知识图谱、混合存储等。
    3. **检索管道**（Retrieval Pipeline）：是否涉及LLM调用、多阶段检索等。
    4. **可变性**（Mutability）：追加（append）、合并（consolidate）、变异（mutate）。
  - **四种范式**：
    - 范式I：长上下文记忆（long-context memory）——直接用模型上下文作为记忆。
    - 范式II：平面RAG记忆（flat RAG memory）——确定性索引（如BM25、EmbedRAG），无LLM参与。
    - 范式III：结构增强RAG记忆（structure-augmented RAG memory）——使用LLM提取事实、关系等，分为追加（append-only，如GraphRAG、HippoRAG v2）和合并（consolidating，如Mem0、SimpleMem）。
    - 范式IV：智能体控制流（agentic control flow）——LLM决定何时读写，如A-Mem、Letta、MIRIX。
  - **阶段感知剖析工具**（将开源）：
    - 记录API遥测（调用的模型、token数、延迟等）和硬件遥测（GPU利用率、功耗、带宽等），按阶段归因。
    - 支持远程（OpenAI API）和本地（vLLM）两种部署模式。
- **关键指标**：构建时长、每查询延迟、每正确回答的能耗、存储大小、尾部延迟、新鲜度 vs 延迟权衡等。

## 6. 论文的主要结论与发现

- **结论1**：长时段全历史预填成本巨大（~38秒/查询），外部记忆系统可大幅降低查询延迟（如Mem0 <0.1秒），但系统间查询延迟差异达两个数量级。
- **结论2**：构建能耗主导智能体生命周期：对大多数LLM介导的记忆系统，构建能耗超过300次查询的总能耗；每正确回答能耗跨系统差异超过47倍。
- **结论3**：构建工作负载主要由预填和嵌入主导（而非解码），范式III.a的嵌入流量是大批量的，范式III.b和IV是连续的；建议将构建作为后台吞吐量工作负载，并分别处理嵌入批处理。
- **结论4**：构建LLM降级可用，但受算法限制：无硬性输出契约的系统（如Mem0, SimpleMem, A-Mem）可平滑降级；有严格输出契约的系统（如MIRIX）在模型能力不足时完全失败。
- **结论5**：无单一系统同时在构建成本、查询延迟和准确度上最优；选择需匹配工作负载的查询到达模式和任务类型。
- **结论6**：会话间构建时间若超过会话到达间隔，会导致同步调度暴露延迟或异步调度引入陈旧记忆；每个会话的构建时间跨度达5个数量级。
- **结论7**：每个用户的内存占用在1M token时差异达9倍，但构建token成本差异更大（范式IV呈超线性增长）；长期成本由算法增长斜率决定。
- **结论8**：算法有界（algorithm-bounded）的系统尾部延迟窄，LLM有界（LLM-bounded）的系统尾部宽（p95/p50可达5.9倍），需要外部迭代上限。

## 7. 优点：方法或实验设计上的亮点

- **系统级视角领先**：首次从系统性能（延迟、能耗、存储、可扩展性）而非仅准确度角度全面刻画智能体记忆，填补了研究空白。

- **考虑调度和可扩展性**：通过MemoryArena分析会话间调度和新鲜度权衡，通过缩放实验分析用户历史增长的影响，覆盖了实际部署关键问题。
- **公平性努力**：标准化LLM和嵌入骨干，最小化适应改动，并详细说明了适应策略。

## 8. 不足与局限：包括实验覆盖、偏差风险、应用限制

- **实验覆盖有限**：主要深度分析基于LongMemEval_S_*（五个样本），虽在一定程度上外推到全MAB和MemoryArena，但样本量较小，统计稳健性可能不足。
- **单节点实验**：所有实验在单GPU上进行，未覆盖多节点、多智能体分布式部署场景，而后者引入协调和一致性需求。
- **未考虑多模态记忆**：论文指出多模态记忆（图像、音频等）是新兴挑战，但研究仅限于文本模态。
- **适应性修改可能引入偏差**：为适配非对话任务而修改提示词和参数（如Letta工具调用上限、Mem0提取提示词等）可能偏离系统原始设计，影响比较的公平性。

- **遗忘策略缺失**：所有评估系统默认单调累积记忆，没有内置遗忘策略；论文指出需要独立施加遗忘策略，但未在实验中测试其影响。
- **可复现性挑战**：虽然剖析工具将开源，但各系统的配置和适应性修改细节较多，精确复现可能需额外工作。
