## 摘要
对话和使用工具的LLM智能体在上下文窗口上运行，该窗口同时从多个方向填充。随着会话的进行，智能体累积用户和助手的对话轮次、从持久记忆存储中提取的条目，以及通常最大的部分——工具调用的逐字输出，如文件读取、搜索结果和API响应。一旦累积的上下文超过模型的令牌预算，框架必须决定保留哪些内容。当前的主要机制是最近截断，有时结合定期摘要。这是主题无关的：会话早期建立的事实仅仅因为陈旧而被丢弃，即使当前用户查询正是关于该事实；相反，冗长但无关的最新材料被保留。必须在多个轮次中回忆信息的智能体（记忆的定义案例）正是最近截断失败的地方。现有的替代方案位于智能体的组装步骤之外。检索增强生成将外部文档提取到提示中，但不仲裁智能体已经存在的池化上下文。上下文压缩方法通过重写或修剪文本来减少令牌数量，但在查询盲和有损的方式下操作。两者都不将记忆条目、对话轮次和工具输出视为一个单一的候选池，以便在提示组装时根据相关性进行选择。

## Abstract
Conversational and tool-using LLM agents operate over a context window that fills from several directions simultaneously. As a session proceeds, the agent accumulates user and assistant turns, entries drawn from a persistent memory store, and often largest of all, the verbatim outputs of tool calls such as file reads, search results, and API responses. Once the cumulative context exceeds the model's token budget, the framework must decide what to keep.   The prevailing mechanism is recency truncation, sometimes paired with periodic summarization. This is topic-blind: a fact established early in a session is discarded simply because it is old, even when the current user query is about exactly that fact; conversely, verbose but irrelevant recent material is retained. Agents that must recall information across many turns, the defining case for memory, are precisely where recency truncation fails.   Existing alternatives sit outside the agent's assembly step. Retrieval augmented generation fetches external documents into the prompt but does not arbitrate the agent's \emph{already-present} pooled context. Context-compression methods reduce token count by rewriting or pruning text, but operate query-blind and lossily. Neither treats memory entries, conversation turns, and tool outputs as a single candidate pool to be selected from by relevance at the moment the prompt is assembled.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **问题**：长程运行的LLM智能体在会话过程中不断积累来自用户轮次、持久记忆和工具调用输出的上下文，其总量常常超出模型的有效token预算。
- **现有缺陷**：主流默认策略是**最近截断**（recency truncation），虽简单但**主题盲目**——会丢弃早期建立的关键事实，而保留近期的无关噪音。其他替代方案如RAG（不仲裁智能体已有的池化上下文）和上下文压缩（查询盲且损失性压缩）均无法在提示组装时对记忆、对话和工具输出进行统一的、预算感知的即时相关性筛选。
- **意义**：将上下文组装问题重新定义为**预算约束下的子模选择**，并提供一个可插拔引擎，使智能体能够根据当前查询动态保留最相关的上下文，提升长程记忆检索能力。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：将候选上下文视为一个**统一池子**，包含记忆条目、对话轮次和工具输出。在每次提示组装时，给定最新查询q和token预算B，选择一个子集S，使得S在预算内最大化**查询相关的覆盖度**，同时消除冗余。
- **目标函数**：采用**设施选址**（facility-location）子模函数：
  - 定义相关性 `rel(i,q) = max(0, cos(e_i, e_q))`，覆盖权重 `w_ij = rel(i,q) · max(0, cos(e_i, e_j))`。
  - 目标：`max F(S) = Σ_i max_{j∈S} w_ij`，约束 `Σ_{j∈S} tok(j) ≤ B` 且强制保留集合M。
  - 该函数是**单调子模函数**，支持贪心算法获得常数因子近似保证。
- **算法**：使用**CELF懒惰贪心**算法（cost-aware greedy），在每次迭代中选择能带来最大边际收益且不超过预算的候选。
- **与MMR的关键区别**：
  - 范围不同：MMR的冗余惩罚只考虑已选集合内部，而PACMS的覆盖项对整个候选池求和，奖励覆盖未覆盖区域的候选。
  - 加权方式不同：PACMS的覆盖权重由每个目标项的 relevance 加权，MMR的相似度惩罚与relevance无关。
  - 理论保证不同：PACMS有常数因子近似，MMR是启发式无界。
- **系统设计**：PACMS作为OpenClaw智能体框架的**可插拔上下文引擎**，实现 `assemble()`，将压缩委托给宿主运行时。通过FastAPI服务暴露 `/select` 和 `/select_debug` 接口，使用本地Ollama嵌入缓存。

## 6. 论文的主要结论与发现

- **核心发现**：PACMS在**证据轮次召回率**上与MMR相当，但在**端到端QA准确率**上显著领先。
  - 在45%预算、R=2下：PACMS比lc-mmr高+8（GPT-5-mini）和+12（GPT-5.4-mini）个百分点；甚至超过top-k（+2/+4）。
  - **召回率与QA准确率的分歧**：PACMS召回率略低于top-k（0.909 vs 0.933），但QA准确率却更高，说明**设施选址覆盖产生的提示更利于下游读者抽取信息**，优于纯相关排序和成对多样化。
- **排名稳定**：`PACMS > top-k > lc-mmr ≥ last-k` 在两个读者下一致。
- **最近截断的彻底失败**：last-k在所有条件下表现最差，且更强读者无法弥补（因为主题盲丢弃了证据）。
- **理论保证转化为实际效益**：子模优化的常数因子近似在实际中产生了可观测的改进。
