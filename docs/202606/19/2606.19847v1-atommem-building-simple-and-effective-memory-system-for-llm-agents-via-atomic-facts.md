## 摘要
大型语言模型（LLM）展现了强大的推理和生成能力，但其固定的上下文窗口限制了长期信息的积累和在多会话交互中的复用。现有的记忆增强系统通常以粗粒度且不稳定的方式构建记忆，依赖于低效的记忆表示或不稳定的无约束更新。为了解决这些挑战，我们提出了AtomMem，一种专为价值密集型存储和稳定记忆演化设计的长时记忆系统。AtomMem引入了一个事实执行器（Fact Executor），它从长形式交互中选择性地提取高价值原子事实，作为高效记忆表示。随后，AtomMem将这些事实组织成层次化事件结构和时间剖面，捕获连贯的情节上下文并随时间追踪动态演化的用户属性。在检索过程中，系统激活一个关联记忆图来连接碎片化的记忆。在LoCoMo基准上的实验证实，AtomMem在各种推理任务中达到了最先进的性能，为部署智能个性化智能体提供了可扩展且经济可行的解决方案。

## Abstract
Large language models (LLMs) demonstrate strong reasoning and generation abilities, but their fixed context windows limit long-term information accumulation and reuse across multi-session interactions. Existing memory-augmented systems often construct memory in a coarse and unstable manner, relying on inefficient memory representations or unstable unconstrained updates. To address these challenges, we propose AtomMem, a long-term memory system designed for value-dense storage and stable memory evolution. AtomMem introduces a Fact Executor, which selectively extracts high value atomic facts from long form interactions to serve as highly efficient memory representations. Subsequently, AtomMem organizes these facts into hierarchical event structures and temporal profiles, capturing coherent episodic contexts and tracking dynamically evolving user attributes over time. During retrieval, the system activates an associative memory graph to connect fragmented memories. Experiments on the LoCoMo benchmark confirm that AtomMem achieves state-of-the-art performance across various reasoning tasks, offering a scalable and economically viable solution for deploying intelligent personalized agents.

## 1. 核心问题与研究动机

### 背景与挑战
- 大语言模型（LLM）在推理和生成方面能力强大，但其固定的上下文窗口限制了跨多会话交互的长期信息积累与复用。
- 现有记忆增强系统（如Mem0、AMem、LightMem等）存在以下根本性问题：
  - **记忆表示粗粒度**：直接存储原始对话导致信息冗余，检索时引入大量噪声；而过度压缩则丢失细节。
  - **记忆更新不稳定**：依赖LLM频繁重写现有条目，容易引入幻觉或错误编辑，导致记忆膨胀和原始事实破坏。
  - **关联检索困难**：有用记忆分散在多会话中，平面检索难以捕获跨会话的复杂关联。

### 目标
- 设计一个简单、有效且稳定的长期记忆系统，实现高信息密度存储、可控的记忆演化以及高效的图式关联检索，使LLM智能体能够保持对用户一致且可靠的理解。

## 2. 方法论（核心思想与关键技术）

### 整体架构
AtomMem 以**原子事实（Atomic Facts）**为核心，构建层级记忆结构（原子事实 → 事件记忆 → 时间画像），并通过**关联记忆图**在检索时激活相关记忆。

#### 2.1 原子事实提取（Fact Executor）
- **目标**：将原始对话转化为自包含、结构化、高价值的原子事实。
- **方法**：
  - 通过**监督微调（SFT）**训练一个轻量级LLM（基于Qwen3-14B，LoRA）作为事实提取器。
  - 构造高质量训练数据集（含4,352样本，通过教师模型GPT-4o提取 + 人工精炼）。
  - 提取时执行降噪、指代消解、时间锚定等轻量推理，输出格式化为结构化原子事实：
    - `{id, c (文本), v (嵌入向量), P (参与者), K (关键词), T (时间), E (事件ID列表)}`
  - 事实验证：通过混合相似度（语义嵌入+关键词Jaccard）检测重复或冲突，LLM决定是存储新事实、更新已有事实还是忽略。

#### 2.2 事件记忆构建（Episodic Consolidation）
- **定义**：事件E = `{id, S (摘要), Fids (事实ID集), Pe, Ke, Te}`。
- **动态更新算法**：新原子事实进入时，根据与已有事件的语义和逻辑匹配，吸收到现有事件（更新摘要、参与者、时间跨度）或创建新事件，或独立存储。

#### 2.3 时间画像建模（Temporal Profile）
- **目的**：捕获用户稳定但演化的长期属性（偏好、习惯、背景）。
- **结构**：画像条目P = `{id, u, c, vp, Kp, Eevi (支持事实), tf rom, H (历史版本)}`。
- **更新机制**：会话结束时批量处理。使用混合相似度匹配最相关的现有画像，LLM决定冗余、更新、保留历史或创建新条目。

#### 2.4 关联记忆图与检索（Associative Recall）
- **图结构**：以原子事实为节点，三种边：
  - **实体边**：基于关键词（IDF加权重叠）。
  - **事件边**：属于同一事件的事实。
  - **时序边**：同会话相邻对话轮次的事实。
- **检索流程**：
  - **查询意图分析**：解析用户查询，提取是否需要画像、参与者、关键词、时间范围。
  - **层级混合检索**：
    1. **主检索**：按参与者/时间过滤，按混合相似度取前`ks/2`事实。
    2. **补偿检索**：从匹配事件中提取事实，融合事件相关性与事实自相关性评分，取前`ks/2`事实。
    3. **关联检索**：以种子事实激活图，通过带重启的随机游走（RWR）传播激活，选择前`kf`事实。
  - **画像增强**：若需要，检索匹配的用户画像。
- **响应生成**：将检索到的事实集和画像集拼接，输入LLM生成答案。

## 6. 主要结论与发现
- **AtomMem在所有任务上达到SOTA**，尤其在多跳和时间推理任务上显著优于最强基线LightMem（J-score提升5.5%和31.1%）。

- **各组件均有效**：消融实验显示，移除画像使单跳F1下降约10%，移除图检索使多跳F1下降约5%。
- **检索容量需平衡**：k=10时最优，过多则引入噪声导致性能下降。
- **计算效率高**：总token消耗仅为Mem0的约38.6%，同时保持高质量。

## 7. 优点
- **方法新颖**：首次系统地将“原子事实”作为基础记忆单元，并构建多层语义结构（事件+画像），实现高密度、可追溯的长期记忆。
- **设计稳定**：通过事实验证和版本历史机制，避免无约束更新导致的记忆退化。
- **检索高效**：图式关联检索结合RWR，有效连接跨会话碎片化信息，且检索延迟极低（平均~146ms）。
- **实验全面**：在两大基准上多角度评估，消融实验深入，超参数分析细致。
- **可复现**：开源代码，提供详细超参数配置。

## 8. 不足与局限
- **依赖LLM能力**：多个阶段（事实提取、验证、更新、意图分析）依赖底层LLM的生成稳定性，若基座模型性能波动，系统可靠性受影响。
- **仅支持文本**：当前框架只处理文本交互，而真实对话常涉及图像、音频等多模态输入，尚未扩展。
- **token效率可进一步优化**：虽优于Mem0，但完整版总token消耗仍有约21k，仍有压缩空间。
- **实验偏差风险**：训练数据（LoCoMo风格）与评估数据（LoCoMo测试集）虽然主题不重叠，但对话生成范式相同，可能存在分布偏移。LongMemEval的补充实验部分缓解此问题。
- **画像更新机制**：采用会话级批量处理，可能无法实时反映即时变化。
- **计算成本**：完整版需多次LLM调用（提取、验证、事件更新、画像更新、意图分析等），在线延迟主要来自LLM推理（平均3.6s），虽检索快，但整体响应时间可能对实时性有要求。
