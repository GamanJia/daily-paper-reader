## 摘要
长周期智能体可以归档大量历史记录，但未来的答案仍会产生检索、重读和上下文成本。当保留的记忆缺少与答案相关的证据时，系统必须返回到原始历史记录的更大片段。我们研究预算证据生存问题：在查询未知之前，应保留哪些源证据，以便在固定的保留源证据令牌预算下，这些证据仍然可恢复且可用？我们将此设置实例化为预算预查询保留，其中记忆在摄取期间写入，之后在无法访问完整原始数据流的情况下读取。我们引入EMBER，一种学习得到的保留策略，它构建一个紧凑的、基于源证据的证据状态。EMBER存储证据胶囊：逐字源摘录，配有检索键和更新元数据，保留grounding和读取时访问。查询后结果反馈训练写入器在摄取-检索-答案链中保留证据。在LongMemEval-RR上，这是我们基于LongMemEval派生的保留证据协议，EMBER-14B在8192令牌保留证据比较点达到0.3017 F1，而最强的非EMBER预算基线为0.1765。在不同的保留源证据预算下，EMBER提高了F1、保留召回率和读取召回率，表明长周期记忆依赖于在预算内保留证据，而不是重读更大的历史记录。

## Abstract
Long-horizon agents can archive large histories, but future answers still incur retrieval, rereading, and context costs. When retained memory misses answer-relevant evidence, the system must return to larger portions of the raw history. We study budgeted evidence survival: before the query is known, which source evidence should be retained so that it remains recoverable and usable under a fixed retained source-evidence token budget? We instantiate this setting as Budgeted Pre-Query Retention, where memory is written during ingestion and later read without access to the full raw stream. We introduce EMBER, a learned retention policy that constructs a compact, source-backed evidence state. EMBER stores evidence capsules: verbatim source excerpts paired with retrieval keys and update metadata, preserving both grounding and read-time access. Post-query outcome feedback trains the writer to preserve evidence across the ingestion-retrieval-answer chain. On LongMemEval-RR, our LongMemEval-derived retained-evidence protocol, EMBER-14B reaches 0.3017 F1 at the 8192-token retained-evidence comparison point, compared with 0.1765 for the strongest non-EMBER budgeted baseline. Across retained source-evidence budgets, EMBER improves F1, Retain-Recall, and Read-Recall, indicating that long-horizon memory depends on retaining evidence within the budget rather than rereading larger histories.

#### 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：长周期运行的智能体（如对话助手、编码机器人）需要处理并存储海量历史信息（如对话记录、代码文件、工具调用痕迹）。然而，在未来的查询（问题）到来之前，智能体无法预知哪些信息是重要的。如果将所有历史信息都归档为可检索的原始日志，在回答问题时将导致高昂的检索成本和上下文窗口消耗。论文的核心问题是：**在不知道未来查询的情况下，如何在一段固定的“源证据预算”（Bret，例如8192个token）内，从连续的数据流中保留最有可能对未来答案有用的证据，从而避免在回答问题时重读完整的历史记录？**

- **研究动机**：现有研究存在两种极端：
    - **完整日志RAG**：保留所有原始日志，查询时可访问全部信息，但成本高，且延迟了“什么重要”的决策。
    - **查询可见记忆**：在查询已知后才进行记忆操作，这不符合现实场景中智能体“写入时未知查询，读取时才知晓”的常见约束。
    - 本文重点研究一种更现实的约束：**预算预查询保留（Budgeted Pre-Query Retention）**。智能体必须在摄入信息时，在预算限制下决定哪些源证据值得保留，以备未来之需。这比“重读更大历史”更高效，因为它聚焦于从根源上提高记忆质量。

#### 2. 论文提出的方法论：核心思想、关键技术细节、算法流程

- **核心思想**：通过学习一个**保留策略（Retention Policy）**，在信息摄入阶段，智能地选择并存储“证据胶囊（Evidence Capsules）”。这些胶囊由源文本的精确摘录、检索键和元数据构成，确保未来既能被找到又能被原文使用。最终通过查询后的答案反馈来端到端地训练整个策略。

- **关键技术细节**：
    1.  **预算预查询保留（Budgeted Pre-Query Retention）**：形式化地定义了该问题。智能体在摄入流式数据时，必须构建一个有限的记忆状态（St），其大小受源证据预算Bret约束。查询q在记忆构建完成后才被揭示。
    2.  **证据胶囊（Evidence Capsules）**：记忆的基本单元，包含三部分：
        - **源摘录**：从原始数据流中摘录的、携带证据的原文。
        - **检索键**：一组用于在查询时检索该胶囊的键（如实体、意图描述）。
        - **元数据**：包括更新模式（插入、合并、覆盖、跳过）等信息。
    3.  **答案门控证据链训练（Answer-Gated Evidence-Chain Training）**：这是关键训练方法，使用强化学习（GRPO）。其核心是：训练奖励不仅取决于最终答案的质量（Qi），还取决于证据在记忆中的存活情况（Ei）、检索时的排名（Li）、选择的纯度（Pi）和写入的有效性（Wi）。所有这些辅助奖励都被最终答案质量门控（乘以Qi），即**只有当最终答案正确时，中间的记忆环节才能获得正面奖励**。这迫使策略学会保留对答案真正有用的证据。
    4.  **算法流程**（简化描述）：
        - **摄入阶段**：智能体逐步读取数据流，利用“可答案性探针”判断当前片段是否值得保留。如果值得，则生成一个证据胶囊（包含源摘录和检索键），并通过预算会计模块更新记忆库St。
        - **查询与检索阶段**：查询到来后，智能体仅从保留的记忆库St中检索文档。
        - **证据选择与答案生成**：从检索结果中选择与查询最相关的保留证据，并基于这些证据生成答案。
        - **训练**：将整个“摄入-检索-回答”过程作为一个轨迹，通过奖励函数（由答案质量门控）进行端到端的强化学习（GRPO）。

#### 6. 论文的主要结论与发现

- **根本性结论**：**长周期记忆的成功取决于在预算内保留正确的证据，而非重读更大的历史记录**。EMBER证明了通过学习，可以更高效地利用有限的记忆预算。

- **证据链的可分解性**：通过Retain-Recall和Read-Recall指标，论文成功地将性能瓶颈分解为“写入时丢失证据”和“读取时遗漏证据”两类，证明了EMBER在这两个环节上都优于基线。
- **多查询支持**：在MultiQ实验中，EMBER-14B的F1（0.2767）远超最强启发式基线（0.0824），表明其保留的记忆能更好地服务于多个未来查询。

#### 8. 不足与局限

- **对证据标注的依赖**：训练和评估高度依赖于“黄金证据（gold evidence）”的标注。在真实应用中，哪些是回答未来问题的关键信息本身就是模糊和难以标注的。这限制了方法在无标注数据上的直接应用和泛化。
- **读者/检索器的固定**：实验中为了稳定训练，固定了检索器和读者（如GPT-4o）。这种“写-读”分离的设定可能会引入偏向，即策略可能过拟合于特定的检索/读者模型。联合优化“写-读”是一个自然的延伸方向，文中未涉及。
- **领域泛化**：实验主要在长对话和问答领域进行。虽然任务设计（更新、时间推理等）模拟了通用场景，但结论是否适用于编程代码、金融交易记录、科学研究笔记等其他类型的长周期数据，有待验证。
- **隐私与安全风险**：论文本身提及了这一点但未深入探讨。选择性保留证据可能导致隐私风险被放大（保留了敏感信息）或审计困难（删除了某些证据）。部署时需要严格的控制机制，但这在论文中不是研究的重点。
- **Oracle上限的局限性**：虽然Oracle提供了很好的上限参考，但Oracle使用的是基于特定问答的黄金标签。在实际的“预查询”场景中，一个片段在未来可能对不同查询有不同重要性，Oracle并不能完全反映真实的最优策略。因此，EMBER与Oracle之间的差距并非全由方法缺陷导致，也包含了这种理想化假设。
