## 摘要
个人智能体记忆的核心作用是将存储的信息和先前的交互转化为面向未来的辅助。在日常使用中，有用的线索来自智能体观察到的内容以及用户与智能体的交互方式，智能体必须将这些线索从当前请求延续到类似的未来任务中。现有的记忆基准测试通常分别测试对话回忆或任务改进，而将从流式观测到后续辅助的整个轨迹基本未得到测试。我们提出了StreamMemBench，这是一个流式基准测试，围绕来自EgoLife自我中心流的每个证据锚点构建两步任务序列。初始任务测试证据的使用，而后续任务测试反馈和交互经验是否被重用。四个指标评估证据回忆、初始证据使用、反馈整合和后续重用。在两个主干上的八个记忆系统的实验表明，当前的系统通常无法使用观察到的证据，或者无法将反馈转化为可靠的后续行为，即使证据被存储或反馈被局部整合。StreamMemBench在https://github.com/landian60/StreamMemBench公开发布。

## Abstract
A central role of personal-agent memory is to turn stored information and prior interactions into future-oriented assistance. In daily use, useful cues come from what the agent observes and how the user interacts with the agent, and the agent must carry them forward from the current request to similar future tasks. Existing memory benchmarks usually test dialogue recall or task improvement in isolation, leaving the trajectory from streaming observations to later assistance largely untested. We introduce StreamMemBench, a streaming benchmark that constructs a two-step task sequence around each evidence anchor from EgoLife egocentric streams. The initial task tests evidence use, while the follow-up task tests whether feedback and interaction experience are reused. Four metrics diagnose evidence recall, initial evidence use, feedback incorporation, and follow-up reuse. Experiments with eight memory systems across two backbones show that current systems often fail to use observed evidence or turn feedback into reliable follow-up behavior, even when evidence is stored or feedback is incorporated locally. StreamMemBench is publicly available at https://github.com/landian60/StreamMemBench.

## 2. 论文提出的方法论

### 2.1 核心思想

- 基于EgoLife数据集（6人7天连续自我中心记录）抽取用户特定证据（如偏好、习惯、关系、能力等），每个证据锚点对应一个两步任务序列：
  - **初始任务（Initial Task）**：测试智能体是否能在观察到相关证据后正确回答问题（证据使用）。
  - **后续任务（Follow-up Task）**：智能体在先前的交互中收到用户反馈（确认或纠正），然后将该交互经验（包括反馈）提交到记忆，再回答一个基于同一证据但场景不同的新问题（经验重用）。
- 四项指标诊断贯穿全路径：
  - **Fidelity (Fid)**：在任务开始前，直接检查智能体暴露的记忆增量中是否包含目标证据（过程指标）。
  - **Initial Evidence Use (IEU)**：初始回答是否使用了目标证据（性能指标）。
  - **Feedback Incorporation (FI)**：当初始回答错误时，智能体是否在反馈后修正回答（仅在修正场景下计算，性能指标）。
  - **Follow-up Reuse (FUR)**：后续回答是否重用了证据或交互经验（性能指标）。

### 2.2 关键技术细节

- **数据构建**：
  - 将EgoLife原始数据划分为3347个5分钟流片段，每个片段包含约200条带时间戳的观察（自我中心描述或对话转录）。
  - 使用构建智能体 `A_anchor` 从每个片段中提取证据锚点 `(a_k, T1, T2)` 三元组。T1和T2为两个不同应用场景的任务查询，正确答案依赖于证据 `a_k`，且查询中不泄露证据（Leak=0）、必须需要证据才能正确回答（Need=1）、拟真自然（Natural=1）。
  - 使用审查智能体 `A_review` 检查上述条件，并保证两个查询场景不同、依赖同一证据。
- **评估轨迹**：
  - 记忆系统 `M` 按时间顺序摄入流片段（直到提取证据锚点的那一段），然后进入任务序列：
    1. 接收T1 → 生成R1 → 接收模拟用户反馈F → 生成修正回答RF。
    2. 将完整交互（T1, R1, F, RF）通过自身记忆接口提交给 `M`。
    3. 接收T2 → 生成R2。
  - 用户模拟器 `A_user` 基于证据锚点给出反馈（确认或纠正）并打分。
  - 评估智能体 `A_eval` 用于Fidelity检查。
- **评分细则**：
  - Fidelity：将 `M` 在摄入每个片段后暴露的记忆增量与证据锚点进行语义匹配。
  - IEU、FI、FUR：`A_user` 将回答与期望行为（基于证据的gold_behavior_spec）比较，只在使用证据时才通过。FI仅对修正场景计算。
  - 所有判断做3次多数投票。

### 2.3 公式或算法流程（文字说明）

- 算法流程：
  1. 输入：EgoLife流 L = (z1,...,zn)，每个zi为5分钟段。

  5. 聚合所有锚点的通过率。

## 6. 论文的主要结论与发现

1. **当前记忆系统在流式未来辅助上表现差**：即使有高Fidelity（证据已存储），IEU和FUR仍可能很低（如MemOS的IEU仅2.94%、FUR 3.96%）。
2. **证据存储≠任务使用**：存在普遍缺口（Fidelity - IEU），表明存储信息未在回答时被有效检索或利用。
3. **反馈的局部修复≠后续复用**：大部分系统FI远高于FUR，说明能根据即时反馈修正答案，但未将修正后的经验巩固到记忆中以用于未来任务。
4. **时间漂移明显**：随着流增长（更多观测被摄入），某些系统的证据使用可靠性下降（如RAG raw的IEU从早期到晚期下降）。
5. **故障模式差异**：不同记忆机制的主要瓶颈不同：
   - 原始检索（RAG raw、A-Mem、MemoryOS）故障集中在初始使用或后续复用阶段（形成失败少）。
   - 提取/事实系统（RAG ext、Mem0、MemSkill）有较高形成失败。
   - MemOS表现为修正巩固失败为主（FI高但FUR极低）。

## 7. 优点

- **创新性**：首次提出流式未来辅助评估框架，将记忆能力分解为证据使用和经验重用，并设计对应的两步任务序列和四指标体系。
- **数据真实性**：采用真实自我中心视频流EgoLife，场景自然，避免了合成数据带来的偏差。
- **可追溯性**：通过证据锚点，每条证据从其起源到最终使用/遗漏的状态均可追踪，支持细粒度诊断。
- **全面性**：覆盖了8种有代表性的记忆系统，包括检索、主动管理、过程记忆等类型，在两个LLM基座上验证。
- **诊断能力**：不仅仅给出一个分数，而是通过Fidelity、IEU、FI、FUR定位故障发生在哪个环节，为系统改进提供明确方向。
- **公开可用**：代码和数据集均在GitHub开源。

## 8. 不足与局限

- **覆盖范围有限**：仅评估了有限数量的记忆系统，未包括商业助手（如ChatGPT、Gemini）的最新记忆功能，也未包括更多类型的记忆架构（如基于图或向量数据库）。
- **数据局限**：EgoLife只有6名参与者7天的数据，样本量小，可能缺乏多样性（如不同文化、语言、年龄的用户行为）。此外，数据只包含第一人称观察和对话转录，不包含用户内部的思考或复杂决策过程。
- **反馈模拟**：用户反馈由LLM模拟，可能不够真实或多样化（如情绪化反馈、模糊反馈等未覆盖），且反馈始终是基于完美信息（知道正确答案），而真实用户可能不提供反馈或反馈不准确。
- **任务设计**：任务查询由LLM生成，虽经审查，但仍有潜在模板化或与真实用户需求偏离的风险。此外，任务仅两步，未覆盖多轮交互或长期持续学习。
- **隐私风险**：基准基于自我中心数据，评估可能鼓励系统存储敏感信息，需要严格隐私保护措施。
- **计算成本**：未比较训练/推理的实际硬件消耗，不同系统在成本-效益上未充分讨论（表3仅给出了存储/延迟/令牌，但未联系性能）。
- **缺乏消融实验**：未深入分析不同任务类型（如推理型 vs 状态型）、不同反馈类型（确认 vs 纠正）的影响，也未对比不同证据类型（陈述型 vs 推断型）的难度差异。
- **评估者偏差**：`A_user` 和 `A_eval` 同为LLM，可能存在自洽性偏差，尽管使用了多数投票和人工审计缓解，但仍需更全面的评估者互信分析。
