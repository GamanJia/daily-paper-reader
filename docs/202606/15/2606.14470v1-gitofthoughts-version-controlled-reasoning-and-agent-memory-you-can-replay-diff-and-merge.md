## 摘要
大语言模型推理是短暂的：思维链随着上下文窗口消失，修剪的搜索分支不留记录，记忆缓冲区无法进行差异比较、合并或审计。所有其他复杂软件过程（代码、基础设施、数据、实验）都有版本控制；推理却没有。我们提出GitOfThoughts，它将智能体的推理树存储为git仓库：每个评分的想法是一次提交，分数是注释，结果是标签，检索是在智能体自身历史中执行“git log”。这使得推理可以回放、审计，并在近乎零工程成本的情况下跨智能体合并。然后我们提出一个更难的问题：记忆在任何基底上是否真的能提高准确性？跨五种基底（无、markdown、向量、图、git）、两个基准、两种模型规模和预注册的复现，对于新颖问题的答案是否定的。没有任何记忆格式可靠地有所帮助，一个有希望的早期结果在其自身的预注册复现中崩溃了。记忆只有在超过我们所谓的可复制性阈值时才起作用：当检索到的案例与当前问题几乎重复（相似度>~0.8）时，准确性急剧提升；低于该阈值则无效果。收益是答案检索，而非方法迁移：一个4.5倍大的模型使近重复收益翻倍，但仍然无法从已解决的示例中提取可迁移的方法。我们发现的唯一通用杠杆是测试时采样。因此，git作为基底的案例在于审计性、溯源性和合并性，同时保持准确性相当。我们记录了一个被撤回的结果和一个被反驳的假设，以此建模我们所坚持的评估标准。

## Abstract
Large language model (LLM) reasoning is ephemeral: chains of thought vanish with the context window, pruned search branches leave no record, and memory buffers cannot be diffed, merged, or audited. Every other complex software process (code, infrastructure, data, experiments) is version-controlled; reasoning is not. We introduce GitOfThoughts, which stores an agent's reasoning tree as a git repository: every scored thought is a commit, scores are notes, outcomes are tags, and retrieval is "git log" over the agent's own history. This makes reasoning replayable, auditable, and mergeable across agents at near-zero engineering cost.   We then ask the harder question: does memory, in any substrate, actually improve accuracy? Across five substrates (none, markdown, vector, graph, git), two benchmarks, two model scales, and pre-registered replications, the answer for novel problems is no. No memory format reliably helps, and a promising early result collapsed under its own pre-registered replication. Memory pays only above what we call the copyability threshold: when the retrieved case is a near-duplicate of the current problem (similarity >~ 0.8), accuracy jumps sharply; below it, nothing. The gain is answer retrieval, not method transfer: a 4.5x larger model doubles the near-duplicate payoff yet still cannot extract a transferable method from a worked example. The only general lever we find is test-time sampling. The case for git-as-substrate is therefore auditability, provenance, and mergeability at accuracy parity. We document a retracted result and a refuted hypothesis to model the evaluation standard we hold ourselves to.

## 1. 核心问题与整体含义（研究动机和背景）

- **问题**：LLM 推理过程是短暂的——思维链随上下文窗口消失、修剪的搜索分支不留记录、记忆缓冲区无法差异比较、合并或审计。这种“短暂性”阻碍了可复现性、审计、记忆迁移和事件回顾。
- **背景**：软件工程中代码、基础设施、数据、实验均已版本控制，但推理仍是无版本的。作者将推理视为“最后一个未版本化的软件过程”，因此提出将推理树作为 git 仓库存储，以获得可回放、可审计、可合并的推理历史。
- **核心假设**：
  - H-substrate：版本控制的推理基底（git）在准确性上与常规记忆存储持平，同时提供回放、审计、差异、合并等操作价值。
  - H-memory：跨问题记忆能提高智能体在新问题上的准确性。

## 2. 方法论

- **核心思想**：将推理树（有向无环图 DAG）映射到 git 数据结构——每个评分后的思考节点作为一次 commit，分数作为 git notes，验证结果作为 tags，检索使用 `git log`（支持 `--grep`、`-S` pickaxe、tag 过滤）。推理路径可分支、合并，记忆跨 session 持久化。
- **关键技术细节**：
  - **推理管线**：外层为深度 1、分支因子 4 的树状搜索（Tree-of-Thoughts）；内层为 ReAct 循环（最多 3 步），配有计算器、sympy 求解器、pulp LP 求解器。得分公式：\( s = 0.6 s_{\text{local}} + 0.4 s_{\text{cross}} \)；最佳子节点被验证并打上 `success/best` 或 `failed` 标签。（注意：MCQ-aware expansion（多选题选项展开）是最大准确率杠杆。）
  - **Git 原生记忆**：每个问题在独立仓库中解决，`commit-on-score` 钩子写入 `thought.md`、`scores.json`、`trace.jsonl`、`metadata.json` 四个文件，附加 git note 和 outcome tag。长期记忆分支存储跨问题洞察。检索使用 `git log --grep`、`-S`、`git tag -l 'success_*'`，并按置信度加权排序（\(\rho = 0.7 s_{\text{comb}} + 0.2 \text{tag} + 0.1 \text{recency}\)）。
  - **审计性**：可重放任意 SHA 状态、对推理文本做行级 diff、跨代理 git merge 记忆、使用 `git log -S` 进行公平性审计。
- **算法流程（文字描述）**：
  1. 对于每个问题，创建临时 git 仓库。
  2. 使用树搜索生成思考节点（每个节点对应一个 commit），附上分数和验证标签。
  3. 成功路径合并到 `main` 分支；可迁移的无答案教训蒸馏到长期 `memory` 分支。
  4. 跨问题检索时，代理对 `memory` 分支执行 git 操作获取相关教训。

## 6. 主要结论与发现

- **H-memory 被拒绝**：在新问题上，所有记忆基底（markdown、vector、graph、git）均未可靠提升准确率。一个早期 git 的 +15pp 趋势在预注册复现中消失（+1.0pp）。大规模 n=500 实验中，self-consistency 是唯一显著提升（+3.4pp*）。无记忆基底显著优于无记忆。
- **记忆只在可复制性阈值之上有效**：当检索案例与当前测试题余弦相似度 >~0.8 时，记忆带来显著提升（7B: +12~+13.5pp*；32B: +22.5~+28.5pp*）。这明确是答案检索而非方法迁移，因为相同方法但不同数字（余弦~0.72，不可复制答案）的对比臂完全无效（-4.1pp）。
- **模型规模放大可复制性收益但不实现方法迁移**：32B 的近重复收益几乎翻倍（+28.5pp），但方法迁移臂仍为负（-3.6pp），说明更大模型并不自动实现从示例中提取可迁移方法的能力。
- **测试时采样（self-consistency）是唯一通用杠杆**：在多种设置下唯一显著提升准确率的方法。
- **Git 的价值在于运营性而非检索提升**：git 在所有实验中与最佳基底准确率相当（无显著差异），但提供了唯一的结构性操作（三向合并、签名、可复现包、冲突检测），并能通过功能演示合并两个代理的记忆并暴露矛盾。

## 7. 优点

- **方法创新**：首次将 LLM 推理树完整映射到 git 数据结构，使推理获得版本控制的一切优势（回放、diff、merge、审计），且实现成本几乎为零。
- **实验设计严谨**：
  - 采用可插拔记忆接口，仅交换基底而保持代理固定，确保公平比较。
  - 大规模 n=500 实验及多臂消融设计，深入探究机制（内容、相关性、主语过滤）。
  - 预注册复现，主动报告虚假趋势和撤回结果，体现高科研诚信。
  - 相似度扫描明确刻画出记忆有效的边界（可复制性阈值），有力解释了先前所有空结果。
- **审计与透明度**：使用 git 本身进行公平性审计（检查记忆泄漏、期望答案泄露）、提供 bit-identical 复现、所有决策规则预先提交 git commit，增强可验证性。
- **功能演示**：展示了分布式合并功能，验证 git merge 能暴露冲突而简单拼接不能，体现结构优势。
- **开源/实用潜力**：基于成熟 git 生态，易于集成到现有工作流。

## 8. 不足与局限

- **实验覆盖局限**：
  - 模型仅涵盖 7B~32B（中等规模），未测试前沿模型（如 GPT-4、Claude-3 等），因此结论“记忆不能提升新问题”可能不适用于更大模型或富经验记忆（完整轨迹而非蒸馏教训）。
  - ScienceWorld 的代理基座在 12% 左右，太弱导致无法观测记忆收益，结论被排除但遗憾。
  - 记忆形式主要是短蒸馏教训或完整解题过程，缺乏丰富 episodic memory（完整推理链），这可能低估记忆的潜力。
- **计算预算不均**：GPQA 系统对比（Table 8）中不同臂使用不同墙钟预算（60s vs 180s vs 600s），导致该对比混杂了计算量，作者已声明但未解决。
- **32B 量化问题**：使用了 AWQ int4 量化，可能轻微降低模型能力，但作者声称不影响配对差异（Δ 值），但绝对值可能受影响。
- **记忆实验的负面结果范围**：
  - 不覆盖零样本/少样本学习中的检索式增强，仅限内部记忆整合和受控转移。
  - 不覆盖多智能体协作记忆（除了功能性合并演示，准确率阶段待进行）。
- **其他局限**：
  - 背景种子单一（每条件运行种子固定，未报告种子敏感性）。
  - 可复制性阈值基于 cosine 相似度（MiniLM），可能不是普遍最优相似度度量。
  - 分布式合并演示仅用 stub 教训，模型蒸馏教训的准确率实验待完成（归为未来工作）。
