## 摘要
自我进化智能体通过从过去的执行中提炼经验并在未来任务中复用这些经验来随时间改进。现有系统将这些经验表示为注入智能体上下文的自然语言文本，或表示为可调用工具暴露的代码。然而，这两种表示的选择通常在设计时确定，而非源自经验本身的特性，导致它们之间的权衡尚不明确。我们首次在相同经验集上进行了控制实验，隔离了文本记忆与代码记忆。结果表明，两种形式在构建成本、执行效率与可迁移性上表现出互补的权衡，单一表示不足以胜任。基于这些发现，我们提出了Metis，一种基于层次化双表示记忆的自我进化智能体系统。Metis将文本经验组织为执行计划、环境事实和常见陷阱，并选择性地将重复出现的计划固化为经过验证的可调用工具。这种设计结合了文本记忆的广泛适用性与代码记忆的执行效率，同时仅在重复复用有理由时产生工具生成成本。我们在交互式智能体的挑战性基准AppWorld上评估了Metis。结果表明，相较于ReAct，Metis将任务准确率提升了高达20.6%，同时将执行成本降低了高达22.8%。与代表性的自我进化智能体系统相比，Metis在准确率、执行效率和记忆构建成本之间实现了更优的平衡。

## Abstract
Self-evolving agents improve over time by distilling experience from past executions and reusing it in future tasks. Existing systems represent such experience either as natural-language text injected into the agent context or as code exposed as callable tools. However, the choice between these representations is typically made at design time rather than derived from the characteristics of the experience itself, leaving the trade-offs between them poorly understood. We present the first controlled study that isolates text memory and code memory over an identical set of experiences. Our results show that the two forms exhibit complementary trade-offs in construction cost, execution efficiency, and transferability, such that neither representation alone is sufficient. Guided by these findings, we propose Metis, a self-evolving agent system built on a hierarchical dual-representation memory. Metis organizes textual experience into execution plans, environment facts, and common pitfalls, and selectively crystallizes recurring plans into validated callable tools. This design combines the broad applicability of text memory with the execution efficiency of code memory while incurring tool-generation cost only when justified by repeated reuse. We evaluate Metis on AppWorld, a challenging benchmark for interactive agents. The results show that Metis improves task accuracy by up to 20.6% over ReAct while reducing execution cost by up to 22.8%. Compared with representative self-evolving agent systems, Metis consistently achieves a better balance between accuracy, execution efficiency, and memory-construction cost.

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：现有自我进化智能体（self-evolving agents）在积累和重用经验时，固定地选择文本记忆或代码记忆作为经验表示形式，而未能根据经验本身的特征动态选择更合适的表示方式。这导致无法充分利用两种表示的互补优势。
- **研究背景**：部署后的智能体需要在开放、无法完全预见的交互环境中持续适应。当前基于LLM的智能体本质上是**无状态的**：执行经验仅在有限上下文窗口内保留，一旦失效，智能体会重复犯错、重新探索已有解决方案，既增加计算成本又降低任务成功率。
- **研究空白**：虽然已有系统使用文本记忆或代码记忆来存储经验，但字段缺乏对两种表示**系统性、控制性的对比研究**，不清楚哪种经验适合哪种表示、各有什么成本与特性。
- **研究动机**：通过对相同经验集做隔离控制实验，厘清文本记忆与代码记忆的权衡，并据此设计能够动态选择或组合两者的高效记忆系统。

## 2. 方法论：核心思想、关键技术细节、算法流程

### 核心思想
Metis 采用**层次化双表示记忆架构**：
- 文本记忆（text memory）作为低成本、高容错的基础层，广泛捕获经验；
- 代码记忆（code memory）作为高执行效率的升级层，仅对**重复出现、已验证稳定**的程序性模式进行“选择性固化”。

### 关键技术细节

#### （1）结构化文本记忆（Differentiated Text Reflection）
将文本经验分为三类，各司其职：
- **执行计划（Execution Plans）**：可复用的子程序模板，是**唯一允许升级为代码**的类别。
- **环境事实（Environment Facts）**：任务无关的环境约束和特性。
- **常见陷阱（Common Pitfalls）**：结构化失败模式，以（触发条件、错误行为、后果）三元组形式存储。

#### （2）基于复发门控的代码生成（Pattern-Aware Code Generation）
- 仅当某个执行计划被**多次选中**（达到阈值θ）时，才触发工具合成。
- 代码生成器的输入**只包含计划文本和相关任务查询**，显式排除原始轨迹，防止过拟合。
- 生成的工具需通过依赖完整性、编译检查和沙箱验证后才能入库。
- 工具设计原则：合成小型可组合的助手函数，任务变化要素暴露为参数而非硬编码。

#### （3）联合记忆管理器（Memory Manager）
- 对文本条目和工具描述进行嵌入检索 + LLM二次筛选。
- 选中的计划自动带上其已实现的工具集（通过D(p)字段关联）。
- 执行前通过**静态依赖闭包**确保工具上下文完整。

#### （4）反射工具（Reflection Harness）
- 提供**渐进式披露**：反射器先接收压缩后的执行概览（仅保留首尾，中间截断），可按需展开具体步骤。
- 支持工具实现检查、沙箱执行和错误纠正。
- 所有反射操作在**执行关键路径之外**离线运行，不增加服务时延。

### 算法流程（文字描述）
1. **执行**：Memory Manager从当前记忆库M中检索并选择相关条目，Executor执行任务，生成轨迹τ。
2. **更新判断**：检查被选中的执行计划是否积累足够多的重选证据（|B(p)| ≥ θ）。
3. **代码升级**：若满足条件，Codify模块基于计划文本和相关查询生成工具，通过依赖扫描、编译验证和功能测试后入库。
4. **文本反思**：Text Reflector分析轨迹，结合最近N个任务查询分布，更新三类文本记忆（合并重复、修正偏差、新增条目）。
5. **迭代**：更新后的记忆用于下一个任务。

### Metis实验关键发现：
