## 摘要
长上下文语言建模不仅需要扩展上下文窗口，还需要在数千个词符中保持对实体状态和关系的连贯理解——这是语义相似性本身无法解决的挑战。KGERMAR 通过从输入文本中动态构建上下文特定的知识图谱来解决这一问题，实现了利用语义相似性和显式实体关系的领域自适应检索。该框架执行实时实体和关系抽取以构建上下文知识图谱，然后通过多组件记忆架构将图结构嵌入与文本语义集成。维护了三个记忆库——上下文、语义和结构——通过学习权重融合检索信号，以捕获表层语义和更深层次的关系模式。在 SlimPajama（84,700 个训练样本）、WikiText-103（4,358 个样本）、PG-19（100 个样本）和 Proof-pile（46,300 个样本）上的评估显示，KGERMAR 在 1K 到 32K 词符的上下文长度上，与记忆增强基线相比，困惑度降低了最多 8.5%，记忆效率提高了 2-2.5 倍，并在五个 NLU 任务上展现出卓越的上下文学习性能。这种动态知识图谱构建方法通过实现能够根据输入上下文进行自适应调整的领域特定知识表示，而非依赖固定知识库，推动了记忆增强语言建模的发展。

## Abstract
Long-context language modeling requires not only extending context windows but maintaining coherent understanding of entity states and relationships across thousands of tokens -- a challenge that semantic similarity alone cannot address. KGERMAR addresses this by constructing dynamic, context-specific knowledge graphs from input text during inference, enabling domain-adaptive retrieval that leverages both semantic similarity and explicit entity relationships. The framework performs real-time entity and relation extraction to build contextual knowledge graphs, then integrates graph-structural embeddings with textual semantics through a multi-component memory architecture. Three memory banks -- contextual, semantic, and structural -- are maintained with retrieval signals fused via learned weights to capture both surface-level semantics and deeper relational patterns. Evaluated on SlimPajama (84.7K training examples), WikiText-103 (4,358 examples), PG-19 (100 examples), and Proof-pile (46.3K examples), KGERMAR achieves up to 8.5\% lower perplexity and 2--2.5x better memory efficiency than memory-augmented baselines across context lengths from 1K to 32K tokens, with superior in-context learning performance across five NLU tasks. The dynamic knowledge graph construction approach advances memory-augmented language modeling by enabling domain-specific knowledge representation that adapts to input contexts rather than relying on fixed knowledge bases.

- **核心问题**：长上下文语言建模面临的关键挑战不仅是扩展上下文窗口，更在于维持对实体状态和跨数千个词符（token）关系的连贯理解。现有方法（如扩展注意力窗口或记忆增强检索）存在两大缺陷：①扩展注意力模型（如LongLoRA）存在“lost-in-the-middle”退化，即中间位置的信息系统性被弱化；②记忆增强系统（如ERMAR、MemLong）完全依赖语义相似性检索，无法区分因词汇巧合提及相关术语的段落和描述同一实体因果关系的段落。例如一个技术支持的50条消息会话，模型需要将第47条“再次出现初始错误”与第一条的购买记录及中间尝试的解决方案关联起来——这是结构性推理问题，而非单纯检索精度问题。
- **整体含义**：提出KGERMAR框架，通过动态构建上下文特定知识图谱并融合图结构嵌入与文本语义，实现既利用语义相似性又利用显式实体关系的领域自适应检索，从而解决现有方法无法捕捉实体状态和因果链的盲点。

## 2. 方法论
### 核心思想
- 在推理过程中实时从输入文本抽取实体和关系，构建动态上下文知识图谱；然后利用关系图卷积网络（R-GCN）编码图结构，并通过跨模态注意力将图嵌入与文本嵌入融合；最后维护三个专用记忆库（上下文、语义、结构），通过可学习权重融合检索信号，以同时捕获表层语义和深层关系模式。

### 关键技术细节
- **上下文知识图谱构建**：①实体识别：使用在CoNLL-2003微调的BERT-large模型，识别实体跨度、类型（5种：人物、组织、地点、概念、事件）及位置；②关系抽取：使用在TACRED微调的BERT-base模型，对窗口W内的实体对预测关系（7种类型：HAS PROPERTY、CAUSED BY、PART OF、USED FOR、IS A、LOCATED AT、RELATED TO）；③图构建：通过实体合并（字符串相似度+嵌入相似度）、关系置信度评分（分类器置信度与频率加权）、低置信度三元组过滤（阈值0.5）三步优化。
- **图增强嵌入生成**：①R-GCN编码：按关系类型进行消息传递，多跳传播使实体能聚合局部窗口外的邻居信息；②混合文本-图嵌入：每个实体用基础语言模型（OpenLLaMA-3B）的64词符上下文均值池化得到文本嵌入，再通过跨模态注意力与R-GCN输出融合生成最终实体表示。
- **多组件记忆架构与检索**：①上下文记忆：存储第13层LM的键值对，LRU淘汰，容量32768；②语义记忆：存储256词符非重叠块的BGE-M3嵌入，使用FAISS HNSW索引；③结构记忆：存储融合的文本-图实体嵌入。并行从三库检索top-K，最终得分通过可学习权重λ₁、λ₂、λ₃加权融合（λ₁+λ₂+λ₃=1）。检索结果通过检索因果注意力注入LM的第14、18、22、26层。
- **训练目标**：多任务学习，包括语言建模损失、知识图谱嵌入损失（链接预测二元交叉熵）、检索排序损失（margin-based ranking）以及跨模态对齐损失（L2距离）。损失权重：α=0.1, β=0.05, γ=0.01。

## 6. 主要结论与发现
1. **困惑度**：KGERMAR在所有上下文长度上，对记忆增强3B模型取得最低困惑度。在WikiText-103上，4K长度时PPL从ERMAR的7.62降至7.20（降8.5%）。在PG-19和Proof-pile上优势略小（因数学文本命名实体少，图贡献有限）。
2. **ICL性能**：4-shot平均准确率78.6%（ERMAR 76.1%，MemLong 71.0%）；20-shot平均81.2%（ERMAR 80.5%，MemLong 73.4%）。在需要实体级区分的任务（MPQA、Subj）上增益最显著。
3. **记忆效率**：KGERMAR在32K上下文长度上峰值内存14.51GB，比ERMAR（22.87GB）低36%，比MemLong（23.27GB）低41%。归一化每词符内存从1K时的1.6x优势扩大到32K时的2.1x优势。
4. **性能缩放**：延迟在16K→32K时近线性增长（R²=0.98），吞吐量稳定保持在>1000 tokens/sec。
5. **局限性**：实时知识图谱构建带来更高延迟（2-3倍于ERMAR），但方差更低（更可预测）。适用于内存受限但可接受一定延迟的长上下文部署。

## 7. 优点
- **方法创新**：首次在记忆增强检索中引入动态知识图谱构建，使结构知识能针对每个输入上下文自适应生成，克服了静态知识库无法覆盖领域特定实体的根本缺陷。
- **架构设计**：三记忆库（上下文、语义、结构）的结合提供了比纯语义检索更丰富的信号空间，可学习融合权重增强了灵活性。
- **实验扎实**：覆盖多个领域、多种长度、多种指标，且与强基线（ERMAR、MemLong、LongLoRA等）严格对比，结果一致性高。
- **实际价值**：在保持较低困惑度的同时，记忆效率显著优于扩展注意力模型（如Phi3-128k需要双GPU），更适合在单卡消费级GPU上处理长文本。
- **分析全面**：不仅报告性能，还详细分析了延迟、吞吐量、缩放行为等工程权衡，对实际部署有指导意义。

## 8. 不足与局限
- **计算开销**：实时知识图谱构建导致每词符延迟比ERMAR高约2倍（0.43ms vs 0.20ms），吞吐量约减半。在需要极低延迟的场景（如实时对话）中可能不适用。
- **关系抽取窗口限制**：使用固定词符窗口（W）提取本地实体对，跨段落关系仅通过R-GCN传播近似，无法完全捕捉长距离因果链。
- **领域适应性受限**：NER和关系抽取模型分别在CoNLL-2003和TACRED上微调，对于专业术语密集的领域（如生物医学、法律）可能抽取质量下降。
- **缺少明确的消融实验**：未单独去除结构记忆或语义记忆进行对比，未能量化各记忆组件的独立贡献。与ERMAR的对比部分反映了结构记忆的增益，但语义记忆的贡献未分离。
- **ICL基准不全**：未对比Phi3-128k在ICL任务上的表现（虽解释为无发表结果），可能影响结论的全面性。
- **训练细节缺失**：未报告训练时间、优化器参数、学习率调度等，可复现性受一定影响。
- **潜在偏差风险**：实验仅使用英文文本，未验证多语言场景；评估任务限于NLU分类，未涵盖生成任务（如摘要、问答）。
