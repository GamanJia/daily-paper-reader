## 摘要
在大语言模型（LLM）位于智能体记忆流水线中的位置——介于检索平面（广泛基准测试的用于检索存储事实的组件）与控制平面（通过替换、释放、清除等操作改变事实的组件，大多未经测试）之间——决定了系统能够恢复哪些遗忘失败模式。通过在385个对抗性案例上比较十三种系统配置，我们观察到三种具有部分互补覆盖范围的放置机制：确定性原语足以处理词汇/时间类别，但在规范化任务上失败（标识符混淆测试5%，跨语言测试0%）；写入时LLM可以恢复规范化（100%），但无法处理意图感知删除（前缀冲突和复合事实测试0%）；变异时的钩子可以恢复意图感知删除（78-85%），并同时几乎照亮所有类别（整体91.7-93.2%，每次385案例运行成本0.17美元，变异延迟2.3秒/案例 vs 确定性64-191毫秒/案例，召回路径不变）。我们通过ForgetEval揭示了这种权衡：一个包含1000个模板案例和385个对抗性层（132个手工制作+253个由LLM起草并经预言机验证）的套件，通过确定性子串匹配评分，并配有一个六方法适配器协议（诚实N/A评分），使得异构记忆存储能够在130行代码中接入。通过10名标注者的IAA（Fleiss' kappa = 0.958）和77个外部作者子集（四名匿名贡献者）验证了该方法的接纳性，该子集复现了规范化不对称性并放大了联合放置的提升（+27.8个百分点）。生产故障主要是遗忘故障而非召回故障，但现有基准仅衡量召回。ForgetEval和所有适配器均以MIT许可证发布。

## Abstract
Where an LLM sits in an agent memory pipeline -- between the recall plane that retrieves stored facts (extensively benchmarked) and the control plane that mutates them via supersede, release, purge (largely untested) -- shapes which forgetting failure modes the system recovers. Comparing thirteen system configurations on a 385-case adversarial surface, we observe three placement regimes with partly complementary coverage: deterministic primitives suffice for lexical/temporal categories but fail canonicalization (5% on identifier-obfuscation, 0% on cross-lingual); inscribe-time LLM recovers canonicalization (100%) but cannot help intent-aware deletion (0% on prefix-collision and compound-fact); a mutation-time hook recovers intent-aware deletion (78-85%) and brightens nearly all categories simultaneously (91.7-93.2% overall, $0.17 per 385-case run, 2.3s/case mutation latency vs. 64-191ms/case deterministic, recall path unchanged).   We expose the trade-off via ForgetEval, a 1000-case templated suite plus a 385-case adversarial layer (132 hand-crafted + 253 LLM-drafted oracle-validated) scored by deterministic substring match, paired with a six-method Adapter Protocol with honest N/A scoring that lets heterogeneous memory stores enter in 130 lines. Admission is corroborated by 10-annotator IAA (Fleiss' kappa = 0.958) and a 77-case external-authored subset (four blind contributors) that replicates the canonicalization asymmetry and amplifies the joint-placement lift (+27.8 pt). Production failures are predominantly forgetting failures rather than recall failures, yet existing benchmarks measure only recall. ForgetEval and all adapters are released under MIT.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：现有智能体记忆系统（如MemGPT、Mem0、Zep等）的基准测试仅关注**召回平面**（retrieval/recall），即系统能否在对话中正确检索信息，但忽略了**控制平面**（control plane）——即通过`supersede`（替换）、`release`（释放）、`purge`（清除）等操作主动遗忘/修改记忆的能力。然而在真实生产环境中，主要失败模式（泄漏密码、GDPR删除记录未被擦除等）恰恰是**遗忘失败**，而非召回失败。
- **研究背景**：现有记忆框架在召回路径上投入大量资源，而遗忘功能几乎未被系统测试。例如，MemPalace在召回基准（Memora）上得分60/150，但在遗忘测试（ForgetEval）上得分为0/385，说明召回性能无法预测控制平面能力。
- **整体含义**：LLM在智能体记忆流水线中的**放置位置**（位于召回平面与控制平面之间的哪个阶段）决定了系统能够恢复哪些遗忘失败模式。本文旨在通过系统实验刻画这一影响，并提供可复现的评估工具。

## 2. 论文提出的方法论

### 2.1 核心思想
将记忆系统分为两个控制面：**召回平面**（检索事实）和**控制平面**（通过变异操作修改事实）。LLM可以插入在**写入时**（inscribe-time，提取标签、实体链接）、**变异时**（mutation-time，规划替换/释放/清除），或固定在**确定性基元**（不依赖LLM）。不同放置位置产生互补的遗忘覆盖能力。

### 2.2 关键技术细节

#### a. ForgetEval基准套件
- **模板套件（1000条）**：覆盖5个遗忘家族（supersession, decay, amnesia, purge, drift），每个家族4个子模板，确定性生成。
- **对抗层（385条）**：包含132条手工核心用例 + 253条LLM起草（DeepSeek-V3）并经预言机验证的用例，覆盖10个攻击类别：
  - substring_trap, prefix_collision, paraphrase_supersession, negation_trap, temporal_qualifier, shared_attribute, compound_fact, identifier_obfuscation, cross_lingual_identifier, recursive_supersession
- **评分方式**：**确定性子串匹配**（top-k召回中检查must_contain和must_not_contain），不依赖LLM裁判循环，确保可复现性。
- **数据准入**：使用Qwen-2.5-72B作为独立LLM裁判，进行两阶段过滤（结构+语义），辅以10位标注者的IAA（Fleiss' κ=0.958）和跨家族裁判验证。

#### b. Adapter Protocol（适配器协议）
定义6个方法的行为契约：
- 强制性召回原语：`reset`, `inscribe`, `recall_texts`
- 可选控制平面变异：`supersede`, `release`, `purge`（未实现则返回N/A）
- 允许通过组合（如`delete+add`）模拟`supersede`，实现公平比较。
- 所有适配器代码控制在130行以内。

#### c. 三种放置机制
1. **确定性基元**：不使用LLM，依靠字符串/词法精确匹配（如BM25、FFS5）。
2. **写入时LLM**：在写入时刻由LLM提取标签、规范化表面形式（如A-MEM、Mem0+v3）。
3. **变异时hook**：在变异（替换/释放/清除）时调用LLM规划操作（窄JSON契约），保留召回路径无LLM调用。

#### d. 参考实现
提供基于SQLite + sqlite-vec + FTS5的开源参考系统（~700行），支持所有六种方法，并可选接入LLM hook。

## 6. 论文的主要结论与发现

1. **遗忘比召回更困难且更普遍**：生产环境的主要失败是遗忘失败，而非召回失败。现有基准仅衡量召回是片面。
2. **控制平面放置决定遗忘覆盖**：三种机制部分互补，而非冗余：
   - **确定性基元**：对词法/时间类别（substring_trap, temporal_qualifier等）通过率≥95%，但在规范化（identifier_obfuscation 5%, cross-lingual 0%）和意图删除（compound_fact 0%）上完全失败。
   - **写入时LLM**：恢复规范化（100%），但无法处理前缀冲突和复合事实（0%），删除精度差。
   - **变异时hook**：恢复意图删除（compound_fact 78-85%, prefix_collision 79%），并同时提升几乎所有类别，整体通过率91.7-93.2%（排除原语存在类别后为93-94%）。
3. **联合放置效果最佳**：同时使用写入时LLM和变异时hook的系统（如Letta+LLM）可互补覆盖各自弱点，在外部子集上获得最大提升（+27.8 pt）。
4. **提升是架构无关的**：同一hook应用于不同后端（LETHE、LangGraph）获得相似提升量（±2 pt内），证明是放置机制而非特定存储引擎的效果。
5. **Hook提升随LLM能力缩放**：DeepSeek-V3（强JSON遵循）给出+28-30 pt；Qwen-2.5-72B给出+13 pt；Llama-3.1-70B无法解析契约，回退到确定性基线。
6. **召回与遗忘是正交轴**：MemPalace在召回测试得分40%但在遗忘测试为0%，说明两个轴独立。

## 7. 优点（方法或实验设计亮点）

## 8. 不足与局限

- **语言和跨文化覆盖不足**：对抗层只有英语，跨_lingual_identifier类别每个脚本族样本量极薄（如泰文仅1个），结论对少数族裔语言的可推广性有限。
- **子串评分盲点**：约30%的确定性失败是评分伪影（如较长ID包含禁止子串、过去时态子句），主要集中在prefix_collision和supersession类别。虽然这些盲点不直接影响LLM挂钩提升（因为相关类别无伪影），但使确定性系统的真实性能略被低估。
- **compound_fact是原语存在性测试**：该类别需要partial-edit原语，系统若没有则得分为0，但作者保留作为诊断手段，需读者谨慎解读。
- **LLM挂钩依赖在线API**：虽然召回路径保持离线，但变异时的LLM调用依赖外部模型（DeepSeek-V3等），对于离线部署用户无法直接使用。且提升幅度随LLM质量波动（Llama-3.1-70B完全失败）。
- **某些类别样本量小**：部分攻击类别仅36-40例，给子类别统计带来限制；外部子集上3个类别全系统失败，无法区分系统间差异。
- **记忆系统覆盖面有限**：虽然评估了13种配置，但仍未包含如Redis Semantic Memory、AutoGen Memory等（需API密钥或主机账户，与论文无GPU单CPU可复现目标冲突）。社区贡献适配器未来可扩展。
- **Mem0+v3配置的公平性**：Mem0的默认LLM为gpt-4o-mini，但论文因无OpenAI密钥仅能用DeepSeek-V3，可能未达到Mem0最优配置（加JSON修复后下降24.7 pt）。
- **生态效度有限**：论文提供了结构映射（将遗忘类别与真实生产泄漏事件关联），但没有直接使用企业级记忆轨迹进行实证验证。
