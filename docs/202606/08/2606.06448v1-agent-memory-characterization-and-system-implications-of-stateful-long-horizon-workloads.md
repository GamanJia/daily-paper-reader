## 摘要
LLM智能体越来越多地部署于长周期任务，这类任务需要在扩展的交互历史中进行持续推理。要实现大规模部署，智能体需要在会话之间持久化存储、检索并更新自身记忆。目前，智能体记忆系统已形成丰富的生态系统，涵盖平面检索、LLM中介提取、事实存储整合以及智能体控制流。然而，这些记忆系统在系统层面的行为特征尚未得到描述。我们首次对智能体记忆进行了系统特征分析。首先，我们提出了一种面向系统的分类法，沿四个维度对智能体记忆系统进行分类。其次，我们构建了一个阶段感知的分析框架，将开销归因于构建、检索和生成三个阶段。第三，我们在两个基准套件上对十个代表性系统进行了特征分析，揭示了设计选择如何在不同读写路径上转移开销。最后，我们提出了10条系统建议，涵盖构建调度、能力下限、查询量的摊销、新鲜度-延迟权衡以及集群规模管理。

## Abstract
LLM agents are increasingly deployed on long-horizon tasks requiring sustained reasoning over extended interaction histories. Realizing this at scale requires agents to persistently store, retrieve, and update their own memory across sessions. A rich ecosystem of agent memory systems has emerged spanning flat retrieval, LLM-mediated extraction, consolidating fact stores, and agentic control flows. Yet, their system-level behavior remains uncharacterized. We present the first systems characterization of agent memory. First, we introduce a system-oriented taxonomy classifying agent memory systems along four axes. Second, we build a phase-aware profiling harness attributing cost to construction, retrieval, and generation. Third, we characterize ten representative systems across two benchmark suites, uncovering how design choices shift cost across the write and read paths. Finally, we derive 10 system recommendations covering construction scheduling, capability floors, amortization via query volume, freshness-latency tradeoffs, and fleet-scale management.

## 3. 实验设计
- **数据集/场景**：
    - **MemoryAgentBench (MAB)**：主要基准，包含四个任务类别：准确检索、测试时学习、长程理解、选择性遗忘。子集包括LongMemEval_S_*（约360K token历史、60个查询）、SH-Doc QA、MH-Doc QA、EventQA、BANKING77、CLINC150、TREC、MovieRec、∞Bench-Sum、Detective QA、FactConsolidation等。每个样本增量输入4096 token分块。
    - **MemoryArena**：多会话任务，后一会话依赖前一会话信息，用于评估新鲜度-延迟权衡（20个多会话任务，物理分解场景）。
- **Benchmark**：主要使用MAB的LLM-Judge准确率，以及MemoryArena的会话依赖完成率。
- **对比的方法**：10个代表性系统覆盖四大范式：

- **设置**：远程构建使用OpenAI API（GPT-4o-mini / GPT-4.1-mini, text-embedding-3-small），本地构建使用vLLM部署本地模型（Qwen3-32B/14B/8B/1.7B，FP8或BF16；嵌入模型Qwen3-Embedding-0.6B）。查询时QA LLM固定为GPT-4o-mini。每个系统在隔离SLURM作业中运行。

## 6. 论文的主要结论与发现
- **核心发现1**：对于长周期任务，全历史处理成本巨大，外部队存可大幅降低查询延迟，但不同系统在相同硬件上查询延迟差异达两个数量级（0.1s vs 38s）。
- **发现2**：构建能量主导智能体生命周期，对于LLM中介系统，构建能量超过300个查询的总查询能量。能量每正确回答差异超过47倍（BM25的4.1 kJ到MIRIX的185.9 kJ）。
- **发现3**：构建工作负载是预填充和嵌入密集型的（中值解码token仅占4.6%），与延迟敏感的QA流量结构冲突。嵌入批次大小因范式显著不同：IIIa类系统大批量，IIIb/IV类系统顺序小批量。
- **发现4**：构建LLM小型化可行，但受算法输出契约的硬下限限制（MIRIX在Qwen3-1.7B完全失败）。
- **发现5**：没有系统同时在构建成本、查询延迟和准确率上最优；系统占据不同的帕累托前沿位置（BM25构建最快、准确率最高但查询延迟中等；Mem0查询延迟最低但准确率低）。
- **发现6**：会话间构建时间跨度5个数量级，导致新鲜度-延迟权衡：慢构建系统在异步调度下会出现记忆陈旧。
- **发现7**：人均存储空间差异9倍（1M token时），但构建token成本斜率差异更大：智能体控制流系统随历史增长超线性增长（Letta在256K token后陡峭发散）。
- **发现8**：LLM有界系统产生更宽的尾部延迟（p95/p50可达5.9×），需要外部迭代上限。

## 8. 不足与局限
- **实验覆盖限制**：所有实验在单GPU、单机环境下进行。多节点分布式部署所需的记忆一致性、同步等挑战未涉及。
- **多模态缺失**：仅处理文本，当前前沿有图像/音频记忆，会放大存储和检索复杂度。
- **任务长度上限**：最长历史1M token，无法外推到真实长期服务（数月/年）产生的数千万token历史。
- **固定QA LLM**：仅用GPT-4o-mini，更强或更弱模型可能改变记忆系统相对表现。
- **系统实现差异**：各系统实现质量不同（如Letta工具调用效率较低），可能引入非算法本身的偏差。
- **未评估维护阶段**：当前所有系统单调累积不做遗忘，长期部署需要附加遗忘/压缩，但未量化其影响。
- **基准任务代表性**：MAB任务为合成/实验室任务，真实部署中的用户意图多样性、噪声、多语言等未覆盖。
- **能耗测量限于GPU**：未考虑CPU、网络、存储IO等非GPU能耗。
