## 摘要
代理记忆框架——mem0、Letta/MemGPT、Cognee、Zep/Graphiti、MemoryOS、MemTensor——各自提供专有的SDK、存储布局和操作词汇。目前缺乏共享的线格式：每次集成都是定制化的，每次迁移都需从头重建记忆，且没有框架提供治理界面，让人类在写操作进入长期存储前进行审查。我们提出memorywire，一种基于JSON-Schema 2020-12的线格式，支持五种记忆操作（记住、回忆、遗忘、合并、过期）和四种记忆类型（语义性、情景性、程序性、情感性），并包含MemoryStore接口、扇出路由器以及可选的人工回环治理通道。我们描述了一个开源参考实现，包含五个后端适配器（sqlite-vec、mem0、Letta、Cognee、pgvector）；在一个包含100条事实/50个查询的标注语料库上的微基准测试中，针对42个标注查询实现了recall@5=1.000，摄入p50=37.8毫秒，回忆p50=40.6毫秒；一项对抗性融合实验显示，在1-of-N秩0注入扫描（K∈{0,5,…,50}）中，倒数秩融合（RRF）保持recall@5=1.000，而最大融合在K≥5时降至0.500且泄露率达80%；以及一个包含16种场景的跨适配器一致性测试套件，80个用例中通过68个，零失败。本文贡献并非新算法，而是将成熟组件（RRF、有限状态机、短时/长时记忆整合、差异-审批工作流）封装成一个中立协议，并附有经过实证验证的参考实现，旨在与模型上下文协议（Model Context Protocol）协作而非竞争。

## Abstract
Agent-memory frameworks - mem0, Letta/MemGPT, Cognee, Zep/Graphiti, MemoryOS, MemTensor - each ship their own SDK, storage layout, and operational vocabulary. There is no shared wire format: every integration is bespoke, every migration rebuilds memory from scratch, and no framework ships a governance surface that lets a human review writes before they enter long-term storage. We present memorywire, a JSON-Schema 2020-12 wire format for five memory operations (remember, recall, forget, merge, expire) over four memory types (semantic, episodic, procedural, emotional), with a MemoryStore interface, a fan-out router, and an optional HITL governance channel. We describe an open-source reference implementation with five backend adapters (sqlite-vec, mem0, Letta, Cognee, pgvector); a microbenchmark on a 100-fact / 50-query labelled corpus achieving recall@5 = 1.000 on the 42 labelled queries with ingest p50 = 37.8 ms and recall p50 = 40.6 ms; an adversarial-fusion experiment showing Reciprocal Rank Fusion holds recall@5 = 1.000 across a 1-of-N rank-0 injection sweep (K in {0,5,...,50}) where max fusion collapses to 0.500 with 80% leak at K >= 5; and a 16-scenario cross-adapter conformance suite passing 68 of 80 cells with zero failures. The contribution is not a new algorithm; it is a packaging of established components (RRF, FSMs, STM/LTM consolidation, diff-and-approve workflows) into a venue-neutral protocol with an empirically validated reference, positioned to compose with the Model Context Protocol rather than compete with it.

# 论文总结：memorywire——代理记忆操作的厂商中立线格式

## 1. 核心问题与整体含义
- **研究动机**：现有智能体记忆框架（mem0、Letta、Cognee、Zep/Graphiti等）各自使用私有SDK、存储布局和操作词汇，缺乏统一的线格式。这导致每次集成都需要定制，迁移时记忆需从头重建，并且没有框架提供人类审核写入内容的治理机制。
- **整体含义**：作者提出memorywire，旨在解决上述问题，通过定义一个共享的协议，使任何客户端能与任何后端通信，代理能在不同运行时之间携带记忆，并且每次写入都能被差异审批。

## 2. 方法论：核心思想与关键技术
- **核心思想**：将记忆操作标准化为五种操作（remember、recall、forget、merge、expire）和四种记忆类型（semantic、episodic、procedural、emotional），使用JSON Schema 2020-12定义请求/响应格式。同时提供MemoryStore接口、扇出路由器以及可选的HITL（Human-in-the-loop）治理通道。
- **关键技术细节**：
  - **操作定义**：五个操作各有严格请求和响应模式。remember写入记忆，recall检索，forget删除，merge合并重复，expire执行TTL策略。每个操作参数包括agent_id、type、content等。
  - **记忆类型**：semantic（事实）、episodic（事件）、procedural（过程/FSM编码）、emotional（情感关联）。
  - **MemoryStore协议**：后端必须实现接口，包括五种操作、health和capabilities声明。capabilities允许路由知晓后端支持哪些功能（如vector、graph等）。
  - **路由器**：自身也实现MemoryStore，将操作扇出到多个子存储；recall采用倒数秩融合（RRF，k=60）融合结果，支持可选图一跳提升。RRF公式：score(d)=∑_{i∈S} 1/(k+ri(d))。RRF不依赖原始分数，提供了对恶意后端的鲁棒性。
  - **治理通道**：允许写入标记approval_required=true，写入被暂存为PENDING状态，只有通过UI审批后才可见。实现了diff-and-approve模式。
  - **参考实现**：包含五个后端适配器（sqlite-vec、mem0、Letta、Cognee、pgvector），以及FSM过程记忆后端、STM/LTM转换器（异步后台任务）、治理UI（HMTX+Starlette）。

## 3. 实验设计
- **数据集/场景**：
  - **微基准**：100条人工撰写的事实，混合四种类型，50个查询（24个释义、10个精确/近似匹配、8个多命中、8个无匹配探测）。嵌模型：all-MiniLM-L6-v2，后端：sqlite-vec内存。
  - **对抗性融合实验**：合成数据集50条记忆，20个查询，每个查询有两个黄金ID。在三个后端（两个良性+一个恶意）下，扫描恶意后端注入K个攻击者控制的ID（K从0到50），评估RRF、MAX和加权融合。
  - **跨适配器一致性测试**：16个协议不变性场景×5个适配器=80个测试单元。
  - **初步LongMemEval和LoCoMo**：nq=12/10，单种子。
- **基准**：自身设计的召回率、延迟、漏报率等。未与其他协议直接对比，因为memorywire是首个统一协议。
- **对比方法**：在对抗融合实验中对比了三种融合算法（RRF、MAX、加权）。

## 4. 资源与算力
- **明确说明**：所有评估在单一开发者级Windows 11笔记本上运行，使用CPU推理。未使用GPU。模型加载开销被排除（预热的第一次调用不计入延迟）。作者承认分布式部署、网络跳转等未测量。算力资源非常有限，且未进行大规模分布式测试。

## 5. 实验数量与充分性
- **实验数量**：共三组主要定量实验：（1）微基准：100事实/50查询；（2）对抗融合：20个查询，11个K值，三种融合；（3）一致性测试：16场景×5适配器=80单元。此外还有初步LongMemEval（12个问题）和LoCoMo（10个问题）。
- **充分性**：作者自身指出其局限性：语料小（100条），合成，非真实海量场景；只有单机测量；对抗融合假设恶意后端完美填充rank-0，且假设良性后端完美；一致性测试很好但只覆盖16个场景；LongMemEval/LoCoMo样本太少（单种子），且所用小嵌入模型（all-MiniLM-L6-v2）是故意选择的弱配置。作者将这些视为初步结果，计划v2进行更大规模评估。总体来说，实验设计具有一定的合理性和针对协议关键属性的验证，但覆盖范围有限，统计效力不足。

## 6. 主要结论与发现
- **微基准**：recall@5=1.000（42个有标签查询），precision@5=0.214，摄入p50=37.8ms，回忆p50=40.6ms，无匹配查询返回空结果0/8（因无校准阈值，总是返回k个结果）。
- **对抗融合**：RRF在整个K扫描下保持recall@5=1.000，泄露率0；MAX在K≥5时recall@5降到0.500，泄露率80%；加权融合（相等权重）行为与RRF类似。
- **一致性测试**：68 PASS / 12 SKIP / 0 FAIL。SQL支持的后端（sqlite-vec, pgvector）全部通过；SDK包装的后端因缺少user_id命名空间、空策略保护、稳定记录ID而跳过部分用例。
- **初步LongMemEval/LoCoMo**：LongMemEval 0.417，LoCoMo 0.150，多会话和时间推理薄弱，本质是弱小嵌入器的限制。
- **核心结论**：memorywire通过RRF提供了对恶意后端的鲁棒性，通过标准化降低集成成本，通过治理通道实现人类审核；但协议本身不是新算法，而是成熟组件的包装。

## 7. 优点
- **设计简洁清晰**：仅五种操作、四种类型，易于理解和实现。
- **RRF的鲁棒性**：理论结合实验证明了RRF在恶意后端下的优越性，是工程保障。
- **成熟的组件复用**：合理利用现有技术（RRF、FSM、STM/LTM、diff-approve），避免重复造轮子。
- **开源参考实现**：提供五个后端适配器和完整的工具链（CLI、UI、测试套件），可复现性和实用性高。
- **注重安全性**：附带详细威胁模型（6个攻击者），并针对每个威胁给出当前缓解和v0.2计划，代码中有具体引用。
- **与MCP的兼容性设计**：设计即考虑与MCP组合使用（作为工具、资源或扩展），而非竞争。
- **实证充分性意识**：作者明确列出局限性，诚实坦诚，无过度宣传。

## 8. 不足与局限
- **实验规模小**：微基准仅100条事实；对抗合成仅50条记忆；LongMemEval/LoCoMo样本极低（n=12/10），不支持统计显著结论。
- **计算资源局限**：仅在单台CPU笔记本上运行，未评估分布式部署、网络延迟、高吞吐场景。
- **忽略真实嵌入服务干扰**：微基准使用本地嵌入，未评估调用远程嵌入服务的延迟抖动。
- **评估作者为主**：一致性和基准未经过第三方审计，存在评估者偏差。
- **初步基准成绩弱**：LongMemEval 0.417 和 LoCoMo 0.150 显著低于当前同类系统分数，尽管作者解释为小嵌入器限制，但也表明统一协议并不自动带来高召回能力。
- **无校准阈值**：recall总是返回k个结果，导致无匹配查询误报为0/8，缺乏判断记忆存在的置信度截断。

- **治理通道功能有限**：仅支持单体全局令牌，无细粒度角色权限，v0.2才能改进。
- **未与已有协议对比**：未直接与MCP本地内存工具对比开销或功能差距，虽有定性分析但缺定量对照。
