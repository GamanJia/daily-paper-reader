## 摘要
基于LLM的代理能够通过结合推理与环境反馈来解决多步交互任务，然而每一轮都从相同固定上下文开始，且过程中发现的任何有用策略在任务结束后即丢失。现有方法要么将学习局限于当前任务，要么将所有经验汇集到一个无类型区分的单一存储中，既不区分知识类型，也不通过使用情况追踪质量，更未平衡库中仍欠缺的内容。我们提出统一上下文进化（UCE），一种无梯度框架，将代理经验外化到不断演化的、类型化的可进化上下文单元（ECUs）库中。UCE将经验分解为四种互补类型（记忆、策略、工作流与技能），每种类型从轨迹中根据特定类型条件生成，在决策时检索，通过重复使用结果评分，并在不再有价值时剪枝。一个调度模块将每轮生成预算分配给库中最弱的类型。在两个交互基准测试中，UCE将ALFWorld成功率从75.4%提升至96.3%，WebShop任务得分从45.1%提升至61.3%，且积累的库无需重新训练即可迁移到其他代理骨干网络。

## Abstract
LLM-based agents can solve multi-step interactive tasks by combining reasoning with environment feedback, yet each episode starts from the same fixed context and any useful strategy discovered along the way is lost once the task ends. Existing approaches either limit learning to the current task or pool all experience into a single untyped store, without distinguishing knowledge types, tracking quality through use, or balancing what the library still lacks. We introduce Unified Context Evolution (UCE), a gradient-free framework that externalizes agent experience into an evolving library of typed Evolvable Context Units (ECUs). UCE decomposes experience into four complementary types (Memory, Strategy, Workflow, and Skill), each generated from trajectories under type-specific conditions, retrieved at decision time, scored through repeated usage outcomes, and pruned when no longer valuable. A scheduling module allocates each cycle's generation budget toward the types where the library is weakest. Across two interactive benchmarks, UCE raises ALFWorld success from 75.4% to 96.3% and WebShop task score from 45.1% to 61.3%, and the accumulated library transfers to alternative actor backbones without retraining.

# 面向LLM代理的统一上下文进化（UCE）——论文详细总结

## 1. 核心问题与整体含义（研究动机与背景）

- **问题**：现有LLM代理在执行多步交互任务时，每轮都从固定上下文（系统指令、少量示例等）开始，过程中发现的任何有用策略（如环境机制、决策规则）在任务结束后即丢失。这导致代理无法跨任务积累经验，每次都是“从零开始”。
- **现有方法局限**：
  - 强化学习方法虽可提升能力，但需梯度访问和高昂训练成本。
  - 单任务内方法（如Reflexion、Self-Refine）的改进仅限于当前任务。
  - 跨任务知识库方法（如ExpeL、Agent Workflow Memory）要么将所有知识混存在无类型池中，要么只保存单一类型（如技能或工作流），且通常仅通过一次性LLM评估质量，缺乏基于重复使用效果的质量追踪和资源分配。
- **论文目标**：提出一种无梯度、编译时（prompt-level）的框架，使代理能够在不同任务间不断积累、评估和优化四种互补类型的知识，让“上下文本身成为学习主体”。

## 2. 方法论（核心思想、关键技术细节、公式或算法流程）

### 2.1 核心思想
- **外部化经验库**：将代理经验组织为**可进化上下文单元（ECUs）**，每个ECU是一个类型化的知识条目，存储在外部队列中，可被检索并注入到代理提示中。
- **四种功能互补的ECU类型**：
  - **Memory（记忆）**：环境机制的事实性陈述，例如“水槽盆无需打开水龙头即可清洁物品”。
  - **Strategy（策略）**：条件性决策规则，例如“若放置失败，则打开容器重试”。
  - **Workflow（工作流）**：任务类型的标准执行序列，例如“找到目标→转换→放置”。
  - **Skill（技能）**：跨任务类型的可复用子操作方法，例如“搜索容器→打开→取物”。
- **生命周期管理**：每个ECU通过实际使用结果（成功/失败次数）计算**适应度分数**，用于检索、生成和剪枝。
- **知识生成调度**：通过**知识产出调度（KYS）**根据各类型当前覆盖缺口和历史贡献动态分配每轮生成预算。

### 2.2 关键技术细节
- **ECU表示**：每个ECU五元组 `e = (z_e, τ_e, w_e, c_e, f_e)`，其中`z_e`类型，`τ_e`适用任务类型，`w_e`检索条件（自然语言），`c_e`注入内容，`f_e`适应度分数。
- **检索公式**：
  ```
  score(e, t_i) = sim(h_{w_e}, h_{d_i}) + β·𝟙[τ_e = τ_i] + λ·(f_{τ_i}(e) - 0.5)
  ```
  其中语义相似度、类型匹配加成、质量偏差三项加权，且Skill类型不受类型过滤，各类型独立排列后取top-K注入。
- **适应度分数**：`f_e = (s_e + 1) / (u_e + 2)`（Laplace平滑），`u_e`累计使用次数，`s_e`累计成功信用；先验为0.5。还可维护按任务类型条件化的分数。
- **进化周期**：每个周期五阶段：
  1. 评估：在保留评估集上运行代理，不更新适应度。
  2. 收集：在不相交的收集集上运行，更新适应度。
  3. 调度：KYS根据库状态、收集成功率等产生各类型生成预算。
  4. 生成：使用类型特定提示从收集轨迹中提取候选ECU，经滤重后加入库。
  5. 清理：移除低适应度或冗余的ECU。
- **知识产出调度（KYS）**：三层架构：
  - 层1：可行性过滤——检查各类型是否还有未覆盖的任务类型或仍缺技能。
  - 层2：需求评估——基于覆盖缺口和质量缺口计算需求值`d_c^{(k)}`。
  - 层3：产出追踪——维护各类型历史产出提升的指数移动平均`y_c^{(k)}`。
  最终融合得分`s_c^{(k)} = α_c·d_c^{(k)} + (1-α_c)·y_c^{(k)}`，按比例分配预算。

## 6. 主要结论与发现

1. **显著性能提升**：UCE在ALFWorld上峰值成功率96.3%（+20.9 pp），WebShop任务得分61.3%（+16.2 pp），购买成功率从30%升至42%。
2. **知识可迁移**：累积的ECU库可直接应用于NoThinking、Plan-and-Act、ReflAct等不同骨干，无需重训练，且Plan-and-Act+UCE达到ALFWorld最高97.8%。
3. **多类型协同**：单类型消融表明在ALFWorld上Workflow贡献最大（97.0%），但WebShop上全类型优于任何单类型（42% vs 36%），说明不同类型知识互补。
4. **错误模式**：WebShop主要失败为属性部分匹配（50%）和超时（27%）；UCE擅长环境机制、决策规则和工作流，但精确属性选择仍需策略优化。
5. **进化曲线**：提升主要集中在前几个周期，后续趋于稳定；并非严格单调，但总体向上。

## 7. 优点

- **方法创新性**：首次将代理经验显式分解为四种互补类型，并为其设计独立的生成条件、检索边界和生命周期规则，解决了“类型混杂”问题。
- **实用性强**：无梯度、不修改模型权重，完全通过上下文工程实现，适用于闭源API模型。
- **检索-评估-调度闭环**：适应度分数基于实际使用结果，KYS动态分配预算，避免了静态规则或人工调参。
- **跨骨干迁移**：库的格式与推理骨干解耦，一次积累可零成本复用于不同算法。
- **实验设计严谨**：严格区分评估集与收集集、统计显著性检验（McNemar、bootstrap，p<0.05）、全面的消融和案例研究。

## 8. 不足与局限

- **环境覆盖窄**：仅测试文本式、离散动作空间的ALFWorld和WebShop，未涵盖连续动作（如机器人控制）、多模态观测（如AndroidWorld、VisualWebArena）或更长规划视野的任务。
- **模型依赖**：仅使用单一模型对（gpt-4.1-mini + gpt-5.2），未能分离框架设计与生成器能力的影响。若生成器较弱，ECU质量可能下降。
- **任务规模有限**：总任务数分别为134和100，库调度信号估计较稀疏。更大规模任务集或更长期进化下库是否持续改善会否降解尚不清楚。
- **知识类型固定**：四种ECU类型为人工设计，可能不适应新领域或更复杂的知识层次。论文建议未来可探索自动类型发现。
- **无梯度方法的上限**：UCE属于prompt级改进，无法像RL方法那样优化细粒度动作概率。WebShop部分匹配失败即体现了这一点。
- **评估单次尝试**：每个任务每轮仅运行一次（无pass@k），可能引入随机性，但论文已通过多次周期平均和统计检验缓解。
