## 摘要
个性化演示文稿生成不仅需要基于当前提示或模板进行条件化：智能体必须在不同任务间保留稳定的用户偏好，在多轮修订过程中保留新引入的偏好和约束，并可靠地执行局部编辑。我们提出MemSlides，一种用于个性化演示智能体的层次化记忆框架，它将长期记忆与工作记忆分离，并进一步将长期记忆分为用户画像记忆和工具记忆。用户画像记忆存储意图条件化画像，用于第0轮个性化；工作记忆跨修订轮次携带活跃偏好和会话约束；工具记忆存储可复用的执行经验，用于可靠的局部编辑。MemSlides将这种记忆设计与有范围的幻灯片局部修订相结合，使得有针对性的更新作用于最小受影响区域，而非重复生成整个演示文稿。在受控实验中，用户画像记忆提升了在多画像、多意图画像库中的角色一致性判断；工具记忆注入改善了诊断性匹配对设置中的闭环修改行为；定性案例展示了工作记忆延续偏好的能力。综合而言，这些结果表明，在演示文稿创作中实现有效个性化依赖于将持久用户画像、会话级工作记忆和可复用执行经验在生成与局部修订过程中分离。

## Abstract
Personalized presentation generation requires more than conditioning on a current prompt or template: agents must preserve stable user preferences across tasks, retain newly introduced preferences and constraints during multi-turn revision, and carry out local edits reliably. We propose MemSlides, a hierarchical memory framework for personalized presentation agents that separates long-term memory from working memory and further divides long-term memory into user profile memory and tool memory. User profile memory stores intent-conditioned profiles for round-0 personalization, working memory carries active preferences and session constraints across revision rounds, and tool memory stores reusable execution experience for reliable localized editing. MemSlides pairs this memory design with scoped slide-local revision, so targeted updates act on the smallest affected region instead of repeatedly regenerating the full deck. In controlled experiments, user profile memory improves persona-alignment judgments on a multi-persona, multi-intent profile bank, tool-memory injection improves closed-loop modify behavior in diagnostic matched-pair settings, and qualitative cases illustrate working memory's ability to carryover preferences. Taken together, these results suggest that effective personalization in presentation authoring depends on separating persistent user profiles, session-level working memory, and reusable execution experience across generation and localized revision.

## 1. 核心问题与整体含义（研究动机和背景）

- **问题**：现有自动幻灯片生成系统虽然能够生成完整且视觉美观的演示文稿，但缺乏**持久化个性化**。用户在不同任务（如学术讲座 vs 商业演讲）中有不同的偏好（布局、模板、风格、内容密度等），但现有系统要么依赖单次提示或模板，要么在处理多轮修订时通过重新生成整个幻灯片来应对，导致已对齐内容被覆盖、上下文压力大、局部修改不可靠。
- **关键差距**：
  - 用户偏好往往在修订过程中才逐步暴露，但现有系统处理编辑时将小改动与大篇幅历史反馈竞争有限上下文，使多轮局部修改脆弱。
  - 现有系统将个性化视为提示的隐式副产品，而非通过明确记忆设计来服务。
- **整体含义**：作者提出需要将记忆作为显式框架，区分**持久用户画像**、**会话级工作记忆**和**可复用执行经验**，以实现真正有效的个性化幻灯片生成和多轮修订。

## 2. 方法论：核心思想、关键技术细节

### 2.1 核心思想

- **MemSlides** 是一个层次化记忆框架，包含：
  - **长期记忆（Long-term Memory）**：进一步分为**用户画像记忆（User Profile Memory）** 和**工具记忆（Tool Memory）**。
  - **工作记忆（Working Memory）**：携带当前会话状态、活跃偏好和临时反馈。
- 同时引入**有范围的幻灯片局部修订（Scoped Slide-local Revision）**：将更新限制在最小受影响区域，避免全稿重新生成。

### 2.2 关键技术细节

#### 问题形式化
- 给定源材料 \( x \）、用户画像 \( P_u \)、可选任务模板 \( \tau \)，系统首先生成初始幻灯片 \( S_0 = G_{\text{init}}(x, P_u, \tau) \)（称为**第0轮**）。
- 在修订轮次 \( t \)，收到用户反馈 \( f_t \) 后，更新会话状态 \( z_t \) 并编辑当前幻灯片：  
  \( z_t = U(z_{t-1}, f_t; S_{t-1}) \)  
  \( S_t = G_{\text{edit}}(S_{t-1}, x, P_u, \tau, z_t) \)
- 三种个性化信号具有不同生命周期：用户画像 \( P_u \)（跨任务持久）、任务模板 \( \tau \)（任务局部）、会话状态 \( z_t \)（轮次临时）。冲突时：明确会话反馈优先 > 任务模板 > 用户画像。

#### 多轮局部修订执行（Plan–Act–Guard 管道）
- **Plan**：将修订请求转换为显式执行契约，记录推断范围、目标幻灯片路径、活动规则标识符、选择器提示。局部请求绑定到单个幻灯片，全局规则扩展覆盖所有幻灯片。
- **Act**：根据契约选择编辑工具：
  - 共享选择器 → 批量CSS更新
  - 跨幻灯片语义一致（如标题、正文） → 语义批量样式
  - 单张幻灯片内容/结构 → 布局优先修复表面 + 非空补丁操作
  - 插入/删除幻灯片 → 显式页面操作
- **Guard**：检查完成状态，补丁绑定到快照哈希，陈旧的快照触发重新绑定提示而非立即重写。每个补丁必须指定具体操作。覆盖要求未满足时阻止过早结束。

#### 用户画像记忆
- 用户画像按**意图**和**演示维度**（主题、视觉、布局、内容、模板、通用）组织，仅路由兼容子集进入工作记忆。
- 工作记忆根据请求更新：\( A_t = U(A_{t-1}, r_t) \)。
- 任务结束时，通过整合（Consolidation）更新长期画像：\( P_u^+ = C(P_u, H) \)，防止临时请求成为持久偏好。

#### 工具记忆
- 两种执行粒度：
  - **轮次级任务经验（Round-scope Task Experience）**：在修改轮次中缓冲，更新后于任务结束整合。
  - **操作级工具链经验（Operation-scope Tool Chain Experience）**：将原始推理-工具调用-观察链分割成可复用片段，按操作上下文索引，在类似工具调用前检索注入。
- 工具记忆不定义幻灯片外观，而是帮助代理更可靠地执行目标，减少重复错误和回溯。

## 3. 实验设计

- **用户画像记忆提升第0轮人物对齐**：在GLM-5和Gemini 3.1 Pro上，MemSlides在所有四个对齐维度均优于基线；在GPT-5上，内容、结构和特异性领先。平均提升：相比DeepPresenter内容+1.37、结构+0.53、视觉+1.66、特异性+1.19；相比SlideTailor更大。且改善不是以牺牲一般质量为代价（表2显示质量指标竞争力）。

## 8. 不足与局限

- **实验覆盖有限**：
  - 人物对齐判断仅在受控画像库上进行，非真实用户部署。
  - 编辑请求是诊断性匹配对，而非自然用户输入或随机编辑集。
- **偏差风险**：
  - 画像库部分字段通过种子完成（seeded completion）填充，可能引入构造偏差。
  - 评估使用LLM作为裁判，虽然普遍但可能存在偏好。
- **应用限制**：
  - 未考虑内存隐私问题：持久记忆可能存储敏感偏好，需要用户可见的审查/编辑/删除控制。

  - 缺乏更强的记忆同意、删除和敏感偏好保护机制。
  - 实验结果主要基于API推理，未在端侧设备或低资源环境验证。
- **定性案例局限性**：工作记忆和跨任务整合仅提供有限示例，缺乏定量度量。
