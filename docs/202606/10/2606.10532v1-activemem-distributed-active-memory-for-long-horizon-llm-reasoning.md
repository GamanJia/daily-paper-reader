## 摘要
记忆对于使大型语言模型（LLM）智能体处理长程推理任务至关重要。现有的记忆机制大多是集中式的，通常将检索到的信息和交互历史组织在单个模型上下文中。这种设计带来了一个基本权衡：扩展推理轨迹可能导致上下文过载，而激进的内容修剪则可能造成不可逆的信息丢失。为了寻求更好的权衡，我们从人类认知系统中汲取灵感，特别是前额叶皮层（执行控制）和海马体（记忆管理）之间的功能互补性，表明这种权衡并非必然，而可能源于集中式记忆组织。为此，我们提出ActiveMem，一种异构框架，将智能体记忆与核心推理过程解耦。具体而言，一个高层规划器利用提炼后的语义要点执行推理，同时一个轻量级分布式记忆系统并行运行，在整个任务过程中主动积累和整合这些要点。在BrowseComp-Plus和GAIA上的实验表明，ActiveMem以显著降低的开销实现了最先进的准确率，证明了分布式主动记忆在长程推理中的有效性。

## Abstract
Memory is essential for enabling large language model (LLM) agents to handle long-horizon reasoning tasks. Existing memory mechanisms are largely centralized, typically organizing retrieved information and interaction history within a single model context. This design imposes a fundamental trade-off: scaling reasoning trajectories risks context overload, whereas aggressive content pruning may result in irreversible information loss. Seeking a better trade-off, we draw inspiration from human cognitive systems, especially the functional complementarity between the prefrontal cortex (executive control) and the hippocampus (memory management), suggesting that such a trade-off need not be inherent, but may instead stem from centralized memory organization. To this end, we propose ActiveMem, a heterogeneous framework that decouples agent memory from the core reasoning process. Specifically, a high-level Planner utilizes distilled semantic gists to execute reasoning, while a lightweight, distributed memory system operates in parallel to actively accumulate and consolidate these gists throughout the task. Experiments on BrowseComp-Plus and GAIA show that ActiveMem achieves state-of-the-art accuracy with significantly reduced overhead, demonstrating the effectiveness of distributed active memory for long-horizon reasoning.

## 2. 方法论述：核心思想、关键技术细节、算法流程

### 核心思想
- **认知解耦**：模仿大脑中前额叶皮层（执行推理）和海马体（主动记忆巩固）的分工，将 **高层推理** 与 **分布式主动记忆管理** 分离。
- **架构**：ActiveMem 包含两大模块：
  - **Planner**：负责核心推理（使用 397B 大模型），维护紧凑的推理状态 \(s_t = (x, h_t, m_{t-1})\)，其中 \(h_t\) 仅保留最近 \(K\) 步交互历史（\(h_t = \text{Trim}(h_{t-1} \cup \{a_t, o_t\})\)），\(m_{t-1}\) 是上一步返回的蒸馏语义要点（gist）。
  - **分布式记忆系统**：包含三个组件：
    1. **Memory Shards**（记忆分片）：固定数量逻辑分片，以 key–value 形式持久存储每个文档的蒸馏要点 \(g_c\) 及其相关查询历史 \(H_c\)。
    2. **Memorizers**（记忆器）：轻量级模型（4B），并行处理检索到的文档，根据查询 \(q\) 产生查询条件化的语义要点 \(g_c = \omega(c, q)\)。训练时通过知识蒸馏（教师模型 gpt-oss-120b）构建监督数据，并用条件下一个词预测目标微调（公式 5）。
    3. **Operator**（协调器）：控制层，负责将 Planner 的查询与检索文档转换为记忆任务，路由到对应分片，并管理记忆复用和异步合并。

### 关键技术细节
- **记忆复用**：当文档已在分片中且新查询与历史查询语义相似时（通过 Operator 的判断函数 \(J(q, H_c)\)），直接返回存储的要点，避免重复调用 Memorizer。
- **异步合并**：当同一文档被不同查询多次蒸馏时，Operator 在后台异步合并新旧要点（公式 6），消除冗余、保留全部事实，不阻塞推理主循环。
- **Trim 机制**：Planner 上下文仅保留最近 \(K\) 步交互，丢弃的原始内容已蒸馏并存于分片中，因此无信息丢失。

### 算法流程（Algorithm 1）
1. 初始化所有记忆分片，将系统提示和问题放入历史。
2. 循环 \(t = 1, \dots, T\)：
   - Planner 根据当前状态 \(s_t\) 生成一组检索查询 \(Q_t\)；若调用 `submit_answer(a)` 则返回答案。
   - 检索模块根据 \(Q_t\) 获取文档集 \(D_t\)。
   - **Route** 将每个文档分配给一个 Memory Shard（负载均衡）。
   - 并行处理每个文档（最多 \(N\) 个并发）：
     - 若文档未在分片中 → **memory miss**：调用 Memorizer 蒸馏，写入分片。
     - 若文档存在且查询相似 → **memory hit**：直接复用存储要点。
     - 若文档存在但查询新颖 → 蒸馏新要点，并异步合并。
   - 收集所有要点，组装成观察 \(o_t\)，更新历史并 Trim。
3. 循环直至提交答案或达到最大步数。

1. **最佳精度‑效率权衡**：ActiveMem 在 BrowseComp-Plus 上达到最高 LasJ 0.79 与 ACT 0.785，在 GAIA 上达到最高 LasJ 0.62 且计算开销最低（187 PFLOPs）。

5. **SFT 训练 Memorizer** 比 instruction-tuned 或 vanilla reasoning 版本取得更好精度和更低的 Planner 开销。

## 7. 优点

- **神经科学启发的解耦设计**：将执行控制与记忆管理分离，有效缓解集中式记忆的根本权衡。
- **分布式主动记忆**：通过并行 Memorizers、持久化 Memory Shards 和异步合并，实现了无损记忆累积，不增加推理上下文负担。
