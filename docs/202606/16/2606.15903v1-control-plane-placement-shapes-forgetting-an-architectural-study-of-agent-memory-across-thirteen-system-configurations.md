## 摘要
LLM在代理记忆管道中的位置——介于检索存储事实（广泛基准测试）的回忆平面与通过取代、释放、清除（未经测试）改变事实的控制平面之间——决定了系统会恢复哪些遗忘故障模式。在385个对抗性案例上比较了十三种系统配置，我们观察到三种布局机制，部分覆盖互补：确定性原语足以处理词汇/时间类别，但无法实现规范化（标识符混淆5%，跨语言0%）；写入时分LLM可以恢复规范化（100%），但无法帮助意图感知删除（前缀碰撞和复合事实0%）；变异时分钩子可恢复意图感知删除（78-85%），并同时提升几乎所有类别（总体91.7-93.2%，每次385案例运行0.17美元，每个案例变异延迟2.3秒 vs 确定性64-191毫秒/案例，回忆路径不变）。我们通过ForgetEval揭示了权衡，包含1000个案例模板套件和385个案例对抗层（132个手工制作+253个LLM起草经预言验证），通过确定性子串匹配评分，配合六方法适配器协议（诚实N/A评分），允许异构记忆存储在130行内接入。准入通过10名标注员IAA（Fleiss kappa=0.958）和77个案例外部作者子集（四名匿名贡献者）验证，复制了规范化不对称性并放大了联合布局提升（+27.8 pt）。生产故障主要是遗忘故障而非回忆故障，但现有基准仅测量回忆。ForgetEval及所有适配器在MIT许可下发布。

## Abstract
Where an LLM sits in an agent memory pipeline -- between the recall plane that retrieves stored facts (extensively benchmarked) and the control plane that mutates them via supersede, release, purge (largely untested) -- shapes which forgetting failure modes the system recovers. Comparing thirteen system configurations on a 385-case adversarial surface, we observe three placement regimes with partly complementary coverage: deterministic primitives suffice for lexical/temporal categories but fail canonicalization (5% on identifier-obfuscation, 0% on cross-lingual); inscribe-time LLM recovers canonicalization (100%) but cannot help intent-aware deletion (0% on prefix-collision and compound-fact); a mutation-time hook recovers intent-aware deletion (78-85%) and brightens nearly all categories simultaneously (91.7-93.2% overall, $0.17 per 385-case run, 2.3s/case mutation latency vs. 64-191ms/case deterministic, recall path unchanged).   We expose the trade-off via ForgetEval, a 1000-case templated suite plus a 385-case adversarial layer (132 hand-crafted + 253 LLM-drafted oracle-validated) scored by deterministic substring match, paired with a six-method Adapter Protocol with honest N/A scoring that lets heterogeneous memory stores enter in 130 lines. Admission is corroborated by 10-annotator IAA (Fleiss' kappa = 0.958) and a 77-case external-authored subset (four blind contributors) that replicates the canonicalization asymmetry and amplifies the joint-placement lift (+27.8 pt). Production failures are predominantly forgetting failures rather than recall failures, yet existing benchmarks measure only recall. ForgetEval and all adapters are released under MIT.

- **核心问题**：现有LLM代理记忆系统基准只评测**回忆**（recall）能力（如LongMemEval、MTEB、BEIR），但生产环境中的主要失败模式是**遗忘失败**（forgetting failure），例如：旋转后的密码仍被推荐、GDPR删除的记录仍被检索、同一用户的职位信息在多个会话中矛盾。这些失败源于控制平面（control plane）的缺失——系统能够执行`supersede`、`release`、`purge`等突变操作，但现有基准从未测试这些能力。
- **整体含义**：论文首次系统研究LLM在记忆管道中的**放置位置**（placement）——在回忆平面（retrieval）、写入时分（inscribe-time）、变异时分（mutation-time）等——如何塑造系统的遗忘失败模式。通过架构布局而非提示工程来优化遗忘能力，并提供了一个标准化的评估框架。

- **放置模式互补**：
  - 确定性原语：在词汇/时间类别上接近完美（>95%），但在规范化（identifier_obfuscation、cross-lingual）上失败（0-5%）。

- **架构无关性**：相同的LLM钩子应用于不同后台（Lethe、LangGraph、Letta）产生几乎相同的提升（2pt以内），证明是放置效应而非特定架构。
- **召回-遗忘权衡**：存在非支配点（Lethe强调遗忘，LangGraph强调回忆），LLM钩子可在不影响回忆的情况下大幅提升遗忘。

### 7. 优点

- **创新性**：首次提出系统评测遗忘能力的基准ForgetEval，填补了控制平面评测空白。
- **可重复性**：使用确定性子串匹配评分（无LLM judge），可复现性高。
- **公平性**：Adapter Protocol支持异构系统通过行为契约比较，N/A评分避免偏袒。
- **严谨性**：大规模消融、交叉验证、预印本条件复现（如Llama模型失败）、外部作者验证。
- **实用性**：低部署成本（单CPU，0.17美元/385案例），LLM钩子简单（窄JSON模板），可直接应用于现有系统。
- **洞察性**：揭示了架构放置而非提示工程的重要性，指导了未来记忆系统设计（联合写入+变异放置）。

### 8. 不足与局限

- **语言覆盖不足**：所有手工案例为英语，跨语言类别（cross_lingual_identifier）每脚本家族样本量极小（如Devanagari仅1例），无法区分不同LLM钩子系统。
- **系统覆盖缺口**：未评估Cognee（API不兼容）、Zep CE（已弃用）、Redis Semantic Memory和AutoGen Memory（需要API密钥）。部分系统（如Graphiti、HippoRAG）因架构不匹配（KG抽象丢失表面形式）而得分极低，可能低估其设计目标。
- **LLM钩子对模型能力敏感**：在Llama-3.1-70B上完全失效（JSON契约解析失败），仅DeepSeek-V3和Qwen-2.5-72B有效，限制了通用性。
- **复合事实（compound_fact）类别的混淆**：该类别不是遗忘测试而是部分编辑原语存在测试，无编辑原语的系统必然得0分，可能误导总体得分解释。
- **外部作者子集局限性**：77案例中有3个类别全部失败（negation_trap、compound_fact、recursive_supersession），无法区分系统，且部分失败源自评分设计盲点（子串匹配在否定句上）。
- **生态效度缺失**：未用真实生产环境中记忆泄漏数据验证（作者承认这是一项结构性映射，尚未经验证）。
