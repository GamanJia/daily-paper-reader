## 摘要
LLM智能体越来越多地部署在需要跨长时间交互历史持续推理的长时任务上。大规模实现这一点需要智能体在会话间持久存储、检索并更新自身的记忆。一个丰富的智能体记忆系统生态已经出现，涵盖扁平检索、LLM介导提取、整合事实存储以及智能体控制流。然而，其系统级行为尚未得到表征。我们首次对智能体记忆进行系统特征描述。首先，我们引入一个面向系统的分类法，沿四个轴对智能体记忆系统进行分类。其次，我们构建了一个阶段感知的性能剖析工具，将成本归因于构建、检索和生成。第三，我们在两个基准套件上对十个代表性系统进行特征描述，揭示了设计选择如何在写入和读取路径上转移成本。最后，我们推导出10条系统建议，涵盖构建调度、能力下限、通过查询量实现的摊销、新鲜度-延迟权衡以及集群规模管理。

## Abstract
LLM agents are increasingly deployed on long-horizon tasks requiring sustained reasoning over extended interaction histories. Realizing this at scale requires agents to persistently store, retrieve, and update their own memory across sessions. A rich ecosystem of agent memory systems has emerged spanning flat retrieval, LLM-mediated extraction, consolidating fact stores, and agentic control flows. Yet, their system-level behavior remains uncharacterized. We present the first systems characterization of agent memory. First, we introduce a system-oriented taxonomy classifying agent memory systems along four axes. Second, we build a phase-aware profiling harness attributing cost to construction, retrieval, and generation. Third, we characterize ten representative systems across two benchmark suites, uncovering how design choices shift cost across the write and read paths. Finally, we derive 10 system recommendations covering construction scheduling, capability floors, amortization via query volume, freshness-latency tradeoffs, and fleet-scale management.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究动机**：LLM 智能体在长时间跨度的任务中需要持久存储、检索和更新交互历史。现有的智能体记忆系统（如基于 RAG 的扁平检索、LLM 介导提取、知识图谱、智能体控制流等）在准确度基准上各有表现，但其**系统级行为**（如计算成本、延迟分布、资源消耗）尚未被系统地表征。
- **整体含义**：论文首次将智能体记忆作为系统工作负载进行研究，揭示设计选择（构建机制、存储组织、检索策略、更新方式）如何根本性地改变成本分布，从而为系统部署和优化提供量化依据。其发现直接关系到长时智能体的服务 SLO、成本和可扩展性。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：提出一个面向系统的四轴分类法（Taxonomy），将智能体记忆系统分为四种范式，然后通过阶段感知的剖析工具量化其系统行为。
- **四轴分类法**：
  - **构建方式**：absent（无）、deterministic（确定性）、LLM-mediated（LLM 介导）、agentic（智能体控制）。
  - **存储组织**：raw context、inverted index、dense vector、knowledge graph、hybrid multi-store。
  - **检索流程**：single-shot sparse/dense、multi-stage pipeline、graph traversal、reranking、LLM-controlled tool calls。
  - **可变性（Mutability）**：append-only、consolidating（合并更新）、mutate（主动改写）。
- **四种范式**：
  - Paradigm I: Long-context memory（直接使用模型上下文）
  - Paradigm II: Flat RAG memory（确定性索引 + 单次检索）
  - Paradigm III: Structure-augmented RAG memory（LLM 提取结构化信息，分为 append-only 和 consolidating 子类）
  - Paradigm IV: Agentic control flow（LLM 控制读写决策）
- **阶段感知剖析工具**：将执行分解为 **construction（构建）**、**retrieval（检索）**、**generation（生成）** 三个阶段，记录 API 调用（tokent数量、模型调用次数、延迟）和硬件指标（GPU 利用率、功率、HBM 带宽）。通过时间戳对齐实现阶段归因。
- **关键流程描述**：系统先对交互流进行 ingestion，然后 memory construction 将原始历史转换为持久记录（如事实、摘要、图结构），存储到 agent database；查询时 retrieval 选取相关记录，prompt assembly 串入 LLM 上下文，最后 generation 输出答案；maintenance 阶段可选地执行去重、合并、遗忘。

## 3. 实验设计：数据集、基准、对比方法

- **基准套件**：
  - **MemoryAgentBench (MAB)**：包含 4 类任务（准确检索、测试时学习、长程理解、选择性遗忘），共约 26 个数据集，输入长度 103K–1.44M tokens。核心使用 LongMemEval_S_*（5 个样本，各 ~360K tokens，共 300 个查询）。
  - **MemoryArena**：包含 20 个多会话任务，每个任务包含多个依赖子任务，用于研究新鲜度-延迟权衡。
- **对比方法**：10 个代表性系统，覆盖所有范式：
  - Paradigm I: long_context
  - Paradigm II: BM25, embedRAG
  - Paradigm III.a: GraphRAG, HippoRAG v2
  - Paradigm III.b: Mem0, SimpleMem
  - Paradigm IV: A-Mem, Letta, MIRIX
- **控制变量**：统一生成 LLM（GPT-4o-mini 或 Qwen3-32B），统一嵌入模型（text-embedding-3-small 或 Qwen3-Embedding-0.6B），检索上限 10 条目，缓存长度 4096 tokens。对各系统的原生执行模型仅做必要最小适配（如提示词调整、工具调用上限）。

## 6. 论文的主要结论与发现

论文提出 **10 个系统观察 (Insight)** 和对应的 **10 条建议 (Recommendation)**。以下提炼关键结论：

- **构建成本主导**：LLM 介导的构建能耗远超查询阶段，在 300 次查询后仍占据生命周期大部分成本。能源每正确回答差异超过 47 倍（BM25 4.1 kJ vs MIRIX 197 kJ）。
- **构建是预填充和嵌入密集型**：构建阶段解码 token 占比极低（中位数 4.6%），主要为长输入短输出，与延迟敏感的 QA 流量冲突。
- **嵌入流量模式分叉**：Paradigm III.a 系统生成大批量离线索引请求，Paradigms III.b/IV 生成顺序单序列嵌入。
- **构建 LLM 选择存在算法约束**：无严格输出契约的系统可平滑降级（如 GraphRAG），有严格格式要求的系统（如 MIRIX）存在能力下限，低于下限则存储不可用。
- **无系统在所有维度同时最优**：BM25 在准确检索上准确率最高（55.8%），但查询时延中等；Mem0 查询时延最低但准确率仅 26.8%；SimpleMem 查询时延最高但构建时延尚可。
- **新鲜度-延迟权衡**：当每会话构建时间超过会话到达间隔时（如 Mem0、MIRIX 等），异步调度将产生记忆滞差（staleness），同步调度则暴露构建时延于关键路径。
- **存储与 token 成本增长斜率不同**：存储大小最多差 9 倍，但 token 成本增长斜率差异更显著——Paradigm IV 系统的构建 token 成本随记忆规模超线性增长。
- **延迟结构**：有效 TTFT 跨系统差异两个数量级（0.1s–22.6s），LLM 控制深度是主要因素；LLM 边界系统（如 GraphRAG、Letta）尾延迟比确定性系统宽 3-5 倍。

## 8. 不足与局限

- **实验覆盖有限**：仅关注单节点、单智能体、纯文本记忆。未覆盖多节点分布式部署、多智能体协作、多模态记忆（图像、音频）。

- **基准偏差风险**：MAB 中包含大量精确检索任务，BM25 有天然优势。在一些需要推理和泛化的任务上，结构增强系统的表现可能被低估（图 7b 显示任务类别间差异大）。

- **可控变量标准化可能忽略系统原生最优化配置**：例如给所有系统固定检索条目数 10，但对某些系统（如 GraphRAG）可能过于严苛。作者承认并最小化适配，但无法完全消除偏差。
