## 摘要
长期记忆对于持久的大语言模型智能体至关重要，然而现有架构通常将历史交互存储为非结构化的扁平文本。这种无约束的存储会导致来源-角色崩溃，即一种智能体遭受源监测错误的严重故障模式。为了在架构层面解决这一认知脆弱性，我们提出了MemIR，一种类型化记忆中间表示，将源监测操作化为结构约束。MemIR将长期记忆写入基于事实的原子单元，分离原始证据、检索线索和承载真实性的声明，并将事实授权限制在支持的声明原子上。然后，它应用多路原子投影和来源范围利用，将异构检索命中转换为以声明为中心的候选包，并为答案生成提供规范化的事实接口。在LoCoMo和BEAM-100K上的实验表明，MemIR持续优于现有记忆基线，尤其是在需要源追踪、时间定位和碎片化证据聚合的任务上。

## Abstract
Long-term memory is essential for persistent LLM agents, yet prevailing architectures store historical interactions as unstructured, flat text. This unconstrained storage induces provenance-role collapse, a critical failure mode where agents suffer from source-monitoring errors. To resolve this cognitive vulnerability at the architectural level, we propose MemIR, a typed Memory Intermediate Representation that operationalizes source monitoring as a structural constraint. MemIR writes long-term memory into grounded atoms that separate raw evidence, retrieval cues, and truth-bearing claims, with factual authorization restricted to supported claim atoms. It then applies multi-route atomic projection and provenance-scoped utilization to transform heterogeneous retrieval hits into claim-centered candidate bundles and a normalized fact interface for answer generation. Experiments on LoCoMo and BEAM-100K demonstrate that MemIR consistently outperforms existing memory baselines, especially on tasks requiring source tracking, temporal grounding, and aggregation of fragmented evidence.

# 论文总结：通过类型化记忆表示缓解长期智能体中的来源-角色崩溃

## 1. 核心问题与研究动机

- **背景**：长期记忆是大语言模型（LLM）智能体从无状态响应转变为持久、个性化助手的关键能力。智能体需要跨片段会话积累经验流并恢复相关信息。
- **问题**：现有长期记忆架构大多将历史交互存储为非结构化的扁平文本（如摘要、叙事片段），通过词法或密集检索召回。这种扁平化移除了源监测所需的结构线索，导致**来源-角色崩溃**——即不同来源或话语角色的片段被未经授权地合并，或指代同一演化对象的片段被当作独立实体处理，从而引发源监控错误（如将观察证据与推断内容混淆、无法追踪引用、混淆陈述的认识状态等）。
- **含义**：可靠的记忆利用不仅需要检索有效性，更需要一种结构机制来保留来源和认识角色，以解决认知层面的脆弱性。

## 2. 方法论：MemIR

- **核心思想**：将源监测操作化为显式的结构约束，通过类型化记忆中间表示（Typed Memory Intermediate Representation）组织长期记忆。
- **三个主要阶段**：

  ### 2.1 系统写入记忆原子（Systematic Writing of Memory Atoms）
  - 将非结构化交互历史编译为类型化原子集合 \( M = \{P, S, H, T, V, A, R\} \)：
    - **Page (P)** 和 **Span (S)**：保留局部上下文边界和逐字证据。
    - **Handle (H)、Time (T)、Pivot (V)**：用于指称、时间和语义访问的辅助线索原子。
    - **Claim (A)**：唯一承载真实性的声明原子，必须由支撑 span 集 \( \text{sup}(x) \subseteq S, x \notin P \) 提供显式证据来源。
    - **Retrieval Views (R)**：跨原子访问关系，不创建新内容，仅指定访问路径。
  - **关键约束**：任何提取的线索或生成的声明都必须保留显式的证据来源，防止 LLM 衍生的原子被误认为无支撑的事实。

  ### 2.2 多路原子投影（Multi-Route Atomic Projection）
  - 检索路径：**稀疏路由**（BM25）和**密集路由**（BGE-M3），分别覆盖视图键和语义匹配。
  - 初始命中集 \( X_q \) 为各路径 top-K 结果的并集，使用**倒数排名融合（RRF）** 计算检索分数 \( s_{\text{ret}}(x|q) \)。
  - **类型约束投影**：将异构命中 \( h \) 映射到相关声明原子 \( a \)，规则为 \( \Pi(h) = \{a \in A \mid o(h) \in \Omega_a \cup \{a\}\} \)，其中 \( \Omega_a \) 是声明的关联集（支撑 span、handle、pivot）。仅保留能投影到有效声明的命中。
  - **候选包**：每个声明 \( a \) 形成候选包 \( b_a = \langle a, \rho_a, E_a \rangle \)，其中 \( \rho_a \) 为聚合检索强度（支撑命中分数之和），\( E_a \) 为来源闭包（包含检索到的证据和完整关联集）。

  ### 2.3 来源范围利用（Provenance-Scoped Utilization）
  - 先按 \( \rho_a \) 排序保留前 \( M \) 个候选包作为预重排池。
  - 使用交叉编码器 \( g_\theta \) 对每个包打分，选择 top-K 有序包。
  - **LLM 选择器**进一步从 top-K 中选取最多 \( X \) 个互补候选包，并分配角色（`direct` 或 `support`）。
  - 将选中的包转换为**标准化事实接口** \( F_q = \{f_i\} \)，每条记录包含声明文本、来源闭包、时间线索和角色。若证据不足则返回“insufficient evidence”，避免无依据生成。

- **整体流程**：交互历史 → 类型化原子 → 多路检索 + 投影 → 候选包 → 排序/选择 → 事实接口 → 答案生成。

## 3. 实验设计

- **数据集**：
  - **LoCoMo**：10个长多轮对话，1540个问题，涵盖单跳、多跳、时间、开放域四类问答。
  - **BEAM-100K**：20个对话，100K令牌历史，400个问题，涵盖10个任务类别（如冲突解决、知识更新、多会话推理等）。

- **指标**：
  - LoCoMo：token-level F1、BLEU-1、LLM-based Judge（GPT-4o-mini评估语义一致性）。
  - BEAM-100K：LLM-as-Judge分类评分（GPT-4o-mini，使用官方评价提示）。

- **基线方法**：ReadAgent, LoCoMo baseline, Zep, LangMem, A-Mem, MemoryOS, Mem0, LightMem, NEMORI, SimpleMem, HIMEM, O-Mem, SwiftMem 等（共13种以上）。

- **骨干模型**：
  - 主要实验（LoCoMo）：GPT-4.1-mini 和 GPT-4.1。
  - BEAM-100K主实验：GPT-4.1-mini（记忆构建、束选择、答案生成）；Judge 用 GPT-4o-mini。
  - 不同骨干分析：额外测试了 Qwen3-14B、MiMo-7B、GLM-4 9B。

- **消融实验**：在 LoCoMo 和 BEAM-100K 上分别移除四类组件（去掉声明原子、去掉线索原子、去掉类型约束投影、去掉候选包结构）。

- **超参数分析**：LoCoMo 上考察了每页声明数量（默认12）、预重排池大小 M（默认32）、选定包预算 X（默认6）；BEAM-100K 调整至每页18个声明、M=72、X=10。

- **案例研究**：展示 MemIR 如何从竞争性记忆状态中正确选择最新事实。

## 6. 主要结论与发现

- MemIR 在 LoCoMo 和 BEAM-100K 上**持续优于所有现有记忆基线**，尤其在需要源追踪、时间定位、冲突解决、碎片证据聚合的任务上提升显著（如 LoCoMo 单跳、时间、开放域；BEAM-100K 的 ABS、CR、KU、MSR 等）。
- 收益来源：不是单纯依靠更强的检索覆盖率，而是通过**类型化原子分离 + 来源范围利用**，将长期历史转换为易于访问、比较和消费的、来源受控的事实单元。
- 复杂跨声明推理（如多跳）仍需依赖下游模型的推理能力，MemIR 主要优化了证据组织与暴露方式。

## 7. 优点

- **设计合理性**：严格区分原始证据、线索和声明，确保只有受支撑的声明可作为事实，防止幻觉。

- **实验充分**：涵盖多种评估维度（跨数据集、多指标、消融、超参数、不同骨干），结果具有说服力。

## 8. 不足与局限

- **计算开销**：多类型记忆原子的系统写入（尤其 LLM 驱动的声明生成和线索提取）增加交互编译时的额外成本，论文承认这一点，并计划未来研究轻量化编译技术。
- **下游推理瓶颈**：复杂跨声明推理（如多跳）仍高度依赖生成模型的自身能力，MemIR 对结构化了事实但未提供显式的逻辑推理机制。
