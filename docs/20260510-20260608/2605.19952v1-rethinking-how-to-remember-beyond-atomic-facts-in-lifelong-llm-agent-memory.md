## 摘要
为实现可靠的长期交互，LLM智能体需要具备一个能够忠实存储、高效检索并深度推理累积对话历史的记忆系统。现有方法大多采用基于提取事实的范式：通过手工设计的静态提示将原始对话压缩为原子事实，随后存储、匹配并注入下游推理。然而，这种以事实为中心的设计不可避免地丢弃了原始对话中的细粒度细节，且无法支持对分散孤立事实的深度推理。此外，静态提示无法在不同对话风格间保持一致的提取粒度。为克服这些局限，我们提出TriMem，它维护三种共存的表示粒度：以源标识符锚定的原始对话片段（保证存储忠实性）、提取的原子事实（用于高效记忆检索）、以及将分散事实聚合为整体语义理解的合成画像（用于深度推理）。我们进一步采用基于TextGrad的提示优化方法，通过响应质量反馈迭代优化提取与画像提示，实现无需任何参数更新的终身演化。在LoCoMo和PerLTQA数据集上基于多种LLM骨干网络的广泛实验表明，TriMem持续优于强记忆基线方法。代码已开源：https://TMLR-TriMem.github.io

## Abstract
To enable reliable long-term interaction, LLM agents require a memory system that can faithfully store, efficiently retrieve, and deeply reason over accumulated dialogue history. Most existing methods adopt an extracted fact based paradigm: handcrafted static prompts compress raw dialogues into atomic facts, which are then stored, matched, and injected into downstream reasoning. Nevertheless, such fact-centric designs inevitably discard fine-grained details in original dialogues and fail to support deep reasoning over scattered isolated facts. Moreover, static prompts cannot maintain consistent extraction granularity across diverse dialogue styles. To address these limitations, we propose TriMem, which maintains three coexisting representation granularities, including raw dialogue segments anchored by source identifiers for storage fidelity, extracted atomic facts for efficient memory retrieval, synthesized profiles that aggregate dispersed facts into holistic semantic understanding for deep reasoning. We further adopt TextGrad-based prompt optimization, which iteratively refines extraction and profiling prompts via response quality feedback, achieving lifelong evolution without any parameter updating. Extensive experiments on LoCoMo and PerLTQA across multiple LLM backbones demonstrate that TriMem consistently outperforms strong memory baselines. The code is available at https://TMLR-TriMem.github.io .

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **问题**：现有LLM智能体记忆系统普遍采用“原子事实”范式——通过手工编写的静态提示将原始对话压缩为原子事实，然后仅存储这些事实，在检索和推理阶段也完全依赖它们。这种设计导致三大局限：
  1. **有损存储**：事实提取不可避免地丢弃原始对话中的细粒度细节（如修饰语、具体数字），使得依赖精确细节的问题无法回答。
  2. **浅层推理**：系统仅能进行单事实匹配，无法对分散于多个事实的综合理解（如情感推断、性格判断、多步逻辑推理）做出可靠回答。
  3. **提示次优**：静态提示无法应对现实世界中高度多样化的对话风格和信息表达模式，导致提取粒度不稳定，性能波动大。
- **动机**：需要重新思考记忆系统的三个阶段（存储、检索、推理）应分别采用何种表示粒度，并让系统具备自适应演化能力，以在保真度、效率和深度理解之间取得平衡。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：构建**三层共存表示粒度**的系统 TriMem：
  1. **原始对话片段**（raw dialogue segments）：通过源标识符（source identifier）与压缩记忆条目关联，保证存储保真度。
  2. **提取的原子事实**（extracted atomic facts）：用于高效检索，通过向量相似度匹配。
  3. **合成画像**（synthesized profiles）：在记忆摄入阶段逐步将分散事实整合为关于实体（人物）的多维画像（身份、性格、兴趣、职业、价值观等），在推理时直接提供整体理解，避免浅层匹配。

- **关键技术细节**：
  - **记忆构建**：
    - 使用滑动窗口（大小 \(l=40\)，步长 \(s=38\)）切分对话，保持局部连贯性。
    - 利用提取提示 \(p_e\) 对每个窗口进行多维事实提取（含 `lossless_restatement`, `timestamp`, `person`, `location`, `keywords`, `entities`，以及新增的 `source_dialogue_ids` 字段，指向原始对话片段）。
    - 同一人物的所有事实按人物分组，再由画像提示 \(p_\psi\) 合成结构化画像。
  - **记忆检索**：
    - 先对问题分析所需信息和关键词，生成搜索查询（target query）。
    - 基于事实的嵌入向量进行 top-K（K=25）相似度检索。
    - 检索结果作为锚点，通过索引获取对应的原始对话和完整画像。
  - **提示进化**：采用 TextGrad（基于文本的“梯度”方法），将提取提示 \(p_e\) 和画像提示 \(p_\psi\) 视为可优化字符串。通过比较系统回答与参考答案的 LLM 评分，由高级模型（Claude Opus 4.6）生成自然语言编辑建议，迭代更新提示（共4轮优化）。无需更新模型参数，适用于 API 模型。

- **算法流程**（文字描述）：
  1. 输入历史对话 \(H\) → 滑动窗口分割 → 每个窗口通过LLM+提取提示生成结构化事实条目（含源ID） → 存储事实并建立索引。
  2. 按人物分组事实 → 通过LLM+画像提示生成各人物画像 → 存储画像。
  3. 给定问题 \(q\) → 分析问题生成搜索查询 → 基于事实嵌入检索 top-K 事实 → 获取对应原始对话和画像。
  4. 将原始对话、事实、画像拼接为上下文 → LLM生成最终答案。
  5. 评估答案质量 → 失败案例驱动 TextGrad 更新提取提示和画像提示 → 重复1-5多轮（实验中4轮）。
