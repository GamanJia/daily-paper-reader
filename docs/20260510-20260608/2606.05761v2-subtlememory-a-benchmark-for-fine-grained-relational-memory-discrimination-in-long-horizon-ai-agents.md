## 摘要
持久性AI助手（例如OpenClaw）在长期交互中积累了大量相关的记忆。随着这些记忆的增长，它们可能相互强化、在不同上下文中出现分歧或直接冲突，使得正确的协助依赖于记忆关系而非孤立的回忆。现有的长期记忆基准很少探究智能体在下游任务中如何保留和利用此类关系。为弥补这一空白，我们引入了SubtleMemory，一个用于长期运行的AI智能体进行细粒度关系记忆判别的基准。SubtleMemory构建了关系控制的潜在语义制品，其变体实例化互补、微妙或矛盾的关系，并将其嵌入到逼真的用户-智能体历史中，要求智能体在后续查询和指令中恢复分布式的关系结构。该基准包含10个长历史中的1522个评估实例，基于1090个关系控制的记忆变体集，涵盖用户相关和非用户相关的查询。评估了六个独立记忆系统、两个带有原生记忆模块的Claw风格智能体以及三个带有插件记忆模块的Claw风格智能体，我们发现当前系统在细粒度关系记忆判别上仍然薄弱。我们进一步引入了诊断协议，揭示了在记忆保留、检索和下游推理阶段的不同能力轮廓。

## Abstract
Persistent AI assistants, such as OpenClaw, accumulate large collections of related memories over long-term interactions. As these memories grow, they may reinforce one another, diverge across contexts, or directly conflict, making correct assistance depend on memory relations rather than isolated recall. Existing long-term memory benchmarks rarely probe how agents preserve and utilize such relations during downstream tasks. To address this gap, we introduce SubtleMemory, a benchmark for fine-grained relational memory discrimination in long-running AI agents. SubtleMemory constructs relation-controlled latent semantic artifacts whose variants instantiate complementary, nuanced, or contradictory relations, and embeds them into realistic user-agent histories, requiring agents to recover distributed relational structures during later queries and instructions. The benchmark contains 1,522 evaluation instances over 10 long histories, grounded in 1,090 relation-controlled memory-variant sets and spanning user-related and non-user-related queries. Evaluating six standalone memory systems, two Claw-style agents with native memory modules, and three Claw-style agents with plugin memory modules, we find that current systems remain weak on fine-grained relational memory discrimination. We further introduce diagnostic protocols that reveal distinct capability profiles across memory preservation, retrieval, and downstream reasoning stages.

## 2. 论文提出的方法论

### 2.1 核心思想
- **构建关系控制的潜在语义制品**：以语义种子（用户偏好、世界知识）为基础，通过受控操作生成一组语义变体（**互补、细微、矛盾**三类关系），这些变体共享一个解析目标（resolution target）。变体被隐式嵌入到多轮用户-智能体交互会话中，并分布在长时域对话历史里。评估时，智能体需从历史中恢复这些分布式的关系结构并正确推理。

### 2.2 关键技术细节
- **关系分类**：
  - **互补**（Complementary）：变体互不冲突，应被聚合。细分为 *Multi-evidence*（需整合多个证据）和 *Any-one*（任一证据足矣）。
  - **细微**（Nuanced）：变体语义相似但条件不同，需精细区分。细分为 *Temporal*（时间条件）和 *Contextual*（上下文条件）。
  - **矛盾**（Contradictory）：变体无法同时满足，智能体应识别冲突并适当处理（如请求澄清）。

- **构造流程（五阶段流水线）**：
  1. **语义种子选取**：用户种子来自PersonaMem-v2，非用户种子来自多个QA基准（FanOutQA、MuSiQue、QACC、HoH、AmbigQA）。
  2. **语义变体创建**：LLM根据关系类型生成或选择变体，并经过过滤确保自然性和关系正确性。
  3. **会话构建**：每个变体被嵌入到一个任务导向的多轮对话中（共10种会话类型），信息自然渐进地揭示。
  4. **评估实例构建**：为每个解析目标生成查询及参考答案（正确集A+、错误集A-）。用户相关查询采用结构表单填写或资源安排任务；非用户查询为知识型问题。
  5. **用户历史组装**：相关会话与其他无关会话混合，形成长时域历史（平均236.4个记忆承载会话，211.6K token）。

- **评估协议**：支持三种部署设定：独立记忆系统、原生记忆Claw智能体、插件记忆Claw智能体。引入 **Oracle设定**（直接提供原始相关会话）和 **Perfect Retrieval设定**（提供从相关会话构建的记忆存储对象，绕过检索但保留记忆构造效果）以分离各阶段失效。

1. **当前系统在细粒度关系记忆判别上显著弱于Oracle**：最强系统A-Mem（70.0%）仍比Oracle（85.4%）低15+百分点，矛盾关系最困难（最佳系统仅50.4%，Oracle仅68.7%）。

3. **记忆保留和检索共同决定最终性能**：诊断分析显示两者均存在严重失效；部分系统保留好但检索差（如OpenClaw矛盾关系保留率71.0%但检索率34.2%）。
4. **保留原始交互会话有助于保真**：A-Mem和OpenClaw同时保留结构化记忆和原始会话，保留率最高。
5. **智能体上下文组织与记忆系统交互复杂**：集成OpenClaw有时提升互补/细微，但矛盾关系处理反而下降，效果依赖模型能力。
6. **时间推理仍是薄弱点**：多数系统在上下文细微判别上优于时间细微判别，而Oracle表现出相反模式。

- **诊断框架实用**：瀑布分析分离记忆保留、检索、回答生成阶段，能精准定位系统瓶颈，对开发者改进方向有直接指导。

## 8. 不足与局限

- **评估范围有限**：仅基于文本交互，未涵盖多模态、多语言、高度专业领域（如医疗、法律）的记忆使用场景。
- **依赖LLM-as-judge**：尽管与人工一致性高，但在非常细微的判别上（如是否正确识别冲突）可能存在偏差。
- **Oracle性能未饱和**：矛盾关系下Oracle仅68.7%，表明答案生成模型本身的能力上限，可能掩盖记忆系统的实际差距。未来需更强大的推理模型。
- **构造成本高**：五阶段流水线依赖多次LLM调用和人工过滤，扩展成本较高；对非用户种子依赖源数据集质量（如QACC、AmbigQA）。
- **缺乏人类用户交互的真实性**：所有历史为合成生成，可能缺少真实交互中记忆模糊性、上下文演变等动态特征。
- **未考虑记忆的动态更新**：如用户偏好随时间改变而显式丢弃旧记忆的情形，基准仅测试矛盾共存但未解析的情况。
- **可被过度优化**：作为公开基准，存在被针对性调参“刷分”的风险，需持续维护和版本控制。
