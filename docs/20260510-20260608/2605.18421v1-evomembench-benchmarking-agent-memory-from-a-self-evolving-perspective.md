## 摘要
近期针对大语言模型（LLM）Agent的基准测试主要评估推理、规划和执行能力。然而，记忆对于Agent同样至关重要，因为它使Agent能够随时间存储、更新和检索信息。这一能力仍未被充分评估，很大程度上是因为现有基准测试未能提供系统性的记忆机制评估方法。本文从自我进化的视角研究Agent记忆，并引入EvoMemBench——一个沿两个维度组织的统一基准：记忆范围（回合内 vs. 跨回合）和记忆内容（知识导向 vs. 执行导向）。我们在标准化协议下比较了15种代表性记忆方法与强大的长上下文基线。结果表明，当前的记忆系统仍远未达到通用解决方案：长上下文基线依然极具竞争力；记忆在当前上下文不足或任务困难时最为有效；且没有任何单一记忆形式能在所有设置中一致有效。对于知识密集型场景，基于检索的方法依然强劲；而在执行导向型任务中，当存储的经验与任务结构匹配时，程序性和长期记忆方法更为有效。我们希望EvoMemBench能促进未来对基于LLM的Agent更有效记忆系统的研究。我们的代码可在https://github.com/DSAIL-Memory/EvoMemBench获取。

## Abstract
Recent benchmarks for Large Language Model (LLM) agents mainly evaluate reasoning, planning, and execution. However, memory is also essential for agents, as it enables them to store, update, and retrieve information over time. This ability remains under-evaluated, largely because existing benchmarks do not provide a systematic way to assess memory mechanisms. In this paper, we study agent memory from a self-evolving perspective and introduce EvoMemBench, a unified benchmark organized along two axes: memory scope (in-episode vs. cross-episode) and memory content (knowledge-oriented vs. execution-oriented). We compare 15 representative memory methods with strong long-context baselines under a standardized protocol. Results show that current memory systems are still far from a general solution: long-context baselines remain highly competitive, memory helps most when the current context is insufficient or tasks are difficult, and no single memory form works consistently across all settings. Retrieval-based methods remain strong for knowledge-intensive settings, whereas procedural and long-term memory methods are more effective for execution-oriented tasks when their stored experience matches the task structure. We hope EvoMemBench facilitates future research on more effective memory systems for LLM-based agents. Our code is available at https://github.com/DSAIL-Memory/EvoMemBench.

## 6. 论文的主要结论与发现
1. **长上下文LLM仍极具竞争力**：直接使用原始长上下文的基线（Gemini-3-Flash）在多个任务上表现优异，有时甚至超过所有记忆方法，表明当前记忆的抽象可能带来信息损失。
2. **记忆在保留上优于修订**：现有记忆方法在简单保留任务上表现较好，但在需要更新/修正存储信息的任务（如FactConsolidation）上退化严重，说明记忆更新的瓶颈。
3. **记忆在上下文不足或任务困难时帮助最大**：在短上下文预算或高难度任务中，记忆方法提升显著；在大容量上下文或简单任务中，记忆甚至可能引入噪声导致性能下降。
4. **执行任务受益于程序性指导，但压缩有风险**：程序性长时记忆（如ReasoningBank、AWM）在工具使用等执行任务中表现较好，但短时压缩方法（MemAgent、MemoBrain）丢失细节导致性能下降。
5. **不同执行领域青睐不同记忆形式**：工具使用更适合检索增强记忆，网页搜索更适合通用长时记忆，具身任务更适合程序性长时记忆。
6. **跨环境迁移取决于记忆是否匹配目标决策过程**：工具域迁移较稳定，而具身域迁移不稳定（因环境差异大）。
7. **当前记忆系统远非通用解决方案**：没有任何一种记忆形式能在所有设置下稳定最优，需要针对场景选择。

## 7. 优点
- **统一视角**：首次沿“范围×内容”两轴系统组织记忆评估，覆盖知识/执行、回合内/跨回合四个象限，填补了现有基准的空白。
- **全面对比**：纳入6大类15种代表性记忆方法，加上强力长上下文基线，提供大规模系统性比较。
- **标准化协议**：统一骨干（DeepSeek-V3.2）、统一接口、统一评估流程，提高可复现性。
- **开源**：代码公开，基准数据集重构细节公开，利于后续研究。
- **效率分析**：不仅考虑准确率/成功率，还报告token用量、步数等效率指标，更贴近实际部署需求。
- **反直觉发现**：揭示记忆可能有害（当上下文足够时）、记忆更新比保留更难等关键洞见，对设计记忆系统有指导意义。

## 8. 不足与局限
- **计算资源未报告**：未说明实验所需的GPU型号、数量及运行时间，复现成本不明。
- **骨干模型偏差**：所有记忆方法使用DeepSeek-V3.2，但长上下文基线包含更强模型（Gemini-3-Flash），这种设计虽然合理但可能降低记忆方法的相对排名。此外，未测试不同骨干对记忆方法的影响。

- **忽略选择性遗忘**：基准虽然包含修订任务，但未专门设计对记忆遗忘的细粒度评估（如容量限制下的遗忘行为）。
- **方法覆盖可能不全**：尽管涵盖了15种方法，但如LLMs内置记忆（如Transformer长程记忆）或更复杂的记忆网络未纳入。
