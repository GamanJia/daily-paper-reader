## 摘要
长时程自主智能体需要记忆系统来保留历史信息、追踪不断变化的状态，并在有限的上下文窗口之外复用相关知识。现有的智能体记忆系统通常遵循记忆构建-检索（MCR）流程，但往往主要调整记忆库，而在部署后保持周围的流程固定不变。这种固定流程的设计难以处理异质的任务特定失败模式，并且可能随着时间推移与规模和结构不断演化的记忆库失去对齐。为了解决这些局限性，我们提出了MemPro，一种系统级进化框架，将整个MCR流程视为可进化程序，而不仅仅调整记忆库或提示文本。MemPro维护一个可运行记忆系统实现的版本树，其中进化智能体迭代地选择有前景的版本，诊断重复出现的失败，并通过失败模式引导的编辑-调试完善创建改进的子版本。在LongMemEval、LoCoMo、HotpotQA和NarrativeQA上的实验表明，MemPro在几次迭代内始终优于强大的静态和提示级进化基线，随着进化持续改进，并实现了有利的性能-成本权衡。代码可在https://github.com/wanghai673/MemPro获取。

## Abstract
Long-horizon autonomous agents require memory systems to retain historical information, track evolving states, and reuse relevant knowledge beyond finite context windows. Existing agentic memory systems typically follow a memory construction-retrieval (MCR) pipeline, but often adapt mainly the memory bank while keeping the surrounding pipeline fixed after deployment. This fixed-pipeline design struggles to handle heterogeneous task-specific failure modes and can become misaligned with memory banks that evolve in scale and structure over time. To address these limitations, we propose MemPro, a system-level evolution framework that treats the entire MCR pipeline as an evolvable program rather than adapting only the memory bank or prompt text. MemPro maintains a version tree of runnable memory-system implementations, where an Evolving Agent iteratively selects promising versions, diagnoses recurring failures, and creates improved child versions through failure-mode-guided edit-debug refinement. Experiments on LongMemEval, LoCoMo, HotpotQA, and NarrativeQA show that MemPro consistently outperforms strong static and prompt-level evolving baselines within a few iterations, continues to improve with evolution, and achieves a favorable performance-cost trade-off. Code is available at https://github.com/wanghai673/MemPro.

## 1. 核心问题与整体含义

- **研究动机**：长时程自主智能体需要记忆系统来超越有限上下文窗口，但现有的“记忆构建-检索”（MCR）管道在部署后通常固定不变，只调整记忆库。这导致两个关键问题：
  - **任务异质性**：不同任务（如时序推理、多会话推理）有不同失败模式，固定管道只能应用单一策略。
  - **记忆-管道错配**：随着记忆库规模和结构演化，固定管道可能与记忆组织方式脱节。
- **整体含义**：MemPro主张记忆自我进化应上升到**系统级别**，将整个MCR管道视为可进化程序，而不仅是调整提示文本或记忆库，从而从根本上解决上述局限性。

## 2. 方法论

- **核心思想**：将MCR管道视为一个**可进化程序**，维护一个可运行记忆系统的**版本树**，通过进化智能体（Evolving Agent）进行迭代选择、扩展和评估。
- **关键技术细节**：
  - **MCR管道概述**：
    - **记忆库构建**：输入数据分段后，记忆代理拼接记忆构建提示，生成记忆更新并写入记忆库。
    - **记忆检索与使用**：研究代理进行检索、整合、反思的迭代循环，直到获得足够信息回答查询。
  - **版本树（`T=(V,E)`）**：
    - 每个节点 `v` 包含一个可运行的管道实现 `F_v` 和评估日志 `L_v`（包括总体得分 `S_v`、类别得分 `C_v`、父节点 `pa(v)`、总体评估 `A_v`）。
    - 根节点 `v0` 存储初始管道。
  - **进化流程（三步骤循环）**：
    - **选择（Selection）**：进化智能体评估所有日志，选择最有前景的节点，并产生诊断分析（`R_ℓ`），标准包括高总体得分、可推广改进方向、频繁失败模式。
    - **扩展（Expansion）**：基于选中的节点，智能体进行内部分步迭代，每步选择“EDIT”、“DEBUG”或“TERMINATE”动作：
      - **编辑**：根据诊断分析修改管道（代码或提示）。
      - **调试**：选择诊断示例运行，获取完整跟踪，更新分析但不改管道。
      - **终止**：停止扩展，输出新管道版本。
    - **评估（Evaluation）**：在新管道上运行完整训练集，生成评估日志（包括类别得分和总体评估），作为新节点加入版本树。
  - **诊断分析**：通过分析失败类型和改进方向，指导后续编辑和调试，避免全训练集重评估。

## 6. 主要结论与发现

- **核心结果**：
  - MemPro仅需**5次进化迭代**即可超越所有非MemPro基线，达到长时记忆和QA基准的最高性能（SOTA）。
  - 随进化迭代增加（5→10→15次），MemPro持续改进，表明版本树进化具有高天花板。
  - MemPro在**性能-成本权衡**上优于Full Text和强静态/提示级进化系统，在合理token预算下达到最高准确率。
- **关键发现**：
  - 提示级进化（GEPA、MetaMem）已优于静态系统，但**系统级进化（编辑可执行代码）带来更大收益**。
  - 版本树结构（允许从历史强版本分支）优于线性链式进化。
  - 迭代扩展（内部分步编辑+调试）优于单次编辑。
  - 多轮外部进化是持续改进的必要条件。

## 7. 优点

- **创新性**：首次将MCR管道视为**可进化程序**，实现系统级自我进化，突破仅更新记忆库或提示的局限。
- **技术设计**：
  - **版本树**允许从多个历史强版本探索不同方向，避免线性进化的局部最优。
  - **编辑-调试内循环**：通过诊断示例追踪，避免全训练集重评估，提高进化效率。
  - **诊断分析**引导编辑，聚焦频繁失败模式，而非孤立实例。
- **实验全面性**：覆盖四种不同类型基准、两种骨干模型、多种基线类别，验证了方法有效性和鲁棒性。
- **性能-成本效率**：在竞争性价比上取得优异性，不显著增加推理成本。
- **可复现性**：公开代码，复现基线和对齐设置提高了可信度。
