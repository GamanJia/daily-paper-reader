## 摘要
长时域对话Agent需要通过不断演变的事件、任务和目标与用户交互。这样的历史自然是时序性的，然而许多现有的记忆系统主要按主题相似性组织信息，可能忽略了事件发生的顺序。我们提出线段树记忆（Segment Tree Memory，简称SegTreeMem），一种记忆架构，它将对话历史表示为按时间顺序排列的线段树（基于话语）。SegTreeMem通过在线最右前沿更新规则增量插入新话语，在形成层次化记忆片段的同时保持时间顺序。检索时，SegTreeMem通过树传播相关性分数，将局部语义匹配与层次化时间上下文相结合。在三个长时域记忆基准测试和两个LLM主干网络上，SegTreeMem相较于平面检索、图结构记忆和树结构记忆基线提高了回答质量。额外的时间顺序排列分析表明，性能提升依赖于在记忆构建过程中保留时间顺序，这支持了时间顺序是Agent记忆关键结构的观点。

## Abstract
Long-horizon conversational agents need to interact with users through evolving events, tasks, and goals. Such histories are naturally temporal, yet many existing memory systems organize information primarily by topical similarity and may ignore the order in which events occur. We introduce Segment Tree Memory, or SegTreeMem, a memory architecture that represents conversation history as a temporally ordered Segment Tree over utterances. SegTreeMem incrementally inserts new utterances through an online rightmost-frontier update rule, preserving chronological order while forming hierarchical memory segments. For retrieval, SegTreeMem propagates relevance scores through the tree to combine local semantic matching with hierarchical temporal context. Across three long-horizon memory benchmarks and two LLM backbones, SegTreeMem improves answer quality over flat retrieval, graph-structured memory, and tree-structured memory baselines. Additional temporal-order permutation analysis shows that the performance gain depends on preserving temporal order during memory construction, supporting the claim that temporal order is a key structure for agentic memory.

## 1. 核心问题与整体含义（研究动机和背景）

- **问题**：长时域对话代理（long-horizon conversational agents）需要通过不断演变的事件、任务和目标与用户交互。对话历史具有天然的时序性（temporal order），但现有记忆系统大多按主题相似性（topical similarity）组织信息，而忽略了事件发生的时序顺序。
- **关键缺陷**：忽略时序顺序会导致检索到语义相似但上下文错位的信息；相邻话语的意义依赖于它们在同一片段内的语境，而主题聚类可能把远距离的话语聚合在一起，破坏局部语境。
- **研究目标**：探索两个关键设计问题：(i) 如何在线增量构建一个既能保持主题连贯性又能保持时间顺序的树形记忆索引？(ii) 检索时如何利用该树结构中的主题组织与时间顺序？

## 2. 方法论：核心思想、关键技术细节

### 2.1 核心思想
- 采用**线段树（Segment Tree）**作为记忆数据结构，将对话历史表示为层次化、时间连续的片段树：每个节点对应一个连续的话语区间（contiguous span of utterances），内部节点递归地划分其区间为有序且不重叠的子区间。
- 在线构建时通过**最右前沿（rightmost frontier）**更新规则增量插入新话语，无需全局重建。
- 检索时通过**结构感知的分数传播（structure-aware score propagation）**在树内传递相关性，结合局部语义匹配与层次化时间上下文。

### 2.2 关键技术细节

#### 线段树定义
- 节点 `v` 关联连续区间 `I(v) = [l(v), r(v)]`，表示该节点概括了从 `x_l(v)` 到 `x_r(v)` 的连续话语。
- 三种节点：根节点（覆盖整个历史）、内部节点（区间等于子节点区间的并集）、叶节点（单条话语）。
- 每个节点通过 LLM 生成摘要作为节点注释 `A(v)`。

#### 在线构建（Algorithm 1）
- 维护从叶到根的**有序最右前沿集合** `F_t`（区间右端点均为 `t` 的节点）。
- 新话语 `x_{t+1}` 到达时，通过**兼容性模型**选择最右前沿中的一个非叶节点作为附着点：余弦相似度、逐点 LLM、批量 LLM 三种策略。
- 若存在兼容节点，则在所选节点下创建新叶节点并更新该节点及其祖先的区间和摘要；若没有兼容节点，则创建新根，将原树和新节点合并。
- 更新仅涉及 `O(log|M_t|)` 个节点，满足在线更新要求。

#### 结构感知检索（Algorithm 2）
- 初始分数：根据节点摘要与查询的局部相关性计算归一化分数向量 `s_q^{(0)}`。
- 分数传播：通过稀疏转移矩阵 `W_P` 进行多跳传播，支持两种策略：
  - **自上而下**：分数从父节点向子节点扩散，使检索聚焦于更细粒度的片段。
  - **自下而上**：分数从子节点向父节点扩散，扩大检索到更广的时间上下文。
- 最终分数：结合初始分数与传播分数，通过衰减因子 `α` 和传播步数 `H` 控制：`\tilde{s}_q = \frac{\sum_{k=0}^H α^k s_q^{(k)}}{\sum_{k=0}^H α^k}`。
- 选择 Top-K 节点作为证据。

## 6. 主要结论与发现

1. **时间顺序关键性**：在构建阶段保持时间顺序显著提升性能。时间顺序排列实验证明 SegTreeMem 的性能依赖于原始时间顺序（置换后 accuracy 下降 0.11–0.14），而非时间树仅下降 ~0.02–0.05。
2. **SegTreeMem 全面最优**：在三个基准和两个 LLM 骨干上，SegTreeMem 的 LLM-judge accuracy 均超越所有外部基线，最高提升近 20%（relatively）。
3. **传播策略任务依赖**：自上而下传播在细节导向任务（LoCoMo）中更优，自下而上传播在状态导向任务（RealMem）中更优；无单一策略通用。
4. **建设-成本权衡**：批量 LLM 构建质量最高，余弦相似度构建在质量和成本间取得最佳平衡（LLM 调用少约 10 倍，延迟低约 5 倍）。
5. **结构感知传播通过改变检索粒度提升效果**：传播方向调整了证据的时间粒度（自上而下→更细粒度，自下而上→更广上下文），适用于不同问题类型。

## 7. 优点

- **方法新颖性**：首次将线段树数据结构引入对话代理记忆，兼顾时间顺序与层次化，解决了现有树记忆忽略时序的缺陷。
- **在线构建高效**：利用最右前沿将更新限制在 `O(log n)` 节点，支持实时交互。
- **检索机制灵活**：通过矩阵传播将结构信息融入排序，支持多跳聚合，且传播方向和超参数可调。
- **实验充分**：覆盖多种基准、骨干、消融设置，并设计了时间顺序排列实验和成本-效果分析，结论可信。
- **开源可复现**：提供匿名化代码，详细提示模板，便于进一步研究。

## 8. 不足与局限

- **退化树风险**：在极端话题切换的情况下，最右前沿更新可能导致树高和节点数线性增长（O(T) 树高、O(T²) 节点），造成存储和计算开销大。
- **长程主题重复**：时间树无法将远处但相关的话语合并到同一节点，有限传播步数可能无法连接远距离重复主题。
- **摘要信息损失**：内部节点摘要可能压缩掉精确细节（如日期、名称），影响事实性召回。
- **手动超参选择**：传播策略、衰减因子和传播步数需要针对任务手动调整，缺乏自适应机制。
- **仅限文本**：当前实现仅处理文本对话，未扩展到多模态观察、工具调用或动作轨迹。
- **缺乏长期维护**：缺少增量重建、周期性压缩或去重操作，极长对话下效率可能下降。
- **实验局限性**：未与 MemWalker、LATTICE 直接对比（因无法复现）；仅评估两个 LLM 骨干；LLM-as-a-judge 本身存在偏差风险；部分基线的原始参数可能未针对当前设定最优调整。
