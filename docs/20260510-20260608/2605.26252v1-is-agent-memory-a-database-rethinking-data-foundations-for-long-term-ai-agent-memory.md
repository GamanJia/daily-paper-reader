## 摘要
长期运行的AI智能体需要持久记忆。记忆支持跨会话学习，减少重复上下文注入，并能够审计过去的决策。当前的智能体记忆系统和数据库范式将记忆视为存储。它们将正确性定位于记录、嵌入或边。每种只提供了长期记忆所需的部分能力。结果导致四种反复出现的故障模式：无节制的增长、缺少语义修订、容量驱动的遗忘以及只读检索。在我们的愿景中，长期智能体记忆是一种新的数据管理工作负载。其正确性是状态轨迹的属性，而非单个记录的属性。我们将其形式化为受控演化记忆（GEM）。GEM用四个状态级操作符替代了记录级数据库操作：摄入、修订、遗忘和检索。六个正确性条件约束了状态如何演化。三个结构性观察表明，无论存储模型如何，任何记录级系统都无法满足这些条件。我们在一个属性图后端原型MemState中实现了这一抽象。MemState验证了可行性并揭示了与原生引擎之间的差距。我们概述了三个研究方向，将记忆中心的数据管理定义为一个工作负载。

## Abstract
Long-running AI agents need persistent memory. Memory supports learning across sessions, reduces repeated context injection, and enables auditing of past decisions. Current agent memory systems and database paradigms treat memory as storage. They localize correctness at records, embeddings, or edges. Each supplies only some of the capabilities that long-term memory requires. The result is four recurring failure modes: unregulated growth, missing semantic revision, capacity-driven forgetting, and read-only retrieval. In our vision, long-term agent memory is a new data-management workload. Its correctness is a property of the state trajectory, not of individual records. We formalize this as Governed Evolving Memory (GEM). GEM replaces record-level database operations with four state-level operators: ingestion, revision, forgetting, and retrieval. Six correctness conditions govern how the state evolves. Three structural observations establish that no record-level system can satisfy these conditions, regardless of the storage model. We realize the abstraction in MemState, a prototype on a property-graph backend. MemState validates feasibility and exposes the gap to a native engine. We outline three research directions that define memory-centric data management as a workload.

- **核心问题**：当前AI智能体（如ChatGPT、Claude、Cursor）依赖外部持久记忆来支持跨会话学习和决策审计，但主流实现将记忆视为数据库存储，采用记录级CRUD（创建、读取、更新、删除）操作。这种抽象导致四种反复出现的失败模式：①无节制增长（冗余和低相关条目堆积）、②语义修订缺失（更新仅追加而非整合，新旧事实共存）、③容量驱动遗忘（过期按年龄而非效用）、④只读检索（访问不改变状态，高频访问不能强化信息）。
- **整体含义**：作者认为长期智能体记忆不是数据库问题，而是一个新的数据管理工作负载。其正确性应定义在状态轨迹（state trajectory）上，而非单个记录上。需要从根本上重新设计数据基础，从记录级操作转向状态级操作，并引入演化策略来治理记忆的更新与遗忘。

### 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：提出 **受控演化记忆（Governed Evolving Memory, GEM）** 框架，用一个三元组 \( M_t = (D_t, S_t, P_t) \) 表示记忆状态，其中 \( D_t \) 为内容（语义单元及其值历史），\( S_t \) 为结构组织（类型化边），\( P_t \) 为演化策略（声明式规则）。
- **四个状态级操作符**，替代记录级CRUD：
  1. **摄入（Ingestion）**：将新输入整合到现有状态，更新值历史而不覆写旧值。
  2. **修订（Revision）**：基于内部证据（如矛盾、依赖变化）合并、传播更新，保留旧值与来源。
  3. **遗忘（Forgetting）**：基于相关性信号（访问频率、衰减）逐步压缩、隐藏或归档内容，而非直接删除。
  4. **检索（Retrieval）**：不仅返回结果，还更新访问单元的显著性（salience），使检索成为写操作。
- **六个正确性条件**（C1–C6）：
  - C1（查询正确性）：返回最新非归档值作为当前值。
  - C2（转换正确性）：每次状态转换必须遵守 \( P_t \)。
  - C3（依赖一致性）：沿类型化边的语义依赖必须传播更新。
  - C4（来源保留）：遗忘和修订须保留可达单元的来源链。
  - C5（有界活动状态）：活动内存大小有策略定义的上限。
  - C6（检索诱导适应）：每次检索更新访问单元的显著性，重复检索降低其被遗忘的资格。
- **三个结构性观察**（Observation 1–3）：证明纯函数检索无法满足C6，容量驱动遗忘无法满足C5，追加存储无法满足C2，未类型化传播无法满足C3，从而说明CRUD引擎无法实现GEM。
- **原型MemState**：
  - 基于Kuzu（嵌入式属性图引擎）实现。
  - 数据模型：主题（topic）为语义单元，含字段值历史、摘要、嵌入；边类型分为扩展（extension，蕴含依赖）和关联（association，仅相关）。
  - 策略作为声明式规则存储在 \( P_t \) 中，在提交时检查后置条件，保证C2。
  - 遗忘采用三层阶梯（压缩→隐藏→归档），由显著性阈值驱动。
  - 检索时对访问单元增加显著性，同时返回结果。
