## 摘要
LLM 智能体积累的历史会超出其上下文窗口，这推动了关于记忆系统的日益增多的文献。然而，现有大多数设计仅针对单一场景（多会话聊天或单一轨迹格式）进行了调整，很少有证据表明它们能在部署中遇到的各种异质轨迹中泛化。我们重新审视了八个记忆系统以及一个用于搜索问题的代理框架，在五个场景上进行了评估：单轮问答、多会话聊天、代理轨迹问答、记忆压力测试和长期代理任务。该框架通过工具调用自我管理扁平文本文件存储，实现了最佳跨任务排名，表明记忆性能的关键在于给予智能体对存储和检索的主动控制，而非被动地存储在一个固定管道的后面。我们将这一见解实例化为 AutoMEM，一个具有自我管理工具接口的代理记忆框架，在我们评估的系统中实现了最佳的跨场景通用性。

## Abstract
LLM agents accumulate histories that outgrow their context windows, motivating a growing literature on memory systems. Yet most existing designs are tuned to a single scenario (multi-session chat or a single trajectory format), and there is little evidence that they generalize across the heterogeneous trajectories agents encounter in deployment. We revisit eight memory systems plus an agentic harness for search problems, on five scenarios: single-turn QA, multi-session chat, agentic-trajectory QA, memory stress tests, and long-horizon agentic tasks. The harness, which self-manages flat text-file storage via tool calls, achieves the best cross-task ranking, suggesting that memory performance hinges on giving the agent active control over storage and retrieval rather than on a passive store behind a fixed pipeline. We instantiate this insight in AutoMEM, an agentic memory harness with a self-managed tool interface that achieves the best cross-scenario generality among the systems we evaluate.

### 1. 论文的核心问题与整体含义（研究动机和背景）

-   **核心问题**：大型语言模型（LLM）代理在长期交互中积累了大量历史信息，这些信息会超出其上下文窗口，因此需要“记忆系统”来存储和检索历史。然而，现有的大多数记忆系统都是为单一场景（如多轮对话或单一的代理轨迹格式）精心调优的。论文的核心问题是：**这些记忆系统的设计能否在代理部署场景中遇到的多样化、异质的轨迹中泛化？** 即，它们是否具备“跨场景通用性”？
-   **整体含义**：论文挑战了当前“为特定场景设计复杂记忆结构”的主流范式。作者通过系统的诊断性实验发现，记忆系统的性能并不取决于存储结构的复杂程度，而在于**是否赋予代理对存储和检索过程的主动控制权**。一个允许代理主动查询和操作的简单工具（类似于一个命令行界面），其跨场景表现优于那些拥有固定、复杂流水线的结构化记忆系统。这暗示了从“被动存储”到“主动管理”的范式转变。

### 2. 论文提出的方法论：核心思想、关键技术细节

-   **核心思想**：记忆系统的关键不在于构建复杂的存储结构（如知识图谱或分层摘要），而在于**设计一个让代理能够主动管理与使用记忆的接口**。代理应当能够在运行时，根据当前问题动态制定检索计划，而不是被动地接收从固定流水线中检索到的信息。
-   **AutoMEM 框架**：基于上述思想，论文提出了 AutoMEM。其核心是一个**代理记忆框架（Agentic Memory Harness）**，它不预设复杂的存储结构，而是让代理通过工具调用来自我管理记忆。
-   **关键技术细节（算法流程）**：
    1.  **存储**：将历史数据简单地存储为扁平的文本文件（raw records）。
    2.  **动作集**：代理可以从四个动作中选择其一与记忆交互：
        -   `rg`：对原始文本记录执行正则表达式搜索。
        -   `read`：通过ID读取特定记录。
        -   `dump`：将较短的语料库直接发送给答案LLM。
        -   `index_query`：对预构建的索引（如Cypher图）执行结构化查询。该索引默认基于LightMem的摘要索引。
    3.  **交互循环**：
        -   **规划**：LLM规划器基于当前问题、已收集的证据和之前的提示（hint），从动作集中选择一个动作并生成调用参数。
        -   **执行**：执行器对记忆存储执行该工具调用，不涉及LLM推理。
        -   **判断**：LLM判断器审查当前收集到的证据是否足以回答问题。如果足够，则跳转到下一步；否则，返回一个“提示”（hint），指明缺失的信息，并重新调用规划器。这个过程最多可以重复Kmax次。
    4.  **回答**：当判断器认为证据充分时，LLM回答器基于所有收集到的证据生成最终答案。
-   **单遍模式**：作为多循环模式的高效替代，AutoMEM的单遍模式（Kmax=1）允许规划器一次性并行发出`rg`、`read`和`index_query`，跳过判断环节，在牺牲少量精度的情况下大幅降低延迟和token成本。

### 3. 实验设计：数据集、场景与对比方法

-   **场景与数据集（Benchmarks）**：论文精心设计了五个覆盖主要部署场景的任务家族：
    1.  **单轮问答**（Large-corpus retrieval）：HotpotQA，测试大型语料库下的知识检索能力。
    2.  **多会话聊天**（Personal chat assistant）：LoCoMo，模拟个人日常事务的长期记忆。
    3.  **代理轨迹问答**（Trajectory recall）：AMABench（含ALF， Web， T2SQL三个子域），测试对代理行动轨迹的理解。
    4.  **记忆压力测试**（Memory stress tests）：MemoryAgentBench（含AR， TTL， LRU， CR四个子任务），测试精确检索、长程理解、冲突解决等特定记忆能力。
    5.  **长期代理任务**（Real agentic tasks）：ALFWorld， MemoryArena（shop/travel），将记忆与真实任务完成度挂钩。
-   **对比方法**：论文评估了8种代表性记忆系统 + 1个代理框架，涵盖主要设计空间：
    -   **无记忆**：Long context（将全部历史拼入提示）。
    -   **基于笔记**：SimpleMem（原子化笔记）。
    -   **多存储**：PlugMem， LightMem（分层的场景、语义、程序存储）。
    -   **基于图**：HippoRAG， AMA-Agent（知识图谱或索引化的行动图）。
    -   **代理框架**：DCI-Lite， DCI-Lite+Sum（通过grep/read工具让代理直接交互的文本文件）。
    -   **强化学习训练**：Mem-T， MemRL（通过RL训练检索或写入策略）。

### 6. 论文的主要结论与发现

1.  **没有一种方法能统治所有场景**。现有的记忆系统都高度场景化，在一个场景上的胜利难以迁移。
2.  **Long-context基线比预期的要强**，且在成本上具有竞争力。许多索引型方法的预处理成本很高，除非被大量问题分摊，否则并不划算。
3.  **索引型方法在代理轨迹QA上存在两大失败模式**：
    -   **表示级别失败**：构建时的固定模式（schema）会丢失步骤级和行动级的证据，例如HippoRAG的知识图谱无法存储“操作步骤索引”或“动作标签”。
    -   **检索级别失败**：即使存储中保留了答案信息，被动的检索方式（如一次性稠密检索）也无法可靠地将其取回。一个主动的、可迭代的代理驱动查询接口能够弥补这一差距。
4.  **代理框架（DCI-Lite）的胜利**：DCI-Lite这个允许代理主动“grep”和“read”文本文件的简单框架，取得了最佳的跨场景排名。其成功的关键在于将模式承诺从构建时推迟到查询时，让代理能根据具体问题动态组织检索计划。
5.  **AutoMEM的提出与验证**：作者将上述洞察实例化为AutoMEM，它通过整合代理框架与选择性索引（通过`index_query`工具），在LoCoMo（结构性率最高的基准）上取得了最大幅度的提升（+22.3pp），并在总体排名上超越了所有基线。

### 7. 优点

-   **视角新颖**：论文提出了“跨场景通用性”这一重要而未被充分研究的视角，指出了评估和设计记忆系统的新方向。
-   **诊断深刻**：不仅仅是报告结果，而是通过精心设计的消融和探查实验，揭示了索引型记忆系统失败的**根本原因**（表示级和检索级失败），具有很强的洞察力。
-   **实验框架完备**：构建了一个包含5大场景、10多种方法、并追踪成本与延迟的全面评估框架，为未来研究提供了宝贵的参考。
-   **方法简洁有效**：AutoMEM的设计思想“主动代理+简单工具”非常简洁，却比许多复杂的系统更有效，体现了“奥卡姆剃刀”原则。
-   **对成本效率的深刻理解**：论文分析了token成本、延迟、GPU利用率等多个维度的效率，并指出这些指标与系统设计的内在关联，而不仅仅是浮于表面的计数。

### 8. 不足与局限

-   **未实现分层预算路由**：AutoMEM对所有步骤（规划、判断、回答）都使用相同的强大模型，但规划与判断通常比回答简单。作者指出，未来可以引入一个路由器，将简单任务分配给廉价模型，这能大幅降低成本。目前的成本数字应被视为上限。
-   **判断提示协议的变化性**：判决器（Judge）的提示词敏感度很高。一个较为宽松的提示可能改变方法间的排名。论文使用严格的事实性判定，但读者需留意这个设定。
-   **动态代理任务上的局限性**：论文发现，在真正的动态代理任务（如ALFWorld）上，单纯依靠外部记忆系统无法显著提升性能。性能瓶颈在于代理本身的策略（policy），而非记忆。这揭示了非参数化记忆的能力上限。
-   **应用限制与风险**：论文提到了部署时的伦理风险（如访问控制、内容过滤），但未在实验中涉及。AutoMEM赋予代理工具调用权利，如果记忆存储中包含用户数据，没有适当的安全措施可能会带来风险。
-   **未探索更多前沿方向**：论文提到了知识图谱在代理轨迹上表示能力不足，并建议未来可以研究一个“记忆DSL”来自动化模式设计或专门的基础设施。但这些是未来工作，并未在本文中解决。
