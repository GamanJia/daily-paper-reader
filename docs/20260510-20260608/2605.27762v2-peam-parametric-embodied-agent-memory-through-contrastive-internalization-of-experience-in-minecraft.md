## 摘要
我们提出了PEAM，一种在Minecraft中的参数化具身代理记忆框架，它将代理记忆从推理时检索转变为通过经验内化成为参数驻留的技能。PEAM将一个缓慢的深思熟虑型LLM用于开放式推理，与一个快速的参数化模块配对，用于反射性执行已固化的技能。快速模块是一种多模态专家混合LoRA架构，具有按类别物理隔离的适配器，能够实现参数级别的持续学习而不会灾难性遗忘。我们将失败视为首要训练信号：失败-修正轨迹对通过联合行为克隆和对比目标进行内化，因此代理不仅学习成功的行为，还学习修正后的动作与失败动作的区别。为了管理固化，PEAM引入了一个参数化价值评分来决定哪些经验应该被内化，以及一个无标度自触发固化机制来决定何时内化，无需特定任务的手动调优阈值，使得代理能够在触发器跨任务分布转移时自我进化而无需重新调优。在Minecraft中的实验表明，PEAM提高了长时域任务性能，减轻了对先前固化技能的遗忘，并且在参数化与检索效率方面优于基于检索的具身代理和参数化记忆变体。

## Abstract
We present PEAM, a Parametric Embodied Agent Memory framework in Minecraft that transforms agent memory from inference-time retrieval into parameter-resident skills internalized through experience. PEAM pairs a slow deliberative LLM for open-ended reasoning with a fast parametric module for reflexive execution of consolidated skills. The fast module is a multimodal Mixture-of-Experts LoRA architecture with per-category physically isolated adapters, enabling parameter-level continual learning without catastrophic forgetting. We treat failure as a first-class training signal: failure--correction trajectory pairs are internalized through a joint behavioral-cloning and contrastive objective, so the agent learns not only what succeeds but also how corrected actions differ from failed ones. To govern consolidation, PEAM introduces a parameterization-worthiness score for deciding which experience should be internalized, and a scale-free self-triggered consolidation mechanism for deciding when to internalize without task-specific hand-tuned thresholds, making the agent self-evolving as the trigger transfers across task distributions without re-tuning. Experiments in Minecraft show that PEAM improves long-horizon task performance, mitigates forgetting on previously consolidated skills, and improves parametric-versus-retrieval efficiency over retrieval-based embodied agents and parametric memory variants.

## 1. 核心问题与整体含义（研究动机和背景）

- **问题背景**：当前基于LLM的具身代理（如VOYAGER、Reflexion）大多依赖**非参数化记忆**，即过去的轨迹、反思和技能被存储在外部，每次推理时重新检索并注入到提示中。这使得代理的**参数化策略（即模型权重）在任务间保持不变**，导致：
  - 每轮决策都需要重新注入经验，消耗大量上下文预算和延迟。
  - 外部记忆库虽增长，但策略本身没有进化，**无法实现持续的技能内化**。
  - 面对长时域任务，**灾难性遗忘**问题显著：学习新技能时会覆盖旧技能。
- **整体含义**：PEAM从认知科学中的**互补学习系统**（快速情景记忆 + 慢速参数化整合）获得启发，提出了一种将情景记忆转化为**参数驻留技能**的框架。它实现了一个**自我演化的具身代理**：代理通过自身的探索、失败与修正，将选定的经验内化到模型参数中，从而提升长期任务性能、抵抗遗忘并降低推理成本。

## 2. 方法论：核心思想、关键技术细节

- **核心思想**：采用**两层级架构**：
  - **慢速深思型LLM（π_slow）**：负责开放式推理、规划、代码合成与结果验证。使用Azure GPT-4o。
  - **快速参数化模块（π_fast）**：基于Qwen3-VL-8B-Instruct，构建**多模态MoE（Mixture-of-Experts）LoRA架构**，包含按技能类别（craft、gather、combat）物理隔离的适配器。执行时直接调用参数化技能，无需检索外部记忆。
  - 二者通过**巩固管线**耦合，由两个门控机制决定：**参数化价值（PV）评分**（选择什么）和**自触发巩固（STC）**（何时巩固）。

- **关键技术细节**：
  - **失败-纠正轨迹内化**：情景存储 \( \mathcal{E} \) 包含成功轨迹 \( \mathcal{D}_{\text{succ}} \) 和失败-纠正对 \( \mathcal{D}_{\text{cpair}} = \{(x, \tau_f, \tau_c, c)\} \)。巩固时更新对应类别的适配器 \( \theta_c \)，优化联合目标：
    \[
    \mathcal{L}_{\text{PEAM}}(\theta_c) = \mathcal{L}_{\text{BC}}(\theta_c; \mathcal{D}_{\text{succ}}^{(c)}) + \lambda \mathcal{L}_{\text{PEAM-DPO}}(\theta_c; \mathcal{D}_{\text{cpair}}^{(c)})
    \]
    其中BC为行为克隆（负对数似然），DPO为适配器条件偏好损失，以纠正轨迹为chosen，失败轨迹为rejected。
  - **参数化价值（PV）评分**：用于评估候选技能是否值得内化，综合考虑：
    - 检索成本节省（未来调用频率 × 代码长度）
    - 稳定性（跨上下文成功率 × 上下文方差倒数）
    - 冗余惩罚（与已有参数化技能的代码嵌入相似度）
    - 遗忘风险（与已有技能共享类别则惩罚）
    权重通过网格搜索固定。
  - **自触发巩固（STC）**：无标度统计测试，基于技能最近失败率与历史基线失败率的z检验，当显著差异且PV排名在前q分位数时触发。参数（W=10, B=10, α=0.05, q=0.5）无需针对任务分布调参。
  - **推理流程**：先尝试快速路径（路由到对应适配器，执行生成代码，验证结果）；若失败或无适配器，则回退到慢速路径。成功或修正后的轨迹被存入情景存储，等待后续巩固。

## 6. 主要结论与发现

- **性能提升**：PEAM在11个长时域任务上达到69.7%成功率，比VOYAGER（54.5%）高+15.2个百分点（McNemar p=0.018），且优于最强检索式基线Optimus-1-rep.（60.6%）。
- **效率优势**：中位每次调用延迟从5.5s降至3.2s（-42%），每任务token从~31,200降至~4,600（-85%），源于消除每轮技能库重注入。
- **遗忘抵抗**：在顺序巩固craft→gather→combat后，PEAM对早期craft技能保持100%保留率，而单共享LoRA下降32.4%，EWC下降43.3%，全参数微调下降78.5%。隔离适配器是抵抗遗忘的关键结构机制。
- **组消融确认各组件必要性**：
  - BC项是生成可用代码所必需的（DPO-only格式合规0/12）
  - 隔离适配器是遗忘抵抗的根源
  - PV评分优于启发式阈值（任务成功率+8.7pp）
  - STC比固定计划更高效（收敛延迟从23 episode降至7）
- **自触发巩固无标度**：STC的统计触发标准在craft-heavy和combat-heavy两种分布上产生一致且稀疏的触发，无需针对分布重新调参。
- **额外方法论发现**：前向偏好余量不能预测生成路径的部署能力；量化部署会引入特定失败模式（零化低幅更新）；导航类任务的失败主要是环境性的，无法产生对比对；轨迹重切片可作为跨分布评估的替代方法。

## 7. 优点

1. **新颖的问题形式化**：将具身代理记忆从纯检索式扩展为**参数化内化**，建立了两层级架构，使代理能够自我进化。
2. **失败作为训练信号**：不仅记录失败，还通过纠正-对比对进行直接训练，使代理不仅知道成功模式，还能区分失败与成功动作的差异。
3. **参数隔离机制**：采用按类别物理隔离的MoE LoRA适配器，**从结构上消除灾难性遗忘**，无需复杂的正则化或重放，设计简洁有效。
4. **无标度自触发巩固**：无需任务特定阈值，基于统计检验自动决定何时巩固，提升了系统在不同任务分布上的适应性和可迁移性。
5. **效率显著提升**：参数量仅约83M/适配器，但推理速度提升42%，token消耗减少85%，实际部署收益明确。
6. **实验透明且方法论贡献**：不仅报告主结果，还分析了前向余量不可靠性、量化部署陷阱等，有助于代理研究社区避免常见误区。

## 8. 不足与局限

1. **单一环境**：所有实验在Minecraft 1.19中完成，未在机器人操作、网页代理等其他具身领域验证，结论的泛化性有限。
2. **固定的技能类别集**：仅覆盖三类（craft、gather、combat），适配器数量随类别线性增长，可扩展性在更多类别下需评估。导航等任务未纳入参数化技能，由慢速层处理。
3. **固定的超参数**：PV权重、STC的W/B/α/q通过少量搜索固定；未探索自适应调参策略，可能在不同环境非最优。
4. **对比对构建依赖特定环境**：失败-纠正对提取依赖于可修正的代码级错误，对于环境性失败（如导航）不适用，限制了方法在类似场景的适用性。
5. **跨分布评估采用合成方式**：通过重切片已有轨迹池来模拟不同任务分布，而非独立收集的真实配对数据，与现实分布转移存在差距。
6. **未报告总训练成本**：虽然LoRA训练步数少，但未提供慢速LLM调用次数和总GPU小时数，不利于评估完整计算开销。
7. **量化部署未成功解决**：作者在消费级硬件（RTX 4070）上尝试4-bit量化时遇到三种严重失败模式，最终使用A100集群，限制了方法的低资源可用性。
8. **伦理考量**：参数内化使技能更难以审查；虽然通过环境验证和隔离适配器缓解，但未提供完整的审计工具和安全性保障。
