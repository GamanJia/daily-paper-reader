## 摘要
现有的记忆增强型LLM智能体通常将记忆视为一个静态存储库，具有预定义的表示和固定的检索流程，这在动态智能体环境中是脆弱的，因为反馈、任务变化和异构信号会不断重塑应该记住的内容以及应该如何连接。为了解决这个问题，我们提出了FluxMem，一种连接性演化的记忆框架，它将记忆建模为异构图，并通过三个阶段逐步优化其拓扑结构：初始连接形成、反馈驱动的细化和长期巩固。在执行过程中，FluxMem修复缺失的链接、修剪干扰、对齐抽象粒度，并将重复的成功轨迹提炼为可重用的程序化回路，由记忆泛化性和演化成熟度指标引导。在三个根本不同的基准测试（包括LoCoMo、Mind2Web和GAIA）中，FluxMem取得了一致的最先进性能，在复杂的智能体环境中表现出强大的适应性和泛化能力。代码将在https://github.com/zjunlp/LightMem开源。

## Abstract
Existing memory-augmented LLM agents often treat memory as a static repository with pre-defined representations and fixed retrieval pipelines, which is brittle in dynamic agentic environments where feedback, task variation, and heterogeneous signals continuously reshape what should be remembered and how it should be connected. To address this, we propose FluxMem, a connectivity-evolving memory framework that models memory as a heterogeneous graph and progressively refines its topology through three stages: initial connection formation, feedback-driven refinement, and long-term consolidation. During execution, FluxMem repairs missing links, prunes interference, aligns abstraction granularity, and distills recurrent successful trajectories into reusable procedural circuits, guided by one metric for memory generalizability and evolutionary maturity. Across three fundamentally distinct benchmarks including LoCoMo, Mind2Web, and GAIA, FluxMem achieves consistent state-of-the-art performance, demonstrating strong adaptation and generalization in complex agentic environments. The code will be open-sourced in https://github.com/zjunlp/LightMem.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：现有记忆增强型大语言模型（LLM）智能体将记忆视为**静态存储库**，采用预定义的表示结构和固定的检索流程。这种设计在动态智能体环境中表现脆弱——环境反馈、任务变化和异构信号不断改变“应该记住什么”以及“应该如何连接”，静态范式无法适应这些变化。
- **具体挑战**：
  - **自适应记忆连接失败**：静态检索导致欠连接（丢失关键上下文）或过连接（引入噪声/幻觉）；记忆单元内容被锁定在单一抽象粒度，无法灵活适应执行需求。
  - **记忆连接巩固失败**：现有系统将轨迹视为孤立实例，缺乏逐步整合为稳定关联区域的能力，导致反复重建相同关联，无法内化结构模式。
- **研究动机**：受认知科学启发（Hebb规则、长期巩固理论），将记忆定义为**记忆单元及其连接随时间连续沉淀的结构**，需要通过环境交互动态自组织。

## 2. 论文提出的方法论

#### 核心思想：FluxMem——将记忆建模为**动态演化的异构图**，通过三个阶段连续优化拓扑结构，使记忆从脆弱的初始连接自动演化为稳健的任务优化回路。

#### 关键技术细节

- **三层记忆图**：`G = (V, E)` 包含三类节点：
  - **语义层** `V_sem`：静态事实知识（文档/知识片段）
  - **情景层** `V_epi`：具体状态-动作轨迹（如调试日志、工具调用序列）
  - **程序层** `V_proc`：蒸馏后的可重用法则模板（如多步规划启发式）
- 边类型：`E_ground ⊆ V_sem × V_epi`（事实支撑边），`E_distill ⊆ V_epi × V_proc`（经验蒸馏边）。
- **上下文作为动态子图**：每步 `t` 从图中选取子图 `G_t(q)`，序列化为上下文 `S_t(q)`。

#### 三阶段演化流程

1. **Stage I：初始连接形成（在线、逐步骤）**
   - **语义连接检索**：混合密集嵌入相似度、BM25稀疏匹配和LLM验证，计算候选知识节点与当前观察的相关性分数：
     ```
     Score(v, o_t) = v·o_t / (‖v‖‖o_t‖) + BM25(v, o_t) + LLM_ver(v, o_t)
     ```
     取 top-k 节点建立边。
   - **情景连接检索**：通过嵌入相似度检索最相关的前 k 个情景节点。
   - **程序连接继承**：沿 `E_distill` 边收集与所检索情景关联的技能节点。
   - 输出初始子图 `G_t` 及上下文 `S_t`。

2. **Stage II：反馈驱动的连接精炼（在线、迭代）**
   - 根据执行反馈 `f_t`（环境信号或自验证），进行拓扑编辑：
     - **连接级**：
       - 链接扩展（欠连接）：识别语义相近但未激活的节点，添加新边。
       - 链接剪枝（过连接）：识别干扰边，移除。
     - **单元级**：
       - 内容重塑（粒度对齐）：修改节点内部内容（细化或抽象），替换原节点并保留连接。
   - 循环直至成功或达到预设轮数 `T`，输出精炼子图 `G'_t` 及上下文 `S'_t`。

3. **Stage III：长期连接巩固（离线、周期批量）**
   - **情景聚类与技能归纳**：将情景节点基于轨迹相似度聚类，使用LLM归纳出共享技能作为新程序节点 `v_proc`。
   - **PEMS引导的迭代优化**：定义 **Procedure Evolution Maturity Score (PEMS)**：
     ```
     PEMS(k) = η(k) · log[ℓ(k)] × [1 - δ(G_cons^(k), G_cons^(k-1))]
     ```
     其中 `η(k)` 是技能引导下的源情景平均成功率，`ℓ(k)` 是技能文本长度，`δ(k)` 是当前与上一版本技能嵌入差异。对低分技能进行重写，重复测试-评分-精炼直到 `∆PEMS < ϵ`。

- **性能领先**：FluxMem在三个基准上均达到 **state-of-the-art**：

- **阶段重要性因任务而异**：
  - 在事实导向的长上下文任务（LoCoMo）中，**Stage II（反馈精炼）** 最关键（消除后LMJ下降~10分）。

- **迭代精炼有效**：Stage II的轮数增加带来持续但边际递减的增益；PEMS指标在约4-5轮后收敛，可作为停止进化、避免冗余计算的阈值。

## 7. 优点

- **动态记忆图设计**：将记忆从静态平面存储转变为可演化的异构图，支持连接和单元两级的自适应编辑，更贴近人类认知的可塑性。
- **闭环反馈精炼**：通过“执行-反馈-编辑”循环在运行时修复连接错误和内容粒度问题，无需人工干预。
- **长期巩固机制**：聚类-归纳-验证-PEMS引导迭代，将零散经验固化为结构化技能，同时自动压缩冗长技能，提升可复用性。
- **统一指标引导进化**：PEMS综合成功率、简洁性和语义稳定性，为停止进化提供量化依据，降低不必要的计算开销。
- **广泛而严格的实验**：覆盖三种根本不同的任务类型，对比大量基线并控制骨干模型变量，消融和收敛分析充分。
